# Hermes 配置方案（PAT 阶段一 · VPS 云端节点）

> 状态：待评审（未执行）
> 维护线：整体线
> 最后更新：2026-10-22
> 摘要：Hermes 作为 PAT 阶段一 VPS 节点的推荐配置方案——每项配置的目标值、对应的 PAT 需求、设计理由与调研依据。供多智能体评审；评审通过且前置条件满足后方可执行。

## 0. 文档定位

- 本文件是 `hermes-adjustments.md`（需求核对与调整清单）的执行方案伴生文档：清单回答"差什么"，本文件回答"具体设成什么、为什么这样设"。
- 本文件只写配置姿态与目标值，不写操作命令；执行细节由执行者在实施时按官方文档落实。
- 评审方式：评审意见请另立文档或经用户转交汇总；本文件的结论段在用户确认前不因评审意见径行修改。

## 1. 背景

- **项目定位**：PAT 云端是多 Agent 舰队，用户不忠诚于单一 Agent；Hermes 是给舰队添加的一个节点，不是唯一入口，更不是长期形态本身（长期形态为阶段二自研）。
- **阶段一的用途**：用户本人先真实用起来，用真实使用沉淀可验证的契约与经验数据。契约与经验可继承，节点本体可替换。
- **节点三项基本要求**（2026-10-20 用户定）：① 能在 PAT 框架下跑（开放协议接入数据层/事件/输出层）；② 能与其它 Agent 共享记忆（记忆可外置/可插拔，自带记忆垄断是扣分项）；③ 分阶段轻量化——开箱即用或少量配置先快速跑起来，再逐步接深（最关键）。
- **选型结论**：阶段一节点选 Hermes（适配度评估 92 分居首；决赛对比 QwenPaw 胜出，依据见 §6）。替补顺位：QwenPaw、LangBot。
- **节奏定调**：被提前的只有本节点这一单项；PAT 整体（硬件采集、数据层全量建设）保持探索节奏。共享记忆线独立先行，其记忆层就绪后经由 Hermes 的 MemoryProvider 槽位对接。

## 2. 设计理念（配置姿态的五条原则）

1. **治理先行于使用**：先把 Hermes 自带的写入者（自学习写技能、自动写记忆、后台维护）关进审批与上限的笼子，再接入真实使用。阶段一的产出是经验数据，数据可信优先于功能完整。
2. **默认收口、按需开放**：网络暴露、消息渠道、云组件一律先关或取最小集；验证通过一项，再开放一项。开放是逐项挣来的，不是默认的。
3. **契约只建在文档化面上**：PAT 与 Hermes 的契约只使用其官方文档化的 API 与配置面；未文档化行为不承载契约（对照教训：同类产品的大半 API 面是无稳定性承诺的前端同源接口，在上面沉淀契约等于把地基浇在沙上）。
4. **私有面止于桥**（蓝图 adapter 模式）：Hermes 的私有形态（API 形状、签名规则）只允许出现在 PAT 侧的桥/adapter 内部，不进入固件、不进入数据层。换节点时只换桥的下游。
5. **一切自治循环设死上限**：凡会自己运行的后台机制（维护、巡检、自动总结、定时任务），必须有迭代/预算上限或关闭。无上限的自治是已被实证的事故源（见 §6）。

## 3. 配置方案

### 3.1 版本与升级

- 目标版本 **≥ v0.21.6**（Dashboard 预授权漏洞修复线）；安装时按版本号自查 CVE-2026-71963 的修复状态。
- **关闭自动升级**；升级只手动执行，且执行前确认快照存在（Hermes 升级自带快照与自动回滚，纪律在于触发方式）。
- 对应需求：常驻运维（可控、可回滚）、安全收口。

### 3.2 常驻与网络暴露面

- gateway 注册为系统服务常驻（官方服务化方式），开机自启、异常自拉起。
- API Server 启用但**只绑 127.0.0.1**，Bearer key 必填；Dashboard 不对外网开放；远程访问一律经 Tailscale / SSH 隧道，不直接改绑公网地址。
- CORS 保持关闭（默认）。
- 对应需求：VPS 常驻、暴露面最小。

### 3.3 执行面

- 工具执行走官方 **Docker 加固后端**（官方生产推荐档），不用 local 裸跑（默认无沙箱、以宿主用户权限执行命令）。
- 无人值守场景下命令审批保持开启；审批超时按 **fail-closed**（超时即拒绝）运行。
- 对应需求：安全收口（执行受控、无人值守审批可用）。

### 3.4 记忆与自学习治理（开跑前硬基线，不可后补）

- `skills.write_approval` 开启；`memory.write_approval` 开启——自写技能、自写记忆一律先经审批才落盘。
- curator（自动维护）与 background_review（后台复盘写回）**关闭**；若执行时当前版本提供等效的死上限配置（迭代/预算），可改为设死上限，但"无上限运行"不允许。
- 可选云组件全部关闭并逐项审计：Portal Tool Gateway 不启用、Honcho 不接入、不绑定任何厂商托管服务。
- **本阶段不占 MemoryProvider 槽**：先以治理后的原生记忆运行，槽位预留给共享记忆线对接（节奏定调见 §1；此即调整清单取舍项 A 的定调结论）。
- 对应需求：记忆不垄断（先治理、后让渡）、数据主权（无强制云依赖）、经验数据可信。

### 3.5 模型接入

- 首个模型只接一个跑通：DeepSeek 或 Kimi 二选一（均为原生支持；由用户定）。其余模型（Qwen / GLM / OpenAI / Anthropic 等）开跑后以纯配置逐个追加，不返工。
- 凭据存放接受基线方案：密钥文件权限 0600 + 整机磁盘加密（调整清单取舍项 B 的建议结论，待用户确认）；密钥经安全输入进入机器，不经过聊天与仓库。
- 对应需求：多模型、数据主权（凭据只在本机）。

### 3.6 渠道与外部接入（本阶段范围界定）

- **本阶段不接任何消息渠道**：先以 API / CLI 在本机把本体跑稳、把治理与冒烟做完。渠道接哪些、归哪个节点管，是取舍项 D，迭代期逐个定、逐个开（理念 2）。
- **本阶段不建 MQTT 桥、不接数据层**：二者属接入期（见 `hermes-adjustments.md`）。本方案只预留其 Hermes 侧配置面：设备专用 Webhook route（独立 secret、窄 prompt 模板、限定 toolsets）+ API Server 内网调用；桥的具体方案在接入期另行成文评审。
- 对应需求：分阶段轻量化（开箱先行）；事件唤醒与数据层接入明确是下一阶段目标，本阶段不假装完成。

**桥的设计约束（接入期前置要求，2026-10-22 用户提出）**：桥是所有 Agent 接入的收敛点，按"有意收敛、严格设防"设计——其权力只来自位置，不来自功能。

1. **薄且无状态**：只做协议翻译、凭据打戳与路由；不含业务逻辑、不存数据本体、不持有会话状态。状态只在数据层与 Agent 侧，桥可重启、可替换、可多实例。
2. **一侧固定、一侧插件**：PAT 侧接口固定为本仓契约（蓝图层间协议 + `contracts/`）；Agent 侧为插件位，每个 Agent 一个 adapter 模块，新增 Agent 只加模块、不改桥芯。
3. **能力声明**：每个 adapter 显式声明其能力（如审批长挂起、流式、toolsets 支持），桥按声明路由与降级，不假设、不静默凑合。
4. **故障隔离**：单个 adapter 故障不影响其他 adapter 与桥芯。
5. **契约测试**：每个 adapter 交付时附对 PAT 侧契约的一致性测试，"翻译正确"以测试为准。
6. **降级留痕**：翻译中发生的能力降级或语义丢失必须记录可见，禁止静默降级。

边界提醒：桥不在采集路径上（采集 → 数据层不经桥），桥故障只影响 Agent 的实时消费，不影响数据主权与事后补读。本节约束适用于将来所有 Agent 的 adapter，不限于 Hermes。

### 3.7 舰队身份（PAT 侧约定，非 Hermes 配置）

- 写入归属与 `agent_id` 由 PAT 侧（未来的共享层/数据层服务端）按凭据强制打戳实现，本体零改动。本阶段无数据层，此项仅记录、不实施。

## 5. 明确不做（本阶段）

不 fork、不改源码；不写 MemoryProvider 插件；不接消息渠道；不启用任何可选云组件；不设自动升级；不在纸面假设审批长挂起可用（以冒烟为准）。

## 6. 调研依据（评审可审计）

- **适配度评估**（六个成品 × 五个契约面，文档 + 源码级核验，无活体冒烟）：Hermes 92 分居首，唯一"配置 + 一条 MQTT 薄桥"可跑通阶段一验证者。全文见本仓调研记录与 `design-harvest.md` 相关条目。
- **决赛对比**（Hermes vs QwenPaw）：Hermes 赢在契约面稳定（文档化 Runs API + MCP 双向 vs 无承诺的前端同源 API）、记忆治理闸现成（全配置级）、失败模式已知（事故皆有尸检可逐条设防）、常驻运维成色（一键服务化 + 快照回滚升级）。翻盘条件已记录在案，本方案默认其未触发。
- **事故实证**（支撑 §2 理念 1、5 与 §3.4）：Curator 死循环 20 小时、5,501 次调用烧掉 353M tokens（根因含迭代上限被设为 9999 且全局兜底被拆）；后台 review 把技能文件写成 0 字节并同步到其他机器（Issue #142069，2026-10-20）；机器生成的样板话被当作用户事实写入长期记忆（#141912）；整合失败却被记录为 completed（#137967）。
- **安全实证**（支撑 §3.1、§3.3）：Dashboard 存在预授权漏洞（含会话接管），已修于 v0.21.6；CVE-2026-71963（GitSpawn，CVSS 8.6，二手源对其修复状态说法不一，故要求按版本自查）；官方文档明示插件在进程内运行、非沙箱，Docker 后端为官方生产推荐并写死加固参数。
- **对照教训**（支撑 §7 冒烟项）：QwenPaw 的审批为内存态、默认 300 秒超时、进程重启即丢失——"长挂起审批"是同类产品的已证伪点，Hermes 必须实测排除，不得纸面通过。

## 7. 执行前置与验收

**前置条件（未全部满足前不执行）**：
1. VPS 机器落位（新开或现成；选址按蓝图二要素：模型 API 的地区限制 + 与用户的距离）。
2. 用户授权操作者上机（SSH / Tailscale）。
3. 首个模型选定与密钥就位（安全输入）。
4. 本方案评审完成，意见汇总后经用户确认。

**执行后验收（冒烟，全过才算开跑完成）**：
- 本地对话自检通过；
- 审批挂起数小时且期间重启进程，审批可恢复并走完（§6 对照教训的正面排除）；
- §3.4 治理开关逐项回读无误；云组件关闭逐项回读无误；
- 服务重启后自恢复，版本与配置无漂移。

验收通过后，另行规划接入期（MQTT 薄桥、MemoryProvider 占槽、数据层 MCP 化），各自成文评审。
