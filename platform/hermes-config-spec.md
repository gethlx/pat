## 1. 背景

- **项目定位**：PAT 云端是多 Agent 舰队，用户不忠诚于单一 Agent；Hermes 是给舰队添加的一个节点，不是唯一入口，更不是长期形态本身（长期形态为阶段二自研）。
- **阶段一的用途**：用户本人先真实用起来，用真实使用沉淀可验证的契约与经验数据。契约与经验可继承，节点本体可替换。
- **节点三项基本要求**（2026-10-20 用户定）：① 能在 PAT 框架下跑（开放协议接入数据层/事件/输出层）；② 能与其它 Agent 共享记忆（记忆可外置/可插拔，自带记忆垄断是扣分项）；③ 分阶段轻量化——开箱即用或少量配置先快速跑起来，再逐步接深（最关键）。
- **选型结论**：阶段一节点选 Hermes（适配度评估 92 分居首；决赛对比 QwenPaw 胜出，依据见 §6 与选型调研记录）。替补顺位：QwenPaw、LangBot；Hermes 冒烟暴雷时按顺位启用替补，不重开选型。
- **节奏定调**：被提前的只有本节点这一单项；PAT 整体（硬件采集、数据层全量建设）保持探索节奏。共享记忆线独立先行，其记忆层就绪后经由 Hermes 的 MemoryProvider 槽位对接。

## 2. 设计理念（配置姿态的五条原则）

1. **治理先行于使用**：先把 Hermes 自带的写入者（自学习写技能、自动写记忆、后台维护）关进审批与上限的笼子，再接入真实使用。阶段一的产出是经验数据，数据可信优先于功能完整。附则：**自治作业的完成与状态不以系统自报为准**，须有外部信号（文件侧证据、服务商侧用量）核对——"静默失败"是本赛道的通病，自报成功不可信（采收册 E1）。
2. **默认收口、按需开放**：网络暴露、消息渠道、云组件、出口流量一律先关或取最小集；验证通过一项，再开放一项。开放是逐项挣来的，不是默认的。附则：收口手段之间可能互斥（如容器隔离档会关掉命令检查），**互斥处必须显式取舍并记录**，不许假设多道闸自动叠加。
3. **契约只建在文档化面上**：PAT 与 Hermes 的契约只使用其官方文档化的 API 与配置面；未文档化行为不承载契约（对照教训：同类产品的大半 API 面是无稳定性承诺的前端同源接口，在上面沉淀契约等于把地基浇在沙上）。文档化不等于跨版本保证，故契约面须以钉死的构建版本 + 能力声明 + 契约测试共同承载。
4. **私有面止于桥**（蓝图 adapter 模式）：Hermes 的私有形态（API 形状、签名规则）只允许出现在 PAT 侧的桥/adapter 内部，不进入固件、不进入数据层。换节点时只换桥的下游。
5. **一切自治循环设死上限**：凡会自己运行的后台机制（维护、巡检、自动总结、定时任务），必须有迭代/预算上限或关闭。无上限的自治是已被实证的事故源（见 §6）。本阶段的落地形态是"清点后关停"（§3.4），不是提前建设预算平台；将来启用任何一项自治前，先单独验证其上限真实生效。

## 3. 配置方案

### 3.1 版本、部署形态与升级

- **版本口径改为"安全下限 + 执行时复核"**：安全下限 ≥ v0.21.6（Dashboard 预授权漏洞修复线）。上游迭代极快（评审日 2026-10-21 当前 stable 已是 v0.22.3），钉死旧版本等于主动部署落后构建；执行时安装**当时的当前 stable**，并按实际安装版本**逐项复核本方案全部配置键与默认值**（本方案的行为断言基于评审时点的文档与源码，版本漂移逐项核）。安装版本号与配置哈希记入冒烟档案。
- **部署形态三元组在执行前钉死**：部署形态（git 安装 / pip / 官方镜像）+ 具体版本（镜像则钉具体 tag，禁止 `:stable` / `:latest` 等移动 tag）+ 通道，三者写入执行记录。工具执行后端（§3.3）与本体部署形态是两回事，全文分开用词。
- **CVE-2026-71963（GitSpawn）已了结**：受影响版本 0.18.2–0.21.0，修复提交 `f6234d0`（PR #101483）；经提交祖先关系核验，v0.21.6 标签历史包含该修复。注意 v0.21.6 发行说明中的 git filter 程序加固是**另一条**修复，与 fsmonitor 注入路径不可混淆。执行时核对实际安装对象包含 `f6234d0` 即可；CVSS 口径：4.0 版 8.6 / 3.1 版 8.8。
- **关闭自动升级**；升级只手动执行，且执行前确认快照存在（Hermes 升级自带快照与自动回滚，纪律在于触发方式）；每次升级后按新版本重验受影响的配置键与能力。

### 3.2 常驻、网络暴露面与出口

- gateway 注册为系统服务常驻（官方服务化方式），开机自启、异常自拉起。
- **绑定口径统一**：本阶段 Hermes 与调用方同机，API Server 只绑 127.0.0.1，Bearer key 必填；Dashboard 不对外网开放；远程访问一律经 Tailscale / SSH 隧道。（Tailscale 含外部协调面，在此列为**传输层豁免**；它与 §3.4"不绑定厂商托管服务"不冲突——后者约束的是 Agent 运行时云组件，不是运维访问通道。）将来出现异机部署时，须显式降级为"内网绑定 + 来源白名单"并在接入期方案中立项，不默默改绑。
- CORS 保持关闭（默认）。
- **出口基线（本阶段最小集）**：理念 2 的收口同时管入口与出口——Docker 网络分段 + 模型 API 域名白名单；凭据注入式出口代理（iron-proxy 类）记为接入期候选，本阶段不建。
- **SSRF 与内网拓扑对撞（接入期前置立项，本阶段不处理）**：`security.allow_private_urls` 默认 false，封禁私网/环回/链路本地/CGNAT/云元数据地址；PAT 的数据层与记忆层按蓝图就在内网/本机，接入期必然对撞（采收册 E5 的同款教训）。接入期必答：①优先选 stdio 形态的同机 MCP server 绕开整个问题；②必须用 HTTP 内网端点时，该开关是**全局例外**（开启即连云元数据地址一并放行），须显式立项、写明理由与范围，并与网络分段组合收窄，列为必测项。不许默默关安全开关，也不许默认牺牲拓扑。
- 对应需求：VPS 常驻、暴露面最小、出入双向收口。

### 3.3 执行面与审批双轨

- 工具执行走官方 **Docker 加固后端**（官方生产推荐档），不用 local 裸跑（默认无沙箱、以宿主用户权限执行命令）。
- **容器档与命令检查的真实关系（评审钉死）**：据上游源码口径，容器类后端下危险命令检查是否跳过取决于**宿主访问**——无宿主路径挂载时常规危险命令检查被跳过（容器即边界），但用户配置的 `approvals.deny` 硬规则仍生效；有宿主路径挂载时走正常检查。因此本方案的姿态是**钉死部署形态**，而不是假设两道闸叠加：
  - **不挂载宿主目录**（确需挂载时只读、且在执行记录中明示），不靠"多挂目录"换取审批触发；
  - 命令面防线由三层组成：容器参数收口（下条）+ `approvals.deny` 自定义硬规则 + 写入审批（§3.4，独立于命令检查、不受容器档影响）；
  - 写明边界：**终端隔离 ≠ 进程隔离**——插件、hooks、技能加载与 MCP 代码在进程内运行，不受终端后端隔离覆盖，其风险由 §3.4 的治理与零安装纪律承担。
- **容器参数目标值**：`docker_forward_env` 为空（注意：此项为空不等于无凭据透传，技能声明的透传路径须另行核查）；`docker_network` 按需分段（与 §3.2 出口基线一致）；`container_persistent: false`；资源上限与 VPS 规格匹配（`container_memory` 默认约 5 GB，须按实际规格调整，不得与规格预留冲突）。
- **审批双轨（本版拆分，禁止再混作一套）**：
  - **命令审批**（工具执行层）：人工裁定的范围与模式在执行时明示（默认 smart 模式含辅助模型自动决定，不是"每条命令都由人批"，不得以"审批已开启"含糊带过）；timeout 运行态保持短超时 + fail-closed（超时即拒绝）；过期的审批不可重开，迟到的批准不得落到下一次请求上（验收核，见 §7）。
  - **Runs 审批**（API 长任务层）：本阶段只要求"挂起不超时丢失、不重启可走完"（§7 本体级验收）；其重启语义已确认为**中断终态**（run 关停落为 `interrupted`、网关待审批队列为进程内存态），跨重启恢复不是上游保证，归接入期两级验收的第二级（§7、§8-C）。
  - 无人值守面的 `unattended_mode` 维持默认 deny（危险命令即时拒绝）。
- **零成本加固建议项**：`HERMES_WRITE_SAFE_ROOT` 限定文件写入根目录（与 Docker 后端叠成双壳）；Managed Scope（若所装版本支持）把治理基线钉为管理员受管、Agent 自身不可改的配置——采用与否在执行前按版本支持状态确认。
- 对应需求：安全收口（执行受控、无人值守审批可用）、输出与审批回流（本体级）。

### 3.4 记忆与自学习治理（开跑前硬基线，不可后补）

**配置键基线**（执行时按所装版本复核键名）：

- `skills.write_approval` 开启；`memory.write_approval` 开启——自写技能、自写记忆一律先经审批才落盘。
- `curator.enabled: false`；`auxiliary.background_review.enabled: false`——直接关闭，不留"或设死上限"分支：curator 的迭代上限写死在上游源码（非配置项），在本方案"不改源码"约束下只有关闭一途（理念 5 本阶段的落地即关停）。
- `skills.creation_nudge_interval`、`memory.nudge_interval` 置 0（关掉周期性自动触发写入的提醒机制）。
- **会话预算保持非零上限**：会话 token/费用上限不得置 0（353M 事故的另一半根因正是兜底被人为改成无限）；并在模型服务商侧设消费上限，作为第二道熔断。
- 可选云组件全部关闭并逐项审计：Portal Tool Gateway 不启用、Honcho 不接入、不绑定任何厂商托管服务。

**自治面清点**（理念 5 的完整落地，开跑前逐项确认、结果纳入 §7 回读）：

- cron 存储为空且无任务（**含暂停态**——暂停的 cron 仍会被维护机制视为引用）；heartbeat 关闭；无 standing goals / recurring loops；内置插件逐个明确态（至少要知道 disk-cleanup 一类在跑什么）；插件目录零安装。
- **本阶段不创建任何 cron / loop / goal**。注意：gateway 常驻本身就是调度宿主，零渠道 ≠ 零自治宿主；且定时任务的机器注记会以用户角色混入对话并被记忆吸收（#141912）——自治调度不只是成本源，还是记忆污染源。

**审批纪律与写入恢复**：

- 批准前必须看写入全文（技能看 `/skills diff`），**空内容或体量骤降的写入一律拒绝**——#142069 的 0 字节路径跳过了内容校验，审批人是这条路径的最后防线。
- 待审队列本阶段在 CLI 处理，定固定节奏清理，不许长期堆积。
- 记忆/技能目录实行**变更前快照纪律**（形态由执行者定）；任何备份/同步机制列入审计清单，未审计不得开启（0 字节事故靠跨机同步放大；上游的账本记录 ≠ 回滚能力）。
- **工具层观察项**：#142069 根因在 `skill_manage` 工具层、评审时点仍未修复、且前台对话路径可达——关停后台写入者只消除已知触发路径，不消除缺陷本身。开跑后定期检查技能目录 0 字节/异常文件；执行时核实 `write_approval` 对 `skill_manage` 的 `write_file` 路径的覆盖性并记录结论。

**占槽口径（改写）**：

- 本阶段不占 MemoryProvider 槽：先以治理后的原生记忆运行，槽位预留（节奏定调见 §1；调整清单取舍项 A 已定为两步走）。
- 必须钉死的前提：**占槽只是接入通道，不是记忆权威让渡**。官方明示外部 memory provider 与内建记忆**并存、永不替代**（"run alongside built-in memory, never replacing it"），且占槽激活后内建记忆会自动**镜像写入**外部层。
- 接入期必答四题（不答不占槽）：① 内建两处存储（`memory.memory_enabled`、`memory.user_profile_enabled`）关不关——注意不可禁用整个 memory toolset（会连外部 provider 的工具一起隐藏）；② 镜像写入的治理与归属打戳（防共享层被未经审批的本体镜像污染）；③ 阶段一攒下的原生记忆的导出/让渡格式（防经验数据锁死在 Hermes 原生格式里）；④ 外部 provider 自有写路径（如 `sync_turn()`）的治理归属（不可假定原生 write_approval 自动覆盖）。

对应需求：记忆不垄断（先治理、接入期处置权威）、数据主权（无强制云依赖）、经验数据可信。

### 3.5 模型接入与凭据

- 模型路由（2026-10-28 用户定向基线）：主模型经 cloudrelay 中继接入 Claude Sonnet 5.5，fallback 为同中继的 GPT Terra，两端点已经冒烟验证。经中继意味着对话上下文与工具输出多经一道第三方中继——属用户知情选择，下方数据主权边界声明按此理解。其余模型开跑后以纯配置逐个追加，不返工。
- **凭据三层（取舍项 B 的修订框架）**：
  - **地板**：密钥文件（`~/.hermes/.env`）权限 0600——官方生产部署清单同款背书；且 Hermes 子进程环境默认剥离其托管凭据（仅显式声明项透传），爆炸半径有限。
  - **顺手项**（开跑基线内、一次性配置、零日常运维）：`auth.adopt_external_logins` 设为 **false**（默认 true 会借用机器上 `~/.codex`、`~/.claude` 等其他工具的登录凭据，属必须显式关掉的放行型默认值）；使用**专用、可撤销、低额度**的 API key；在模型服务商侧设消费上限（与 §3.4 第二道熔断同条；2026-10-28 落地形态为账户预付费、余额耗尽自动停机，验收结论 §3 已裁定其实质满足，开通自动充值或长期放大余额时须重估）。
  - **可选项**：密钥注入**不是改造**——Hermes 原生支持 Bitwarden Secrets Manager / 1Password / command helper 三类秘密源，全为配置级（小时级）。是否启用、何时启用，由用户按风险接受度定，不挡开跑、不必等"迭代期"。
  - **磁盘加密降为可选加固**：无人值守 VPS 上自管全盘加密的开机解锁与"开机自启、异常自拉起"互斥，厂商侧盘加密又不防宿主与运行时泄露；采用前须先核解锁方式与重启恢复的兼容性，不列入基线承诺。
  - 密钥经安全输入进入机器，不经过聊天与仓库。
- **数据主权边界声明**：本方案的"数据主权"限定于 Hermes 侧（无遥测、无强制云组件、状态本地、凭据本机）。使用远程模型 API 时，对话上下文与工具输出必然上行至模型服务商——这是 LLM 使用的固有面；实际发送范围随所用工具与任务在执行时核查，**不以"云组件已关"推断"数据不出机"**。
- 对应需求：多模型、数据主权（凭据在本机、边界诚实）。

### 3.6 渠道与外部接入（本阶段范围界定）

- **本阶段接入一个消息渠道：Telegram**（2026-10-28 用户定向，覆盖原"零渠道"口径）：供用户本人发起对话与接收审批回流。**渠道自动化（由渠道消息自动触发任务、无人值守执行）不在本阶段范围**，启用须另行评审，并一并重估 §3.4 的熔断边界。其余渠道接哪些、归哪个节点管，仍是取舍项 D，迭代期逐个定、逐个开（理念 2）。
- **本阶段不建 MQTT 桥、不接数据层**：二者属接入期（见 `hermes-adjustments.md`）。本方案只预留其 Hermes 侧配置面：设备专用 Webhook route（独立 secret、窄 prompt 模板、限定 toolsets）+ API Server 调用；桥的具体方案在接入期另行成文评审。预留注记：设备 route 的约束以 **toolsets 收窄 + `approvals.deny`** 为准，不依赖危险命令审批（无人值守面默认即时拒绝危险命令；容器档下该层检查亦可能被跳过，见 §3.3）。

**桥的设计约束（接入期前置要求，2026-10-22 用户提出、四方评审加厚）**：桥是所有 Agent 接入的收敛点，按"有意收敛、严格设防"设计——其权力只来自位置，不来自功能。

1. **薄且无状态**：只做协议翻译、凭据打戳与路由；不含业务逻辑、不存数据本体、不拥有持久业务/会话状态。任务与审批状态由 PAT **工作记忆层**（蓝图的独立薄层，与只增不改的主权资产库分离）或 Agent 侧承接，桥可重启、可替换、可多实例。
2. **一侧固定、一侧插件**：PAT 侧接口固定为本仓契约（蓝图层间协议 + `contracts/`）；Agent 侧为插件位，每个 Agent 一个 adapter 模块，新增 Agent 只加模块、不改桥芯。PAT 侧固定的是行为语义；各 Agent 私有的 run/状态/错误映射留在各自 adapter 内。
3. **能力声明**：每个 adapter 显式声明其能力（如审批长挂起、流式、toolsets 支持），声明须对应**已验证的构建与运行模式**（"可查中断结果"不得声明成"可原地续跑"）；Hermes 侧优先以官方 `GET /v1/capabilities` 特性位机械抓取，不靠猜。SSRF/私网配置面（§3.2）列入 adapter 必须显式声明的配置面之一。
4. **故障隔离**：单个 adapter 故障、超时或积压不影响其他 adapter 与桥芯。
5. **契约测试**：每个 adapter 交付时附对 PAT 侧契约的一致性测试，覆盖**失败语义**：重复投递、过期/错配审批、重启、不确定执行结果的处理。"翻译正确"以测试为准。
6. **降级不静默**：翻译中发生的能力降级或语义丢失必须记录可见；凡**影响批准或写入**的语义缺失，必须拒绝执行或显式转交人工，不得执行后只补日志；可接受的降级才记录后继续。
7. **身份与入站防护**：每个 adapter 使用独立的 PAT 侧凭据（与 §3.7 的服务端凭据打戳衔接，桥侧凭据是打戳的基础）；桥的入站面须有鉴权与限流；设备事件投递须有幂等/防重放口径（可借鉴上游 Webhook 的 delivery-ID 幂等与时间戳签名）。

边界提醒：桥不在采集路径上（采集 → 数据层不经桥），桥故障只影响 Agent 的实时消费，不影响数据主权与事后补读。本节约束适用于将来所有 Agent 的 adapter，不限于 Hermes。

### 3.7 舰队身份（PAT 侧约定，非 Hermes 配置）

- 写入归属与 `agent_id` 由 PAT 侧（未来的共享层/数据层服务端）按凭据强制打戳实现，本体零改动。本阶段无数据层，此项仅记录、不实施。

## 6. 调研依据（评审可审计）

- **适配度评估**（六个成品 × 五个契约面，文档 + 源码级核验，无活体冒烟）：Hermes 92 分居首，唯一"配置 + 一条 MQTT 薄桥"可跑通阶段一验证者。全文见 `platform/research/vps-agent-selection-report.md`（2026-10-22 整理入仓）与 `design-harvest.md` 相关条目。
- **决赛对比**（Hermes vs QwenPaw）：Hermes 赢在契约面稳定（文档化 Runs API + MCP 双向 vs 无承诺的前端同源 API）、记忆治理闸现成（全配置级）、失败模式已知（事故皆有尸检可逐条设防）、常驻运维成色（一键服务化 + 快照回滚升级）。翻盘条件已记录在案（同上选型记录），本方案默认其未触发；其中"中国 IM 入口"一条已因 Hermes 频道核查（28 个官方适配器、中国系覆盖与 QwenPaw 打平）下调分量。
- **事故实证**（支撑 §2 理念 1、5 与 §3.4）：Curator 死循环 20 小时、5,501 次调用烧掉 353M tokens（双根因：迭代上限被设为 9999、全局预算兜底被人为改成 0）；后台 review 把技能文件写成 0 字节并同步到其他机器（Issue #142069，2026-10-20，评审时点仍未修复、根因在工具层且前台可达）；机器生成的样板话与定时任务注记被当作用户事实写入长期记忆（#141912 等）；整合失败却被记录为 completed（#137967）。
- **安全实证**（支撑 §3.1、§3.3）：Dashboard 存在预授权漏洞（含会话接管），已修于 v0.21.6；CVE-2026-71963（GitSpawn）的修复状态已钉死（见 §3.1）；官方文档明示插件在进程内运行、非沙箱，Docker 后端为官方生产推荐并写死加固参数；容器后端下危险命令检查的跳过条件（宿主访问判定）与 `approvals.deny` 的存续，经评审方源码级核验。
- **对照教训**（支撑 §7 两级验收）：QwenPaw 的审批为内存态、默认 300 秒超时、进程重启即丢失——"长挂起审批"是同类产品的已证伪点；Hermes 的 Runs 重启语义经评审核验为中断终态，故跨重启恢复自始按 PAT 侧设计处理，不指望本体。

**本体开跑验收（下列全过才算开跑完成）**：

- 命令审批行为实测：批准 / 拒绝 / 超时三态符合 §3.3 姿态，迟到的批准不落到下一次请求；

- 写入行为冒烟：经 API 触发一次记忆/技能写入 → 只进暂存不落盘 → 待审项可见 → 批准后以**文件侧证据**核对落盘正确、拒绝后无残留（不采信会话自述）；

- 服务重启后自恢复；安装版本号与配置哈希入冒烟档案，版本与配置无漂移。

**接入期验收预告（不在本阶段卡口，先立判据）**：跨重启业务恢复按判决矩阵裁定——原审批状态保留且可解 = 通过；状态保留但需重新发起审批 = 有条件通过，按 §8-C 的分段 run 设计推进；状态丢失或中断被误报为完成 = 不通过，兜底设计强制进入接入期方案。恢复的状态载体为 PAT 工作记忆层，不进主权资产库。接入期开始前另行成文评审（含 §3.2 的 SSRF 议题、§3.4 的占槽必答四题）。

- **A 占槽节奏**：**已定**——两步走（先治理后原生记忆运行、共享记忆线就绪后再占槽）。接入期占槽前必须先答 §3.4 的必答四题。
