## 逐条账

### 1. 开放协议接入

- **需求原文要点**：蓝图「数据层」——开放格式（标准视频容器、结构化 JSON 事件）、开放协议（MQTT/HTTP/文件）；「Agent 适配层（长期）」——数据层包装成 MCP server，任何支持 MCP 的 agent 即插即用，换 Agent 只换消费端。核对框架补充：能被 PAT 编排（外部驱动 run、拿状态、给审批结论）。
- **Hermes 现状**：**满足**。MCP client 原生（三 transport＋OAuth＋sampling），可直接消费数据层 MCP server；自身可被编排的面是全场最强：异步 Runs API（建 run／轮询状态／SSE 事件流／stop／steer／approval 皆一等公民）；另有 `hermes mcp serve` 可把它的渠道面反供其他 agent。
- **差距**：不在 Hermes 侧，在 PAT 侧——数据层目前还没有被包装成 MCP server；Hermes 的 MCP client 凭据与工具权限需要在接入时按最小权限配置。
- **调整动作**：①（PAT 侧）把数据层资产库包装为 MCP server（只读消费面先行，写入面走资产库自有通道，不经 agent）；②（Hermes 侧，配置）接入时为数据层 MCP server 配独立凭据、按工具粒度收窄权限。
- **层级**：配置（Hermes 侧）＋旁路/PAT 侧建设（MCP 包装）。
- **优先级**：接入期。
- **工作量**：Hermes 侧配置半天内；PAT 侧 MCP 包装 3–5 天（量级估算，非 Hermes 调整，但为本条前置依赖）。

### 2. 事件唤醒

- **需求原文要点**：蓝图层间协议固定为 MQTT（事件/触发/审批卡片/通知）＋HTTP；铁律「私有协议终止于 adapter」；Agent 层职责含 L4 策略下发（云端按上下文动态调采集策略）。ESP32/外部事件须能唤醒 agent，agent 的策略下发须能回到设备。
- **Hermes 现状**：**不满足**——无原生 MQTT，全频道清单（28 适配器）中唯一的设备事件面是 Home Assistant 插件。入站 Webhook 可触发一次 run（HMAC 签名），Runs API 可异步建 run 并取回结果；入站 Webhook 的结果**不回调用方**（只投递到聊天平台/log）。
- **差距**：MQTT ↔ Hermes 之间缺一座桥；下行（策略下发、回复回设备）同样缺。
- **调整动作**：建 **MQTT 薄桥**（常驻小进程）：订阅唤醒主题 → 译成 Runs API 调用（需要结果时）或 Webhook 触发（只上报不等回复时，桥代算 HMAC）；桥轮询/SSE 订阅 run 状态 → 结果与 L4 策略 publish 回设备下行主题（broker 持久会话兜设备休眠）。Hermes 私有面（签名规则、Runs API 形状）只活在桥里，固件与 broker 拓扑不感知 Hermes——即蓝图 adapter 模式的原样落地。Hermes 侧只需开配置：`WEBHOOK_ENABLED`＋设备专用 route（独立 secret、窄 prompt 模板、限定 toolsets）、API Server 绑内网＋`API_SERVER_KEY`（仅供桥调用）。
- **层级**：旁路（桥）＋配置（Hermes 侧开关）。
- **优先级**：接入期（ESP32 事件接入之前必做；不挡 Hermes 本体先开跑）。
- **工作量**：1–3 天（估算，含下行回注与休眠兜底）。

### 3. 输出与审批回流

- **需求原文要点**：蓝图数据流示例 3「Agent 办公审批」——agent 产出 → pub/sub 发布审批卡片 → Tier 2（e-ink/手机）或 Tier 1 渲染 → 用户批准 → 结果回传；Tier 2 是开放渲染目标（pub/sub：向主题发布结构化输出，各显示面订阅渲染）。核对框架补充：长挂起审批（小时级）不能丢。
- **Hermes 现状**：**部分满足**。审批机制本体一流：命令审批默认开（LLM 分级＋Hardline 黑名单＋无人值守默认 deny＋超时 fail-closed），Runs API 有一等 `/approval` 端点，PAT 侧可编程地拿待审批项、回审批结论；出站 Webhook（hooks.outbound）可把生命周期事件推给外部。但它的原生审批呈现面是**自己的聊天渠道**，不是 PAT 的 pub/sub 渲染目标；审批卡片进 MQTT 主题、Tier 1/2 渲染、按钮回传这条链不在本体里。
- **差距**：①审批/输出到 PAT 渲染面的中继缺失；②**待冒烟验证**：Runs API 审批挂起的最长时长、进程重启后待审批状态是否可恢复——文档级未钉死（此项曾是 QwenPaw 的决定性死因：内存态 300 秒、重启即丢；Hermes 须实测排除同类问题）。
- **调整动作**：①建**审批中继**（可与第 2 条薄桥同体）：订阅 run 事件/出站 hooks → 渲染为卡片 JSON publish 到 MQTT 审批主题 → 收用户结论 → POST 回 Runs `/approval`；结构化输出同路发布到输出主题供各显示面订阅。②接入期冒烟专测审批长挂起（发起 run → 挂起 ≥2 小时 → 期间重启 Hermes 进程 → 恢复并完成审批），结果决定是否需要 PAT 侧"分段 run"兜底设计（run 切段＋状态存 PAT 侧）。
- **层级**：旁路（中继）＋验证项。
- **优先级**：接入期。
- **工作量**：中继 1–3 天（与薄桥同体时取下限）；冒烟半天。

### 4. 记忆不垄断

- **需求原文要点**：蓝图设计原则 7＋工作记忆层一节：长期记忆权威不在 agent 本体一侧独占（多 Agent 共享记忆层为独立项目线，权威在 PAT）；工作记忆层是独立薄层（只存指针、TTL、任务作用域、乐观并发），不进数据层。核对框架：Hermes 自带记忆/自学习写入必须可治理（审批门/可关停），记忆可外置。
- **Hermes 现状**：**部分满足**——治理面全场最好，但默认态不合：自学习闭环默认会自己写技能、维护记忆（事故实录：Curator 死循环 20 小时烧 353M tokens；后台 review 把技能写成 0 字节并同步他机；机器样板话被存为用户事实）。好消息是闸全是现成的：skills 与 memory 两处 `write_approval`、curator 与 background_review 可关，**全部配置级**；官方 **MemoryProvider 插件位（单槽）**可让 PAT 的共享记忆层坐正权威位置；本体记忆有硬上限（MEMORY.md 2,200 字符量级），会话史为本地 SQLite＋FTS5（属会话史、非长期权威，可接受）。
- **差距**：①默认自学习写入未治理（开跑前必须先关/设门）；②MemoryProvider 单槽尚未由 PAT 占住；③Honcho 等可选云记忆组件必须保持关闭，否则出现第二权威；④待冒烟验证：write_approval 在无人值守/API 模式下的完整行为（草稿落点、审批入口）。
- **调整动作**：开跑前（配置）：两处 write_approval 全开；curator、background_review 关闭（或给 curator 设死迭代/预算上限——353M 事故根因即上限被拆）；云记忆组件（Honcho）保持关。接入期（插件）：开发 PAT 的 MemoryProvider 插件（后端接共享记忆层，Hermes 本体记忆降为草稿/缓存语义）；Hermes 经 MCP client 读写工作记忆薄层（thread 作用域）属使用约定，无需改本体。
- **层级**：配置（治理）＋插件（占槽）。
- **优先级**：治理＝开跑前必做；占槽＝接入期。
- **工作量**：配置约半天（含逐项核对开关生效）；插件 3–7 天（既有估算）。

### 5. 多模型

- **需求原文要点**：蓝图原则 5「不把任何当前模型能力当永久约束」、Agent 层可替换；核对框架点名：DeepSeek/Kimi/Qwen/GLM＋OpenAI/Anthropic 均可接入与切换。
- **Hermes 现状**：**满足**。原生 provider 含 DeepSeek、Kimi/Moonshot、DashScope（Qwen）、GLM、OpenAI、Anthropic、Gemini、OpenRouter 等，`hermes model` 一键切换；官方与自家模型明确解耦（文档甚至写明自家 Hermes 4 模型"不推荐在 Hermes Agent 内使用"，中立性有原文证据）。
- **差距**：无功能差距；只有配置动作（各 provider key、默认模型、按任务的模型策略属使用层约定）。
- **调整动作**：开跑前配齐常用 provider 凭据并定默认模型；模型切换走本体命令/API 参数，不做任何封装改造。
- **层级**：配置。
- **优先级**：开跑前（无模型无从开跑）。
- **工作量**：1–2 小时。

### 6. 数据主权与隐私

- **需求原文要点**：蓝图核心目标——采集、存储、定价、授权全在自己手里；原则 1/3：数据不进厂商黑盒、不依赖厂商私有协议管线。核对框架：无强制云依赖、无遥测、凭据与状态在本机/自有 VPS、云组件可全关。
- **Hermes 现状**：**满足**（一处保留）。无托管 SaaS 依赖，状态全本地（`~/.hermes`），自托管形态**无遥测实证**；可选云组件（Nous Portal Tool Gateway、Honcho）为显式 opt-in，可全关。保留项：**凭据为明文文件**（`.env` 0600＋auth.json，无加密金库）——权限位正确，但明文落盘的事实需要处置决定（见拍板项 B）。
- **差距**：云组件默认关的状态需要在开跑前逐项审计确认（防版本升级改变默认）；凭据明文一项需用户定风险接受度。
- **调整动作**：开跑前：关闭并审计 Portal Tool Gateway、Honcho 及一切可选云面；确认无厂商账号绑定需求；凭据文件权限保持 0600、所在 VPS 磁盘加密作为运维基线（迭代期可再评估密钥注入方案）。
- **层级**：配置＋运维。
- **优先级**：开跑前。
- **工作量**：半天（含审计清单逐项过）。

### 7. 常驻与运维

- **需求原文要点**：核对框架：VPS 常驻服务化、升级可控可回滚、资源占用可接受（蓝图未单列此条，属阶段一运行基线）。
- **Hermes 现状**：**满足**。`hermes gateway install` 一键成 systemd/launchd 服务，Docker 有 s6 监管；`hermes update` 带升级前快照＋自动回滚，v0.21.7 起默认跟 stable 通道。资源量级（第三方指南口径，无官方空载实测）：API-only 约 1vCPU/1GB 可跑，带浏览器工具建议 ≥2GB。
- **差距**：升级翻车有实录（stable 通道 update 探测超时、锁文件漂移、插件移出 core 后不再随 update）——能力有、纪律要自加。
- **调整动作**：开跑前：以 gateway 服务形态安装；关闭自动升级，升级只手动、只在有快照时跑，升后按清单验一遍渠道/审批/记忆开关；VPS 规格按 ≥2GB 内存预留（带浏览器工具口径）。
- **层级**：配置/运维。
- **优先级**：开跑前。
- **工作量**：2–3 小时。

### 8. 安全收口

- **需求原文要点**：核对框架：执行面沙箱/受控、网络暴露面最小、命令审批可用于无人值守。蓝图侧呼应：数据主权姿态下节点不得裸奔（QwenPaw 的 Console 默认关鉴权即因此被记大坑，标准一致）。
- **Hermes 现状**：**部分满足**——体系完整但默认档不合：默认 local 执行后端**无沙箱**（以本人 OS 权限跑）；插件在进程内运行、官方明示不是沙箱；Dashboard 曾有预授权洞（含会话接管，**已修于 v0.21.6**）；CVE-2026-71963（CVSS 8.6）修复状态各源不一，须按版本自查。正资产：Docker 后端为官方生产推荐（cap-drop ALL 等加固写死）；命令审批默认开且 Hardline 黑名单连 `--yolo` 都越不过、无人值守默认 deny、超时 fail-closed；技能安装强制隔离扫描＋信任分级＋hash 锁定；输出脱敏管线细（工具输出/子进程 env/MCP 报错三道）。
- **差距**：默认执行档与默认暴露面需人工收口后才达标。
- **调整动作**（全配置级，开跑前）：①版本 ≥v0.21.6，并按版本自查 CVE-2026-71963；②工具执行走 Docker 加固后端（或 SSH 后端），不用 local 裸跑；③API Server 只绑 127.0.0.1（桥调用走内网/同机）、Bearer key 必填、Dashboard 与 API 绝不裸奔公网（需远程时反代加鉴权）；④无人值守保持命令审批开启；⑤技能只装经扫描的、hash 锁定。
- **层级**：配置。
- **优先级**：开跑前必做（整条）。
- **工作量**：半天。

### 9. 多 Agent 舰队位置

- **需求原文要点**：**来源标注**——此条来自核对框架与多 Agent 舰队理念（用户 2026-10-20 定调：不忠诚于单一 Agent，节点只是舰队一员）。蓝图原文只确立了"多 Agent 共享工作记忆薄层"与"Agent 层可替换"，**agent_id/写入归属约定并未写入蓝图**（协调约定曾提议写入、经用户决定关闭），故本条按框架核对、定位为 PAT 侧约定而非蓝图铁律。
- **Hermes 现状**：**不满足（本体无此概念）**。Hermes 的自我定位是"用户的那一个助手"：单一 gateway 汇聚全部渠道、会话与记忆以自身为中心；其内部子 agent 是它自己的编排，不带对外归属标识；它经 MCP/数据层写入时不会自带 `agent_id` 戳。
- **差距**：写入归属与身份标识要由 PAT 侧在边界上补：不带戳的写入进共享层即污染归属（呼应数据主权 lineage 要求）。
- **调整动作**（全在 PAT 侧、本体零改动）：①数据层 MCP server 与工作记忆薄层在服务端按调用凭据强制打戳（每个 agent 一组凭据 → 写入自动带 `agent_id=hermes`＋时间戳），不信任 agent 自报；②薄桥以 Hermes 专用身份调用其 API，事件/审批流转中透传归属；③渠道归属纪律：Hermes 网关连接的渠道即归它管，其他 agent 不共用同一网关身份（渠道层面的分工属使用约定，见拍板项 D）。
- **层级**：旁路（PAT 侧约定与服务端强制）。
- **优先级**：接入期起步（首次向共享层写入之前必须有打戳），迭代期完善（归属审计、冲突策略）。
- **工作量**：随第 1/2 条建设顺带，无独立大项。

## 汇总

### 开跑前必做（共 8 项，总工作量约 1–1.5 天，全部配置/运维级，无一项动源码）

1. 版本 ≥v0.21.6 安装，并按版本自查 CVE-2026-71963 修复状态
2. 记忆治理：skills/memory 两处 write_approval 全开；curator、background_review 关闭或设死上限
3. 云组件全关审计：Portal Tool Gateway、Honcho 等可选云面逐项确认关闭、无厂商账号绑定
4. 执行面收口：工具执行切 Docker 加固后端，不用 local 裸跑
5. 暴露面收口：API Server 绑 127.0.0.1＋Bearer、Dashboard 不对外、网关渠道按需开
6. 无人值守审批策略确认：命令审批保持开、超时 fail-closed
7. 服务化与升级纪律：gateway 装成 systemd 服务；关自动升级，手动带快照升级
8. 多模型凭据与默认模型配置

### 接入期（PAT 层逐个接上时）

- MQTT 薄桥（含下行回注与 L4 策略下发）1–3 天
- 审批中继（卡片 publish／结论回 POST）与薄桥同体 1–3 天

### 需要用户拍板的取舍项

- **A. 记忆占槽节奏**：一步到位（开跑即由 PAT 的 MemoryProvider 占槽、本体记忆只当草稿）vs 两步走（先以"治理后原生记忆"跑一段真实使用、攒够体验再占槽）。影响阶段一经验数据的形态，须用户定。
- **B. 凭据明文落盘**：接受"0600 明文＋VPS 磁盘加密"的基线（零额外工作），还是迭代期投入密钥管理注入（旁路改造，额外工作量且引入新组件）。属风险接受度决策。
- **C. 审批长挂起的兜底形态**（冒烟出结果后拍板）：若 Hermes 审批挂起扛不住小时级/重启，接受 PAT 侧"分段 run＋状态存 PAT 侧"的设计约束，还是将其视为必须解决的阻塞项。
- **D. 渠道归属分工**：Hermes 网关接入哪些渠道归它管（如 Telegram/飞书），哪些留给舰队其他节点——影响各节点的身份边界，属舰队分工决策（迭代期定即可）。
