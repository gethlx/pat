# PAT 阶段一实施规划

> 状态：实施规划草案。2026-11-08 已裁定阶段一采用 macOS 桌面版。
> 维护线：整体线
> 最后更新：2026-11-08
> 摘要：用一个 macOS 桌面窗口手动选择 Agent、派活和打开结果。以两个真实执行器验证共用 Git 账本、重复投递与事件恢复。
> 依据：提交 `6b291e9` 的 [v2 蓝图](architecture-v2.md) §三、§四、§八、§九、§十一。阶段一入口及对应验收按 [2026-11-08 桌面版裁定](../AGENTS.md#当前阶段随进展更新本节)执行。

## 首版给谁用

阶段一面向已有 Agent 的个人 macOS 用户。打开 PAT 后，在同一窗口选择 Agent、写任务、看进度、打开结果。应用显示所选 Agent 和任务记录，用户可以回看原请求与产物。每个新任务由用户明确选择一位 Agent，名册支持多个实例。

**PAT 自建桌面壳。** 建议用 SwiftUI 做单窗口，应用内用 Swift 实现受理、派活、产物核验与 Git 记账。Foundation `Process` 用于启动 Git 和已配置的执行命令。Codex CLI 等工具可经各自公开入口登记，选择权在用户手里。首版正式验收至少覆盖两个不同 Agent 的真实接入，每次只派给用户选中的一家。桌面体验参考 OpenBot 的统一入口和手动选人。 [Apple SwiftUI App](https://developer.apple.com/documentation/swiftui/app) · [Apple Foundation Process](https://developer.apple.com/documentation/foundation/process)

## 技术边界

| 部件 | 首版做法 |
|---|---|
| 桌面壳 | 计划在 `platform/desktop/` 放一个 macOS App target。窗口和协调逻辑随同一个 `.app` 交付。Git 与执行调用在后台执行，窗口保持响应。账本写入沿用单机串行与操作系统文件锁，任务归属以远端为准 |
| 名册与配置 | 一份本地 JSON 配置保存账本路径、任务工作目录和多个执行器实例。设置中可添加或修改名称、可执行文件路径、参数和超时。实例沿用 `mode`、`invoke`。阶段一运行已接通的 `push` 实例。其他实例可显示其待接入状态。执行命令用完整路径，启动前核对 Finder 环境下的授权与可用性。阶段四若迁移至 `agents.yaml`，继续只维护一份名册 |
| 执行工作目录 | 每次任务使用独立的普通目录，放经用户选定的输入与预期输出。阶段一只支持小型文本产物。账本 checkout 与执行目录分开 |
| 私有账本仓 | 按蓝图 §4.3 建立一个独立仓，使用 `events/`、`tasks/` 及约定的记忆目录。首版小文本产物放 `artifacts/<任务 ID>/`，和结果记录一起保存。设计仓保留应用源码、模板与合成样例 |
| 共享接口 | 以 [记忆接入契约草案](../contracts/memory-integration-spec.md) 为候选，共享来源、事件、回传和确认的语义。运行时阶段二仍复用 Git 载体 |

首版范围是一个窗口、一套账本和手动选人。阶段二接 Telegram、关键词检索、主动回传与换人接手。阶段三做常驻拉取加固。阶段四接宰相与自动路由。 [蓝图阶段表](architecture-v2.md#八分阶段)

## 用户路径

用户从 Finder 打开 PAT。首次在设置中指定已有的私有账本 checkout 和工作目录，并登记已有登录态的执行器。设置页给出路径缺失、授权失败等可处理的提示。凭据由执行器与 Git 各自管理。用户启用账本同步时授权壳向指定私有仓提交任务记录与获准产物，项目代码的提交和推送按各项目授权执行。

| 窗口区域 | 最小内容 |
|---|---|
| 任务表单 | Agent 下拉列表、任务文本、预期结果文件名与「派活」。新任务显示「请选择 Agent」，提交前明确展示所选实例。缺少配置或启动失败时，显示原因和修复入口 |
| 当前任务 | 任务编号、所选 Agent 与状态。展示正在派活、执行中、待核对、已完成，状态来自实际运行与账本回执 |
| 最近任务 | 显示原请求、执行器与可打开的产物。中断后能打开工作目录，并在用户核对后选择补记完成或释放任务。已有产物尚待同步时提供继续同步原记录的入口 |

应用为每次提交保存一个稳定的 `desktop:<UUID>` 来源编号，重试沿用原编号并展示现有任务。正在提交时暂停重复点击。释放后需由用户在原任务上明确重派。日志放在详情中，主窗口显示能采取的下一步，例如「结果已生成，点击继续同步」。

阶段一的真实样例使用两条无敏感内容的项目事实和整理要求。用户在窗口选择第一个 Agent，派活并打开 `result.md`。随后新建一条任务，在同一窗口选择第二个 Agent，核对两条任务的归属和产物。任选一条重试同一提交，并在临时副本重建它。

## 执行与记账

1. **受理。** 锁住账本写入，验证用户选择、配置与执行器入口。读取专用 checkout 的远端最新状态。用户请求、文件路径与期望产物作为数据传入执行命令。用界面保存的稳定 `source_ref` 在三个任务目录查重。同键同请求展示已有任务，同键变更内容或执行器时提示人工核对。
2. **领取。** 保留蓝图九个任务字段，用所在目录表示状态。壳读取所选实例的 `mode` 和 `invoke`，多个本地执行器共用一条推模式流程。创建、领取均由壳写事件，可以在同一提交中先建后领。壳只暂存本次任务、事件和约定产物路径。普通推送后读回远端，确认任务仍在 `claimed/`、最新领取事件为本次记录，再启动进程。明确冲突时重读当前任务，远端结果未知时暂停核对。 [Git push 官方规则](https://git-scm.com/docs/git-push#_push_rules)
3. **执行。** 壳在指定工作目录启动所选执行命令。执行器使用自身支持的工作区限制与用户已有授权。阶段一只派纯文本本地产物任务。执行进程在账本工作目录之外，壳仅把本任务材料和允许的必要环境传给它。工具回传、退出码、超时及输出分别记录。用户停止时终止本次进程并保留可核对的输出。
4. **完成。** 检查指定产物存在、可读且在工作目录内，拒收路径越界和符号链接。确认它符合预期文件类型并可供用户打开。壳再次核对当前领取事件，复制获准产物，生成路径与内容校验值，连同完成事件和任务移动写入同一个 Git 提交。远端读回确认后才显示「已完成」。结构和文件校验由脚本做，样例内容是否正确由验收者打开确认。
5. **待核与人工处置。** 非零退出、超时、产物缺失、执行后失联或提交未确认时保留 `claimed/` 与本地证据，窗口提示具体原因。再次提交同一请求显示现状。确认旧执行已停止、已有产物与外部动作已核对后，用户可以补记完成，或释放回 `inbox/` 后显式重派。结果提交已在本地但远端未确认时，先核对该提交和当前归属，再补推已有记录。应用重启后按账本恢复最近任务，遗留的已领任务显示待核对。

每次账本变更保留事件中的变更后任务快照与目录，格式见接入契约。JSONL 按壳的 UTC 写入日分文件。回放按远端账本提交顺序读取新增事件，同一提交内按追加行序。发现来源冲突、同 ID 不同内容、账本缺对应事件或本地有未处理改动时停止写入，保留现场供用户核对。首版同步普通快进，处理冲突使用专用 checkout 或新临时副本。

## 维护与恢复

- 应用启动、查看历史和任务结束时检查逾期 `claimed/`、未完成同步和引用失效。结果显示在当前窗口，含任务编号和原因。
- 里程碑从权威远端做完整克隆到独立位置，记录归档对应提交。需要一个文件时可用 Git bundle 打包已入仓历史。工作目录的未提交产物、CLI 登录态和本地配置按各自用途单独管理。 [Git bundle 官方文档](https://git-scm.com/docs/git-bundle#_examples)
- 维护验收从事件向空临时目录重建任务视图。忽略克隆来的 `tasks/`，读事件还原至少一条任务，核对 ID、目录、来源、归属和产物引用。此步骤可由维护者触发，窗口的日常操作使用已保存的任务视图。

## 实施顺序与验收

| 顺序 | 具体交付 | 可检查的完成条件 |
|---|---|---|
| 1. 窗口与执行探针 | 可从 Finder 打开的 `.app`、任务表单、名册设置和临时任务目录 | 窗口显示至少两个已接通的 Agent。用户分别手动选择，各跑一条任务并打开真实文本产物。记录实例、版本、退出值与授权模式，校验无默认选中 |
| 2. 账本闭环 | 私有试用账本、来源查重、同提交记账、最近任务 | 两家任务的创建、领取和完成可从同一账本读回，重开 App 后仍可查并打开结果。同一请求只启动一次，同键改内容或执行器时停下来核对 |
| 3. 异常与恢复 | 失败提示、逾期检查、人工处置、临时回放 | 用一条模拟已产出而未回报的任务验证不再执行。用一次中断或失败推送验证原任务及产物可查。克隆恢复后仅凭事件还原一条任务，与远端账本和产物比对 |
| 4. 交接阶段二 | 可重复的使用说明、一次验收记录、接入契约确认 | 保存任务 ID、产物位置和对应提交。核对蓝图 §十一要求已明确。契约待两区确认后用于真实记忆接入，接入链路另行验收 |

阶段一验收从 Finder 启动应用并实际操作窗口。运行日志记录必要的任务号、时间、结果状态与退出原因。至少验证手动选人、重复派发、失败提示和恢复。日常维护使用窗口状态与任务详情。

## 参考材料如何落到首版

| 参考 | 采用的做法 |
|---|---|
| OpenBot，采收 B21–B23、C8 | 统一入口选择执行器、明确归属、按产物引用交接。Git 一次提交保存对应的任务变更与事件 |
| DeepSeek Super-agent，采收 B19–B20、C7 | 明确派活走确定路径，任务与厂商会话分离，上下文可按原文引用展开。阶段一直接调用用户指定的执行器 |
| Timon，采收 B24–B25、C10–C14 | 失败显露，凭据交给原工具，来源由壳核验后写入，治理只能提案。首版依靠人工确认重跑和晋升 |

这些是本仓对上游的历史采收及本稿的取舍。代码按 PAT 需求自写。详细出处见 [设计采收册](design-harvest.md) 和 [上一轮评审](reviews/2026-11-06-architecture-upgrade-report.md)。

## 待实施核对

- 开工前准备完整 Xcode 并验证 App target 的构建与打包。本机 SDK 的 SwiftUI 窗口及 `Process` 最小类型检查已通过。当前选中的是 Command Line Tools，`xcodebuild` 尚不能用于构建 App target。
- 从 Finder 启动后核对两个选定执行器、Git 登录态和目标账本权限。首版交付本机可打开的 `.app` 与简短设置说明。SwiftUI、单 App target 和本地 JSON 是本稿给出的实现选择。
- 独立子项目的详细设计和里程碑由其维护方确认。整体阶段一的关闭依据是本阶段的账本与交付证据，以及已明确的接入框架。参见 [接入契约](../contracts/memory-integration-spec.md)。
