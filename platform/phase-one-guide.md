## 首版给谁用

阶段一面向能在自己的 macOS 上使用已有 Agent 的个人用户。真机前提是：本机已能非交互调用至少两个已登录的 `push` 执行器、对私密账本仓有写权限，并能从 Finder 打开已构建的 PAT 应用。不要求用户安装完整 Xcode，也不要求在本机打包 `.app` 或安装任何开发工具链。开发、编译、自测和协议/窗口的自动验收在 Linux 开发机上完成。打开 PAT 后，在同一窗口选择 Agent、写任务、看进度、打开结果。应用显示所选 Agent 和任务记录，用户可以回看原请求与产物。每个新任务由用户明确选择一位 Agent，名册支持多个实例。

验收实例怎么选：优先登记蓝图里已实测可驱动的 Codex CLI；第二个选本机已经能跑出文本产物的 `push` 实例。不要为了凑两个去接尚未可驱动的，也不要把不可达实例（例如厂商云电脑）纳入阶段一正式验收。选谁由用户在本机确认，规划只写这条规则，不写死第二家品牌。

**PAT 自建桌面壳。** 用 Electron 做单窗口桌面壳。受理、派活、产物核验与 Git 记账放在可被窗口调用的跨平台账本引擎里，不把 Git 记账写死在渲染进程或视图中。主进程用 Node `child_process`（或引擎自己的进程拉起）启动 Git 和已配置的执行命令。Codex CLI 等工具可经各自公开入口登记，选择权在用户手里。首版正式验收至少覆盖两个不同 Agent 的真实接入，每次只派给用户选中的一家；这两个真实执行器与从桌面打开结果，在用户 Mac 上做真机验收。桌面体验参考 OpenBot 的统一入口和手动选人。选定 Electron 而不是原生 SwiftUI，是因为它能在 Linux 开发机上编译、启动真实窗口并用自动测试验收协议与窗口行为，同一套代码再打出供 Finder 打开的 macOS 应用。不把 Tauri 定为首版，是为了让 Linux 开发机与 Mac 真机共用同一套 Chromium，减少窗口行为不一致；若以后要减包体，可在不改账本引擎接口的前提下换更轻的壳。 [Electron 文档](https://www.electronjs.org/docs/latest/tutorial/quick-start) · [Node.js child_process](https://nodejs.org/api/child_process.html)

## 技术边界

| 部件 | 首版做法 |
|---|---|
| 桌面壳 | 计划在 `platform/desktop/` 放一个 Electron 单窗口应用，不用只能在 macOS 上构建的原生 SwiftUI App target。窗口和协调逻辑随同一份应用交付。Linux 开发机直接编译并启动该窗口做开发与自动测试；macOS 安装包由 CI 的 macOS 构建环境（例如本仓 GitHub Actions 的 macos runner）或任一已有打包能力的构建机打出，供用户从 Finder 打开。不要在用户本机打 `.app`，不要把完整 Xcode 写成开工条件。Git 与执行调用在主进程后台执行，窗口保持响应。账本写入沿用单机串行与操作系统文件锁，任务归属以远端为准 |
| 名册与配置 | 一份本地 JSON 配置保存账本路径、任务工作目录、Git 可执行文件路径、账本提交用的 `user.name` / `user.email`，以及多个执行器实例。设置中可添加或修改名称、可执行文件路径、参数和超时。实例沿用 `mode`、`invoke`。阶段一运行已接通的 `push` 实例；不可达或尚未接通的实例可在下拉中可见但禁用，并旁注「待接入」，不纳入正式验收。执行命令和 `git` 都用完整路径。阶段四若迁移至 `agents.yaml`，继续只维护一份名册，只换格式、不换调度语义 |
| 执行工作目录 | 每次任务使用独立的普通目录，放经用户选定的输入与预期输出。阶段一只支持小型文本产物。账本 checkout 与执行目录分开，账本 checkout 不得兼作执行工作目录 |
| 私有账本仓 | 按蓝图 §4.3 建立一个独立仓，使用 `events/`、`tasks/` 及约定的记忆目录。另增补 `artifacts/<任务 ID>/` 存放获准小文本产物（这是对 §4.3 目录树的补充，不回改冻结蓝图）；任务九字段里的 `artifacts[]` 记相对路径与 SHA-256。空的 `inbox/`、`claimed/`、`done/`、`proposals/`、`confirmed/`、`index/` 以及 `artifacts/` 均提交 `.gitkeep`。设计仓（本仓 `platform/desktop/`）只放应用源码、模板与合成样例，不要和账本 checkout 混在一个工作副本里。禁止对账本仓 `main` force-push |
| 共享接口 | 阶段一按 [记忆接入契约草案](../contracts/memory-integration-spec.md) 第二节的当前样例，只实现四种事件：`task.created`、`task.claimed`、`task.completed`、`task.released`。信封字段为 `id`、`at`、`kind`、`actor`、`source`、`data`；任务快照含蓝图九个字段和 `bucket`。阶段一期间不改这些字段含义。整份契约的两区确认是阶段二开工前置，不是阶段一关门条件，也不是轨 A 开工门 |
| 本地锁 | 锁只防止同一个应用实例重入，不能代替远端归属。锁文件放在 checkout 内且被 gitignore（例如 `.git/pat.lock`），或放在 checkout 外侧 |

首版范围是一个窗口、一套账本和手动选人。阶段二接 Telegram、关键词检索、主动回传与换人接手。阶段三做常驻拉取加固。阶段四接宰相与自动路由。三区是桌面布局；任务对象的字段与动作保持与通道无关，后续通道复用同一套状态，不要求复刻三栏版式。阶段一窗口不预留确认、晋升、记忆检索或 Telegram 入口。 [蓝图阶段表](architecture-v2.md#八分阶段)

**进程拉起与运行环境（轨 A 的命令入口和窗口主进程都要守）：**

- 首版不要启用会阻止拉起用户配置 CLI 完整路径的沙箱（包括 macOS App Sandbox，以及 Electron 过严的 sandbox）。本机分发，不上架。真机包不做强制公证；个人打开未公证应用（例如右键打开）即可，不把 Apple 开发者账号或用户本机 Xcode 写成阶段一条件。
- 账本 checkout 与工作目录用文件夹选择器选择。开发机按 Linux 文件权限使用所选路径；真机 Mac 若系统要求目录授权，选择后持久化该授权（例如 security-scoped bookmark），避免重启后丢权限。不要把 macOS 专用授权 API 写成 Linux 开发依赖。
- `git` 写入配置的完整路径，不要依赖 shell profile。开发机和真机都按「未加载 shell profile」的环境预检 `git -C <checkout> ls-remote`。真机还要按 Finder 启动环境理解 PATH：Finder 启动的 PATH 通常只有系统路径，Homebrew 工具不在其中。HTTPS + 系统可读的凭据助手比只存在于交互式终端的 `ssh-agent` / 交互式 `gh auth` 更稳。
- 主进程不得在 UI / 渲染线程里同步等待子进程结束。异步读完 stdout/stderr，避免管道撑满把执行器堵住。超时和用户停止时结束整个进程组，不要只杀父进程。
- 传给执行器的环境做白名单，不要把整个图形环境原样转发；stdin 关掉或指向空。壳只传本任务材料和允许的必要环境。
- 账本提交的 `user.name` / `user.email` 写在配置里，或每次用 `git -c` 传入。打包后的应用或无交互环境里常常没有全局 Git 身份。
- 启动前核对其在「无交互、无 shell profile」环境下的授权与可用性；真机额外按 Finder 环境核一次。设置页给出路径缺失、授权失败等可处理的提示。

**事件写入约定。** 事件 JSONL 只由壳（账本引擎）追加，执行器不得直写。JSONL 按壳的 UTC 写入日分文件。推模式下：`task.created` 的 `actor` 是用户（经桌面入口）；`task.claimed`、`task.completed`、`task.released` 的 `actor` 是壳；所选实例写入领取后的 `owner`，可知的厂商 / harness / 模型记在事件里并标明未知项。阶段一两个推实例、创建与领取同一提交时，不必另加 `assignee` 字段。过程日志（工具回传、退出码、超时和输出）留在窗口详情或本地日志；阶段一不自造 `task.failed`。失败任务留在 `claimed/` 并保留本地证据。

## 用户路径

用户从 Finder 打开 PAT（这是真机入口。开发机启动同一应用做自测，不代替 Finder 真机验收）。同一窗口有两套主视图，不同时铺开：配置不齐（账本路径、工作目录、至少一个可启动执行器缺失）时进入设置视图；配齐后进入工作台（任务表单 / 当前任务 / 最近任务）。工作台用工具栏按钮在同一窗口内打开设置，不要另开窗口。窗口标题固定为 PAT，不要改成当前选中的 Agent 名。

首次在设置中指定已有的私有账本 checkout 和工作目录，并登记已有登录态的执行器。账本 checkout 与工作目录用文件夹选择器选择。凭据由执行器与 Git 各自管理。用户启用账本同步时授权壳向指定私有仓提交任务记录与获准产物，项目代码的提交和推送按各项目授权执行。

开工前须先有私密账本仓骨架：新建私密仓，按 §4.3 与上文增补目录提交骨架（含 `.gitkeep`），再在本机 clone 到专用路径。用户在设置里指定的是这份已存在的 checkout。

| 窗口区域 | 最小内容 |
|---|---|
| 任务表单 | Agent 下拉列表、任务文本（多行）、预期结果文件名与「派活」。新任务显示「请选择 Agent」，提交前明确展示所选实例。已接通的实例可选；待接入的可见但禁用。缺少配置或启动失败时，在表单内显示原因并链到设置。预期结果文件名必填，占位可用 `result.md` |
| 当前任务 | 任务编号、所选 Agent、状态、一行原因与主按钮。默认可见这些；原请求、产物入口、工作目录入口和日志放在展开区，不另开页面。进行中或正在派活时提供「停止」。按状态提供「继续同步」「确认完成并记账」「放回待领取」「重派」「打开产物」「打开工作目录」 |
| 最近任务 | 可扫读列表：原请求摘要、执行器、状态、产物是否可打开。点一行后，动作出现在当前任务，不要在每行堆按钮 |
| 设置 | 账本路径、工作目录、`git` 完整路径、Git 提交身份、执行器名称 / 可执行文件 / 参数 / 超时。路径缺失、授权失败给出可处理提示 |

**三区选择与并存模型：**

1. 阶段一只允许一条进行中任务。进行中 = 正在派活或执行中。此时「派活」禁用，并显示原因（例如「等当前任务结束或进入待核对，再派下一条」）。
2. 有进行中任务时，当前任务锁定该条，不随最近任务的点选切换；最近任务仍可浏览，进行中那一行保持高亮和实时状态。
3. 没有进行中任务时，当前任务绑定用户在最近任务里点中的那一条，并展示该条状态和可用动作。
4. 工作台提供「新建任务」：清空表单（Agent 回到「请选择 Agent」，任务文本清空），并取消对已结束任务的选中。进行中时它只清空表单草稿，不解锁「派活」，也不打断当前执行。一次派活成功后，Agent 同样回到「请选择 Agent」，任务文本清空，避免下一条误派给同一家。
5. 释放后的重派只在原任务被选中、当前任务出示「重派」时可用，沿用原 `desktop:<UUID>`，不新建任务 `id`，不新生成 `source_ref`。不要在表单里另开一条看起来像新任务、实际却复用旧编号的隐式路径。

同键去重也落到当前任务：同键同请求时不新建，直接把已有任务选进当前任务，并说明「这条任务已经存在」；同键但内容或执行器有变时停在当前任务，说明需要核对，提供「查看已有任务」和「取消」，不要静默覆盖。提交过程中暂停重复点击，这是界面防抖，须与账本按 `source_ref` 去重分开记。

界面状态把「待同步」从「待核对」里拆开：

| 状态 | 含义 | 当前任务主动作 |
|---|---|---|
| 正在派活 | 正在写入账本或确认领取 | 停止 |
| 执行中 | 执行进程未结束 | 停止 |
| 待同步 | 产物已通过本地核验，远端完成记录未确认 | 继续同步；次要：打开产物、打开工作目录 |
| 已完成 | 远端读回确认 | 打开产物 |
| 待核对 | 失败、超时、失联、逾期已领、用户停止，或需要人确认旧执行已停 | 打开工作目录；核对后：确认完成并记账 / 放回待领取 |
| 已释放 | 已回 `inbox/`，等待原任务上的显式重派 | 重派 |

「打开产物」指向获准入账的文件，「打开工作目录」指向执行目录里的现场文件，文案必须分开。逾期 `claimed/`、未完成同步和引用失效在最近任务里高亮，必要时在三区上方放一条可点的摘要（含任务编号和原因），点中后进入当前任务处理，不要连环弹窗。状态用文字徽章，不只靠颜色。

应用为每次提交保存一个稳定的 `desktop:<UUID>` 来源编号，重试沿用原编号并展示现有任务。日志放在当前任务展开区，主窗口显示能采取的下一步，例如「结果已生成，点击继续同步」。

空态：最近任务为空时写「还没有任务。选一个 Agent，写下任务后点派活。」没有选中且没有进行中任务时，当前任务用同一提示。

## 执行与记账

1. **受理。** 锁住账本写入，验证用户选择、配置与执行器入口。读取专用 checkout 的远端最新状态。用户请求、文件路径与期望产物作为数据传入执行命令。用界面保存的稳定 `source_ref` 在三个任务目录查重。同键同请求展示已有任务，同键变更内容或执行器时提示人工核对。
2. **领取。** 保留蓝图九个任务字段，用所在目录表示状态，不另设可写的 `status`。壳读取所选实例的 `mode` 和 `invoke`，多个本地执行器共用一条推模式流程。创建、领取均由壳写事件，可以在同一提交中先建后领。壳只暂存本次任务、事件和约定产物路径。普通推送后读回远端，确认任务仍在 `claimed/`、最新领取事件为本次记录，再启动进程。非快进拒绝时，只在专用且无未保存工作的领取副本上执行 `git fetch` 与 `git reset --hard`，重读 `tasks/inbox/` 后再决定是否领取。禁止对领取提交做 rebase 或 merge。推送结果未知时先读回远端，确认归属后再决定下一步。明确冲突时按上述协议重读当前任务，不要写成含糊的「冲突时重读」。冲突恢复时禁止对账本仓 `main` force-push。 [Git push 官方规则](https://git-scm.com/docs/git-push#_push_rules)
3. **执行。** 壳在指定工作目录启动所选执行命令。执行器使用自身支持的工作区限制与用户已有授权。阶段一只派纯文本本地产物任务。执行进程在账本工作目录之外。工具回传、退出码、超时及输出分别记录。用户停止时终止本次进程组并保留可核对的输出。
4. **完成。** 检查指定产物存在、可读且在工作目录内，拒收路径越界和符号链接。确认它符合预期文件类型并可供用户打开。壳再次核对当前领取事件，复制获准产物到 `artifacts/<任务 ID>/`，生成路径与内容校验值，连同完成事件和任务移动写入同一个 Git 提交。对同一提交内的新文件先用路径加 SHA-256，避免依赖尚未生成的提交哈希。远端读回确认后才显示「已完成」。结构和文件校验由脚本做，样例内容是否正确由验收者打开确认。阶段一拒绝把明显密钥文件当产物提交；完整凭据扫描按蓝图属阶段二，不作为本阶段关门条件。
5. **待核与人工处置。** 非零退出、超时、产物缺失、执行后失联或提交未确认时保留 `claimed/` 与本地证据，窗口提示具体原因。再次提交同一请求显示现状。确认旧执行已停止、已有产物与外部动作已核对后，用户可以确认完成并记账，或放回 `inbox/` 后在原任务上显式重派。结果提交已在本地但远端未确认时，先核对该提交和当前归属，再补推已有记录，不重跑执行。应用重启后按账本恢复最近任务，遗留的已领任务显示待核对。

每次账本变更保留事件中的变更后任务快照与目录，格式见接入契约第二节。回放按远端账本提交顺序读取新增事件，同一提交内按追加行序。发现来源冲突、同 ID 不同内容、账本缺对应事件或本地有未处理改动时停止写入，保留现场供用户核对。首版同步普通快进；处理冲突只使用专用且干净的领取副本做 `fetch` + `reset --hard`，或换新的临时副本后按同一协议操作。

## 维护与恢复

- 应用启动、查看历史和任务结束时检查逾期 `claimed/`、未完成同步和引用失效。结果显示在当前窗口，含任务编号和原因。
- 里程碑从权威远端做完整克隆到独立位置，记录归档对应提交。需要一个文件时可用 Git bundle 打包已入仓历史。工作目录的未提交产物、CLI 登录态和本地配置按各自用途单独管理。 [Git bundle 官方文档](https://git-scm.com/docs/git-bundle#_examples)
- 维护验收从事件向空临时目录重建任务视图。忽略克隆来的 `tasks/`，读事件还原至少一条任务，核对 ID、目录、来源、归属和产物引用（相对路径与 SHA-256）。此步骤可由维护者触发，窗口的日常操作使用已保存的任务视图，不必在主窗口再做一套重建界面。

## 实施顺序与验收

实现拆成可并行的两轨。用户仍然从 Finder/桌面打开已构建的 macOS 应用，不改 2026-11-08 桌面版裁定的入口形态。轨 A 的命令入口只给窗口主进程和测试用，不是给用户的产品入口。

| 轨 | 做什么 | 开工门控 | 可检查的完成条件 |
|---|---|---|---|
| A. 账本引擎 | 创建与领取同一提交、`source_ref` 查重、push 后读回、冲突时按上文领取协议做 `fetch` + `reset --hard`、完成提交、四种任务事件的 JSONL、从事件重建 `tasks/` | 可在 Linux / 无 GUI 环境用假执行器（写入约定的 `result.md` 后退出 0）先写并跑通。不依赖用户 Mac，不依赖 Xcode | 用假执行器证明：创建 / 领取 / 完成可从同一账本读回；同一 `source_ref` 只启动一次；同键改内容或执行器时停下来核对；非快进时硬复位后再读 inbox；克隆后仅凭事件还原一条任务，与远端账本和产物引用比对 |
| B. 窗口 | Electron 单窗口、名册设置、主进程拉起探针；用完整路径调用轨 A 引擎。开发阶段用假执行器或测试替身跑通窗口路径 | 开发机（Linux）能安装跨平台工具链（Node.js 等）、编译并启动窗口。若无图形界面，用虚拟显示（如 Xvfb）跑窗口自动测试。没有「必须先在用户 Mac 上装完整 Xcode / 打出 `.app` / 装任何开发软件」的开工门 | 开发完成：Linux 上同一套窗口可启动、调用轨 A 引擎，自动测试覆盖选人、无默认选中、派活路径（可用假执行器）以及停止 / 重派等窗口动作。真机验收（不算开工门）：用户从 Finder 打开已构建的 macOS 应用，窗口显示至少两个已接通的 Agent，分别手动选择，各跑一条任务并打开真实文本产物。记录实例、版本、退出值与授权模式（写入验收记录，不要只停留在窗口瞬时状态），校验无默认选中 |

两轨可并行的含义：轨 A 现在就能开工；轨 B 的窗口开发也在 Linux 上同时开工，不得因为工具链把开发推回用户的 Mac。派活路径必须调用轨 A 引擎，不得先写一套稍后抛弃的无账本执行。进程拉起的工作目录、完整路径、超时和输出采集只定一次，探针和闭环共用。

分工如下：

- Linux 开发机（老邪云电脑）是开发与自动验收机：承担轨 A 的协议与夹具、轨 B 窗口的编译 / 自测 / 协议与窗口自动验收，以及文档工作。轨 A 跑通不算步骤 1 的用户路径完成；Linux 上窗口自动验收通过，也不等于步骤 1 的用户路径完成，更不等于蓝图①通过。
- 用户 Mac 只做真机测试：从 Finder/桌面打开已构建的应用，用两个真实执行器跑官方用户路径，并从桌面打开结果。不在这台机器上写代码，不安装完整 Xcode，不把本机打出 `.app` 当作开始写窗口的条件。
- macOS 安装包在 CI 的 macOS 构建环境（例如本仓 GitHub Actions 的 macos runner）或任一已有打包能力的构建机上打出，再交给用户做真机打开。这是真机测试产物，不是开工门。

窗口在 Linux 上的自动探针完成不等于蓝图阶段一①通过，也不等于步骤 1 真机验收通过。下面用四步验收把两轨接到蓝图观察点；步骤 1 是用户 Mac 上的真机窗口能力，步骤 2–3 的核心可先在轨 A 用假执行器证明，并在 Linux 窗口自动测试里复验，再在接上真实执行器的真机窗口里做官方验收。

| 验收步骤 | 具体交付 | 可检查的完成条件 | 对应蓝图 |
|---|---|---|---|
| 1. 窗口与执行探针 | 可从 Finder 打开的 macOS 应用、任务表单、名册设置和临时任务目录 | 见轨 B 的真机验收条件。本步只证明手动选人、无默认选中、两个真实执行器能跑出可打开的文本产物。本步不要求验收者把账本读回当作关门。场所是用户的 macOS，性质是真机测试；开发机上的窗口自动测试是过程证据，不能替代本步 | 蓝图① / §九.1 的「指定执行器 + 打开产物」部分；入口形态按 `AGENTS.md` 桌面版裁定。**本步完成 ≠ 蓝图①通过** |
| 2. 账本闭环 | 私有试用账本、来源查重、同提交记账、最近任务 | 两家任务的创建、领取和完成可从同一账本读回，事件与 `tasks/` 变更在同一 Git 提交。重开应用后仍可查并打开结果。同一 `source_ref` 只启动一次，同键改内容或执行器时停下来核对 | 蓝图① 在这一步关闭（指定执行器，任务与结果落仓可查）；§九.1；§九.3 去重前半 |
| 3. 异常与恢复 | 失败提示、逾期检查、人工处置、临时回放 | 用固定夹具「已产出而未回报」验证不再执行。用一次中断或失败推送验证原任务及产物可查。克隆恢复后仅凭事件还原一条任务，与远端账本和产物比对 | 蓝图② / §九.3 的逾期待核；蓝图③ / §九.6 |
| 4. 交接阶段二 | 可重复的使用说明、一份验收记录、一份 §十一 1–10 锁定表 | 验收记录保存任务 ID、产物位置、对应提交、实例与授权模式。按下方锁定表逐条标明阶段一已落实、要求已锁定但本阶段不验收，或由子项目自定节奏。两区确认接入契约不作为本步完成条件 | 蓝图④：§十一框架要求已锁定，作为进入阶段二的前置 |

蓝图正文仍写阶段一用「一条命令 / 脚本命令」发任务。桌面版裁定已规定：阶段一入口及对应验收以本规划为准。完成标志①的观察点改为「用户从 Finder 打开应用，在窗口明确选择 Agent 后派活，任务与结果落仓可查」；完成标志②③④与 §九.3 / §九.6 不变。实现栈改为可在 Linux 编译与自测的 Electron 桌面壳，不为此解冻 `architecture-v2.md`，也不要求用户安装 Xcode。

阶段一官方用户路径验收从 Finder 启动应用并实际操作窗口，场所写明为用户的 macOS 本机（真机测试）。运行日志记录必要的任务号、时间、结果状态与退出原因。至少验证手动选人、重复派发、失败提示和恢复。日常维护使用窗口状态与任务详情。不接受的证据沿用蓝图：模型或应用自己说「完成了」不算过，必须有产物、有 commit、有可核对落盘。开发机上的自动测试不能替代这步真机验收。

步骤 1 的产物先在工作目录打开即可认定该步的执行探针通过，可以先不把账本读回当作该步关门；步骤 2 起才把落仓可查列为关门条件。按终态去验步骤 1 会误判未完成。

### 固定验收夹具

下列夹具中途不更换。空夹具或验收中途改题按验收包缺陷处理。样例正文使用两条无敏感内容的项目事实和整理要求，具体文句由验收包给出，此处不编造项目事实。结构和文件校验由脚本做；「内容正确」由验收者打开确认，不作为自动通过。夹具写「名册中两个已接通的 push 实例」，验收记录再写下实际实例名。

| 编号 | 操作 | 期望落盘 |
|---|---|---|
| 1. 选人 A | 用户从「请选择 Agent」选第一家，派活，打开约定产物（如 `result.md`） | 无默认选中；产物在工作目录内、类型符合、可打开。步骤 2 起账本有创建 / 领取 / 完成，目录落到 `done/` |
| 2. 选人 B | 同一窗口选第二家，新建一条任务 | 两条任务归属不同，产物都能打开；同一账本可回读 |
| 3. 同键重投 | 对已记录的提交再点一次（沿用原 `desktop:<UUID>`） | 不新启动进程，账本仍一条任务；可记一条「重复投递已忽略」事件。界面防抖与账本去重分开记 |
| 4. 同键变更 | 同一 `source_ref` 改任务文本或改执行器后再提交 | 停下来提示人工核对，不覆盖、不第二次执行 |
| 5. 已产出未回报 / 逾期待核 | 见下方标准做法 | 窗口给出任务编号和原因；任务仍在 `claimed/`；原归属不变；不会再次启动执行 |
| 6. 中断或失败推送 | 二选一作为必做，另一个进附加项。中断 = 用户停止本次进程并保留可核对输出；失败推送 = 本地已有完成提交但远端未确认，先核对再补推 | 原任务及产物可查，不丢本地证据，不第二次执行 |
| 7. 强制失败 | 指定一个执行器不会写出的文件名，或制造非零退出 | 保留 `claimed/` 与本地证据，窗口提示具体原因；用户确认旧执行已停止后，可确认完成并记账，或放回待领取再显式重派 |
| 8. 事件重建 | 从权威远端克隆到空临时目录，忽略自带的 `tasks/`，只按事件还原至少一条已完成任务 | 核对 ID、目录、来源、归属和产物引用（相对路径与 SHA-256） |
| 9. 越界产物 | 产物路径在工作目录外，或为符号链接 | 拒收，不显示「已完成」 |

**夹具 5 的标准做法（不要只写「模拟」）：** 构造一条位于 `claimed/` 的任务，其 `deadline` 已过，工作目录里已有约定产物，账本没有 `task.completed` 事件。触发应用启动或任务结束时的逾期检查。期望同上表：窗口显示该任务编号和原因，任务仍在 `claimed/`，原 `owner` 不变，同一 `source_ref` 再次提交时不启动第二次执行。不要改成自动补记完成，也不要释放后在表单里另建一条新任务。

### 阶段一关门：§十一 1–10 锁定表

步骤 4 交付这份表。每条只标三种之一，并附本规划或蓝图出处。阶段一锁定的是要求，不是把治理能力做完。

| 条 | 要求 | 阶段一处置 |
|---|---|---|
| 1 | 一份真相源 | 已用步骤 2/3 落实：影响账本的变更写事件，事件与 `tasks/` 同一提交；维护回放忽略现成 `tasks/`，仅凭事件重建 |
| 2 | provenance 完备 | 已用四种任务事件的信封落实：记录谁、何时、经何通道、原始引用；缺一项不入库 |
| 3 | 分层与单向晋升 | 要求已锁定，本阶段不验收。阶段一不写晋升界面，机器提炼不得冒充知识 |
| 4 | 治理归壳 | 要求已锁定，本阶段不验收整理作业。事件由壳追加，治理不得做成某一 Agent 的私有能力 |
| 5 | 模型只当工具 | 要求已锁定，本阶段不验收。阶段一由用户手动选人，壳不调用模型做派活决策 |
| 6 | 安全三档 | 要求已锁定，本阶段不验收完整扫描（蓝图将其放在阶段二）。阶段一拒绝把明显密钥文件当产物提交 |
| 7 | 开放与可迁移 | 已用开放格式（JSONL / JSON / Markdown）写入用户控制的私有仓落实载体要求；厂商记忆只作输入源这一条要求已锁定 |
| 8 | 信赖门 | 要求已锁定，本阶段不验收。阶段一不默认启用提炼 |
| 9 | 成本可计量 | 要求已锁定，本阶段不验收。计量口径由子项目给出 |
| 10 | 慢层先行 | 子项目层自定节奏。阶段一事件字段以契约第二节当前样例为准，不自定并行格式 |

两区确认接入契约，以及契约中不可达执行器主动回传后再接手等证据，标为阶段二开工前置，不作为阶段一关门项。不要用推模式两家互相能读，去预支阶段二的接手验收。

## 待实施核对

- 轨 A 现在可以开工：用假执行器和合成事件样例验证领取、去重与重建。不依赖用户 Mac，不依赖 Xcode。
- 轨 B 现在也可以在 Linux 开发机开工：用 Electron 写单窗口，用假执行器或测试替身，必要时加上虚拟显示做自动测试。不要等用户安装 Xcode，不要等本机打出 `.app`。

- Electron 单窗口、跨平台账本引擎、非沙盒和本地 JSON 是本稿给出的实现选择。原生 SwiftUI App target 不再作为开发路径。
