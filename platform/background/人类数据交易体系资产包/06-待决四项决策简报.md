# 06 待决四项决策简报（04 方案 v3.1 §十）

> 用途：04 方案 v3.1 末尾留了四个待决项。本简报只做一件事——把四项的依赖顺序和各自的拍板标准钉清楚，不替用户做决定。用户选定先凿哪项后，再就该项展开专项调研。
> 依据：《04-交易市场早期方案.md》v3.1 正文 §八（路线图）、§九（风险）、§十（待决）及附录 Q2/Q4/Q7。整理时间：2026-10-11 晚。

## 核心判断：四项不是并列的，只有一项是真阻塞

- **首发品类（第 1 项）是其余三项的上游**：Phase 0 的定义就是「选一个高频品类 → 建该品类的收录审查清单与多维评分 → 导入该品类的外部先验数据并重排 → 建该品类的验收测试集」。验收集和先验清单都按品类收窄后才可执行，品类不定，这两项只能空转。
- **框架接入（第 2 项）是 Phase 1 的验收项**（「至少 1 个框架/运行时接入发现协议」），不在 Phase 0 的关键路径上，可以最后拍。
- 建议的开凿顺序：**品类 → 先验合规清单 / 验收测试集基准（可并行）→ 框架接入排序**。

## 逐项：要拍什么、按什么标准拍、拍错的代价

### 1. Phase 0 首发品类

- 要拍的：只选一个品类跑通「发现→采购→验收→结算」全链（Phase 0 验收：≥10 笔真实付费成交、验收触发退款至少真实发生并正确处理 1 次、首批作者收到可提现分成）。
- 拍板标准（全部出自方案自身逻辑，非新发明）：
1. **高频**——agent 任务中反复出现的能力缺口（Phase 0 原文要求）；
2. **价值可测**——装上前后的任务成功率差值能量化（附录 Q2：定价锚和验收枢纽都建立在「skill 是价值最可测的品类」之上，首发品类必须把这个优势吃满）；
3. **验收集可建**——该品类存在可标准化、可在沙箱复现的验收任务；
4. **先验可得**——外部市场/注册表已有该品类的评分、评价或使用数据可导入打底（附录 Q7）；
5. **试错风险可控**——沙箱外溢风险低（附录 Q4 硬伤三：测未知 skill 等于跑不可信代码）。
- 拍错的代价：品类选错，Phase 0 的三个衍生件（收录清单、先验导入、验收集）全部重做。
- 尚缺：候选品类的枚举与按上述五条打分的对照表——用户点头先凿此项后再做专项调研，本简报不预选。

### 2. 先验数据的合规抓取清单

- 要拍的：逐源清单——每个外部来源（评分/评价/反馈）能否抓、按什么条款抓、抓什么字段。
- 已定的边界（§九.4、附录 Q7）：导入前逐源核查授权与平台条款；外部信号只作贝叶斯先验、随本站遥测积累自动衰减；跨源矛盾标旗复核。清单的作用是把「逐源核查」从原则变成可勾选的表。
- 依赖：清单的源和字段都随品类收窄（第 1 项定了才知道先查哪几个源）。

### 3. 验收测试集的基准来源与维护方式

- 要拍的：基准从哪来（公开基准改编 / 自研任务集 / 混合），谁维护，多久轮换。
- 已定的边界：测试集由市场制定、沙箱内运行，**不用 skill 自带测试**（自证清白不算数）；须保留私有子集并轮换防考题过拟合（§九.3）；真实使用遥测为最终权重，验收分不是终审。
- 依赖：测试集按品类建，第 1 项未定前只能定原则、定不了内容。

### 4. 首批框架接入对象排序

- 要拍的：首批争取接入发现协议的框架/运行时排序。
- 已定的标准（§三、附录 Q10）：奖品是成为框架的「默认可信源」，该位置只发给守注入红线的市场；接入排序应看对方生态的开放程度与跨生态中立性的契合度，而非单纯流量。
- 不阻塞 Phase 0：Phase 0 跑通全链靠的是自有注册表与能力卡拉取，框架默认位是 Phase 1 才验收的事。现在拍它，等于在品类都没定时先选分发渠道，顺序反了。

## 一句话给用户

四个待决项里，先拍品类一个就够启动 Phase 0 的准备工作；其余三项里两项随品类自动收窄、一项（框架接入）本来就是 Phase 1 的事，不用四项一起纠结。
