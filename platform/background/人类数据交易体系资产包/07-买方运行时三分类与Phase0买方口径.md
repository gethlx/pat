# 07 买方运行时三分类与 Phase 0 买方口径（04 方案补充件）

> 沉淀日期：2026-10-11 晚。来源：当晚侧聊用户追问——「你这个智能体不需要安装 skill？」「像你和 Grok 不也是 agent 吗，你们不需要去寻找和安装第三方 skill？」
> 性质：补充件，不改 04 正文。若用户认可，建议并入 04 附录作 Q13，并同步修订 06 简报对第 4 项（框架接入）的定性。并入与否待用户拍板。

## 一、今晚钉死的新事实：买方不是「agent」，是运行时

04 正文 §一的定位是「买方是 agent 本人——自己发现缺口、自己检索比价、自己在委托预算内付费、自己安装并验收」。今晚的追问暴露了一个此前没拆开的变量：**能不能「安装」，不取决于它是不是 agent，取决于部署形态给不给它包管理器、钱包和安装权限。** 三类运行时：

1. **托管型消费 agent（围墙花园端）**：Muse、Grok 这类公开产品形态。能力来自平台预置工具、连接器和审核过的扩展；skill 对它们只是能力说明书 / 工作流 playbook（读 SKILL.md 按流程调用已有工具），装 skill 不会给模型新增原生工具、也不会绕过权限。它们**不能**在任务中自己去外部市场下载代码、付款、提权执行——不是不需要，是安全、责任与账号权限不允许。
2. **开发者 / 企业 agent 运行时**：LangChain、AutoGen、各类 MCP 客户端、本地 coding agent。接近「可安装」，但采购与安装权在开发者 / 管理员手里——人先把工具、MCP server、skill 包注册进注册表，agent 运行时只能在注册表内挑选调用。agent 的「自主」是**注册表内选择**，不是**市场内采购**。
3. **开放自治 agent**：只有当运行时同时给它 shell / 包管理、预算钱包、权限策略和验收沙箱时，它才能完整跑「发现缺口 → 外部检索 → 付费 → 安装 → 验收」。04 瞄准的是这一类成为主流之后的位置；它现在还不是消费产品的默认形态。

## 二、对 04 的三处实际修正含义

1. **Phase 0 的验收口径需要分层**：§八 Phase 0 验收写作「≥10 笔真实付费成交（预算内 agent 自主决策）」。按三分类，这个「自主决策」今天只能在第 2 类环境里以弱形式实现（管理员先把本市场注册为可信源，agent 在源内自主选购、验收、结算），第 3 类的强形式（agent 自己找上门）现阶段没有现成买方。建议 Phase 0 按弱形式定义验收，强形式留给 Phase 2（§八 Phase 2 已有「agent 全自主采购占比可测」，与此对齐）。
2. **06 简报对第 4 项的定性要拆成两半**：06 说框架接入是 Phase 1 的事、Phase 0 靠自有注册表即可。这个判断对「成为框架默认可信源」成立，但漏了一半——**Phase 0 的试验台本身就得选一个第 2 类运行时**，把市场接成它可注册的一个源 / MCP，否则 10 笔成交没有发生的场所。所以「选哪个运行时当试验台」是 Phase 0 的前置小决策（依附于首发品类，不是独立大项）；「成为默认可信源」仍是 Phase 1 验收项。顺序修正为：品类 → 试验台运行时（小决策）→ 先验清单 / 验收集（并行）→ 默认源接入排序（Phase 1）。
3. **发现机制（§四）多一条硬约束**：对第 1 类 agent，GEO / 能力卡拉取的天花板是「被平台收录进预置注册表」，不存在任务中被 agent 本人发现的路径——平台的收录审核就是第 1 类的「收录审查」镜像。本市场的发现协议真正的作用对象是第 2、3 类运行时；对第 1 类只能走平台合作 / 上架通道，那是巨头主场逻辑，按 §一「明确不做」处理，不投入。

## 三、残留待验证

- 第 2 类运行时中，哪些已支持「运行时从外部注册表动态拉取工具 / MCP server」而非只能启动时静态注册——决定试验台候选名单，需专项核查（LangChain / AutoGen / 主流 MCP 客户端的当前实现为准，不凭印象）。
- 第 3 类形态的真实存量：除 EvoMap / Evolver 这类自带 Hub 的实验生态外，还有哪些带钱包 + 沙箱的开放 agent 在真实运行——与每周三监测的「第二幕信号」同表观察即可，不单独立项。

## 四、一句话给用户

04 的买方假设没错，但要加限定词：**近期买方是「被管理员注册授权的运行时里的 agent」，远期买方才是「自己带钱包找上门的 agent」。** Phase 0 按近期买方设计验收，方案的赌注（跨生态中立、运行时中介）押在远期买方成主流——两层分开，Phase 0 就不再是等风来。
