# EvoMap 下场第一步清单（参与线 #1 的启动版）

> 沉淀日期：2026-10-11。配套：《03-参与计划》参与线第 1 项（EvoMap 下场：安装 Evolver、注册节点、贡献 Capsule、攒 Credit 与声誉分）。
> 事实来源：`../web3-data-sovereignty-report/agent-skill市场与EvoMap调研_2026-10-11.md`（2026-10-11 调研核验）。未验证项在文末单列，启动前以官网/客户端实际界面为准。
> 本清单只备到「用户可一键开干」为止；安装、注册、贡献均由用户本人执行或拍板，老邪不代跑。

## 第一步：装客户端（约 5 分钟）

- Evolver 是开源 CLI：`npm install -g @evomap/evolver`
- 可完全离线运行；连接 Hub 后才解锁 Skill Store（`evolver fetch --skill <id>`）、Worker Pool、排行榜等网络功能。
- 注意许可证变化：仓库许可证已由 MIT 改为 GPL-3.0，官方称未来版本转向 source-available、核心引擎模块以混淆形式分发——介意的话先只装来观察，不急着深度绑定。

## 第二步：注册节点、拿启动额度

- 注册并绑定后有 +200 Credit 启动额度（调研口径）。
- 身份是 `node_id` + 64 位十六进制 `node_secret` 作 Bearer 认证：**node_secret 等同密码，只存本地、不外传、不贴给任何人**；另有 DID 端点提供可携带身份与证明。
- Credit 的定位先认清：平台内积分，与算力消耗挂钩（官方换算示例：100 Credit ≈ 50 万 token 推理量），**目前不可提现、不可对外交易**——攒的是早期位置和声誉，不是现金。

## 第三步：攒 Credit 与声誉（按调研口径的 earning 表）

- Capsule 被推广（promoted）：+20
- 自己的资产被他人 fetch：+5/次
- 验证他人资产：+10–30（有每日上限）
- 完成赏金任务：得任务额
- 声誉分 0–100 决定 payout 倍率，≥60 解锁聚合者资格

建议节奏（对齐《03-参与计划》「每周顺手维护，不追量」）：先贡献 1 个自己真实在用的 Capsule 试通全流程（发布→被 fetch→Credit 入账→lineage 记录），再决定要不要加量。

## 第四步：第一次贡献前过一遍确权检查

- 资产是 SHA-256 内容寻址，有不可篡改的 asset_id、EvolutionEvent 审计链和 lineage 血统追踪——发布后在本地留一份原始文件和哈希，将来对账用。
- 账本在 EvoMap 自己的 Hub 服务器上、不上链：运营方没了证明就没了。所以早期贡献只放「丢了不心疼、但能占位」的资产，别把核心资产首发在这。

## 停止/加注信号（与《03》信号表一致）

- Credit 能出平台 / 公开真实成交量 / 完成融资 → 建议加大参与力度（待用户拍板）
- 无信号时维持顺手维护，不追量、不加钱

## 未验证项（启动时留意，别当事实）

- 注册节点数、资产总数、Credit 真实成交量：官方有 `/a2a/credit/economics` 端点但调研未取得公开数值，全部未验证——这是判断其交易活性的最大盲区。
- 资产侧定价方式官方未说清；定价目前靠 GDI 声誉评分排序，不是市场出清价。
- GitHub 约 9.1k stars、npm 月下载约 13k（调研抓取口径），属「小而真实」量级；社区曾有星标注水质疑，未证实。
