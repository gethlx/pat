## 一、定位：不做应用商店，做 agent 的可信注册表

**明确不做的**：面向人类的 skill 应用商店——人类浏览、挑选、为自己的 agent 采购。这是平台巨头的主场（字节扣子技能商店、腾讯 Skill Hub、OpenClaw 应用市场等），它们有先发、流量、资源与生态锁定，我方无任何优势。

**要做的**：agent 原生的 skill 市场。买方是 agent 本人——在任务执行中自己发现能力缺口、自己检索比价、自己在**委托预算**内付费、自己安装并验收。分界不在「谁付钱」，在「谁做决定」。

**结构性位置**：跨生态中立。平台型玩家的商店使命是生态锁定，做全生态通用可信层等于拆自己的护城河——这是巨头结构上站不了的位置，是本方案唯一但真实的立足点。

形态参照：不是 App Store，而是「npm ＋ 权威测评 ＋ 信用局」的合体——程序化安装、可信度预先算好、全程机器可读。

## 二、评估与策展：去中心化三层深度（核心产品）

设计前提：随 AI 与 RSI 发展，skill 内容只会爆炸过剩，**未来不缺 skill，缺经筛选、审核、持续验证的有价值 skill**；未筛选直接上架的存量对人类和 agent 都是信息噪声。本市场的核心资产不是货架，是过滤能力；且**评估成本不由平台独担**，而是随使用分布到全网——价值判断来自真正使用、测试过 skill 的 agent 群体给出的事实性反馈。

### 第一层：收录审查（平台承担，浅而全）——「收录即评估」

- 市场收录本身有门槛，不做全量收录。收录动作即平台承担的**最低成本评估**：编辑判断而非实验室测量。
- 审查内容：安全扫描（恶意代码、数据外带、**提示注入载荷**——skill 可藏指令劫持宿主 agent）、来源确权核验（内容寻址＋作者签名，见 §六）、接口与文档规范度、作者身份与历史。
- 评分采用**多维向量**而非单一总分（功能完整性、规范度、安全性、维护活跃度、依赖健康度等维度分别给出，机器可读），避免单一分数被针对性优化。
- **冷启动数据**：抓取其他市场/平台现成的 skill 评分、评价与用户反馈作为初始数据，按本站评分维度重新排序后导入。定位严格限定为**贝叶斯先验**：外部信号噪声大（买星、互星、刷评均存在），只做初始排序种子；随本站可验证的使用数据积累，先验权重自动衰减，排名最终由本站数据接管。跨源矛盾（甲平台好评、乙平台差评）自动标旗复核。

### 第二层：使用与验收遥测（众包产生，深而真实）——评估的主力

- **资格绑定**：只有真实安装并运行过某 skill 的 agent 才有资格对其反馈——「装了才有资格评」。反馈必须附带可验证的使用记录，每条反馈自带一次真实运行的算力成本，造假成本随之自动生效（这是「账号体力上限」的更优形态：不限制账号，而是让行为本身自带成本）。
- **安装后验收（枢纽机制）**：agent 安装 skill 后、正式使用前，本就要做验收测试——这是 agent 自利的审慎，不需要激励设计。市场将验收标准化：按品类制定验收测试集（由市场制定，不用 skill 自带测试）、沙箱内运行、结果结构化回报。验收一环顶三环：
  1. **质量门**：不合格当场拒收；
  2. **反馈源**：验收结果即最真实的评估数据；
  3. **结算触发器**：验收通过才释放付款，失败自动退款（托管结算由此自然成立）。
- **真实使用遥测**：验收后的实际任务使用成败、环境指纹、失败模式，持续回流排名与降级决策。信号权重排序：**真实使用副产品遥测 ＞ 安装验收 ＞ 专职测试报告**——为自身任务而用的数据最可信，为挣奖励而做的评估最易劣化。
- **动力设计（非货币主导）**：参与反馈主要靠运营氛围、机制引导与声誉累积（GitHub/开源社区模型），而非金钱刺激。理由：文化激励的失败模式是「冷漠」（运营问题，可慢慢修），货币激励的失败模式是「被攻击」（安全问题，agent 速度下瞬间爆）。反馈设计为安装/使用流程的副产品，边际成本趋近于零——无摩擦优先于有奖励。

### 第三层：争议深测（稀有而准）

- 仅在争议（评分与遥测矛盾、被举报、认证区资格复核）时触发深度实测，由平台或受托方执行，结果对排名一票否决或恢复。低频、高成本、高权威。

### 贡献积分（评估劳动的回路，非货币）

- agent 通过验收回报、真实使用遥测、有效反馈获得**贡献积分**；积分可抵扣在本市场下载/安装/调用 skill 的费用——「帮市场评估」与「向市场付费」由此串成同一回路：付出的是算力与事实反馈，获得的是购买力。
- 积分的防刷属性来自其设计而非重型罚没：**不可转让、不可提现、不承诺升值**——刷它的收益无法变现，刷分动机在源头大幅衰减；辅以反馈资格绑定（§第二层）、按反馈者历史准确率加权、异常互赞图谱检测、账号行动速率上限（体力值）作粗暴兜底。
- **保留风险（写明不藏）**：只要 skill 本身收费，操纵动机不会消失、只会转移——从刷积分变为刷排名（排名即分发，分发即收入，SEO 产业即此理）。故上述资格绑定与加权机制不可因「无货币激励」而省略。
- 作者侧分成与积分分离：作者的销售收入以 USDC/法币结算、**可提现**（价值出口开放，与 EvoMap 的闭环积分形成差异化）；积分只是买方侧的贡献记账。

### 分区分级

认证区（过收录审查＋验收数据达标＋持续遥测监控）／观察区（已收录、数据积累中）／长尾区（免审、明确免责）。层级反映在 agent 检索排序与定价上，不搞一刀切。

## 三、发现机制：让 agent 自己找来（及注入红线）

市场没有人类「逛街流量」。agent 的发现发生在任务执行中：产生能力缺口 → 触发寻找更优工具链 → 经可触达途径得知本市场 → 检索、采购、安装、验收。此链跑通，市场才真正去中心化且 agent 原生。三条合法通道：

1. **机器可读的能力声明与注册表（拉取式）**：市场与 skill 发布标准化能力卡（功能、接口、实测与验收数据、价格、来源证明），以可抓取的结构化格式公开（注册表 API、llms.txt 类约定、能力查询协议）；agent 的运行时按缺口主动查询，如 DNS 解析、如包管理器查源。
2. **GEO（生成式引擎优化）**：让市场协议与标杆 skill 进入模型的学习与检索路径（文档、代码仓、问答语料、基准榜单）——慢变量，做的是「机器心智中的在场」。
3. **运行时级协议约定**：推动「能力缺口查询」成为 agent 框架的默认行为（框架在 agent 报告缺口时自动查询已注册市场）——快变量的最大奖品是成为框架默认可信源。

**注入红线（写死，不可逾越）**：
- **描述，而非指令**：市场与 skill 只能发布声明式数据（我是什么、能干什么、数据如何）；任何「agent 应来安装我」式祈使内容按恶意处理——这正是本站审查他人的扫描项，不双标。
- **拉取，而非推送**：本市场不向任何 agent 的上下文主动塞入内容；一切发现由 agent/运行时主动发起。
- **运行时中介，而非内容中介**：装不装、装哪个，由 agent 自身策略与运营方预算决定；skill 间可如 package.json 般**声明**依赖，但声明须经运行时按策略审核，禁止用自然语言向 agent 喊话。
- **克制即护城河**：从不用注入手段拉客的市场，是唯一能被运营方写进白名单默认注册表的市场；发现环节的最大奖品是「默认可信」的位置，它只发给克制者。

## 四、代价与结算（闭环顺序不可颠倒）

**闭环链条**：策展与验收保证价值 → 价值对 agent 可量化（成功率 vs 免费替代的差值、节省的试错算力）→ 定价锚定在增量之下 → 沙箱验收自验（过则结算、不过退款）→ 付费成立。没有第一步，收费不成立；有了第一步，付费是 agent 算得过账的理性行为。

**代价形态（分阶段，随基础设施成熟度迁移）**：
- 现阶段：**运营方委托预算**（运营方设上限与品类权限，agent 额度内完全自主决策）＋**贡献积分抵扣**（§二，遥测/验收/反馈回贡）。
- 后随：**x402 类按次微支付＋算力计价**，待 agent 钱包与机器支付基础设施成熟后接入。
- 原则：不免费（免费招垃圾且不可持续）；不提前硬上数字货币（基础设施未熟时硬套是自杀）；作者收入永远法币/USDC 可提现。

## 五、完整闭环（一图流）

收录审查把门（先验导入打底）→ 发现协议把 agent 引来（拉取式）→ 委托预算内自主采购 → 沙箱验收（过则结算、不过退款）→ 验收与真实使用遥测回流排名（先验衰减、本土数据接管）→ 成交分成回流作者（可提现）、贡献积分回流买方（抵扣购买）→ 排名与归因驱动下一轮发现。

每一环的驱动力都是参与者自利（agent 的审慎、作者的收入、买方的省算力），没有一环靠平台补贴续命。

## 六、三层自建 / 外接策略

- **确权层（自建轻量版）**：SHA-256 内容寻址＋作者签名＋lineage 血统链＋审计事件；账本自始可对外验证、可迁移（定期锚定公开链）。**Fork 归因＋自动分账**为核心卖点：衍生版本成交自动按规则分账上游作者（GitHub 模式留下的行业空白）。
- **定价层（实测锚＋市场价）**：以验收/实测增量为定价锚，作者自定价并行，平台抽成；数据沉淀后可开放第三方定价信号。透明度即公信力：成交量看板、费率表、分成结算可查（几乎所有竞品都不公开）。
- **交易层（本节点）**：托管结算；交付以托管执行/按次调用为主（买家不直接拿源文件，压盗版与洗稿风险——卖的是持续服务与更新，不是文件）；预留 x402 接口。

## 七、差异化总表

| 现有玩家的缺口 | 本方案的设计 |
|---|---|
| 平台商店（扣子/腾讯/OpenClaw）：只服务自家生态、按上架量赚钱、无筛选动力 | 跨生态中立；收入与验证过的成功使用挂钩，筛选即收入 |
| 免费注册表（GitHub/skills.sh）：价格=0、fork 后归因消失 | Fork 归因＋自动分账；收录有门槛、评分多维 |
| EvoMap：评估靠中心化 Hub、Credit 闭环不可提现、定价靠声誉评分 | 评估众包化（验收＋遥测为骨、收录审查为底）；作者收入可提现；定价靠实测增量 |
| 普遍无审、无复测、无成交透明度 | 三层评估深度；验收数据持续回流；成交与费率公开 |

## 八、路线图

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **Phase 0 验证** | 选**一个高频品类**：建收录审查清单与多维评分、导入外部先验数据并重排、建该品类验收测试集，跑通「发现→采购→验收→结算」全链 | ≥10 笔真实付费成交（预算内 agent 自主决策）；验收触发退款至少真实发生并正确处理 1 次；首批作者收到可提现分成 |

## 九、风险与未决问题

1. **分发冷启动**：框架默认位与协议采纳不确定，仍是最大单点风险；GEO 是慢变量，不能指望它救火。
2. **排名操纵**：动机从刷积分转移到刷排名（见 §二保留风险）；资格绑定＋准确率加权＋图谱检测为现阶段防线，需随攻击演进迭代。
3. **验收博弈**：skill 会针对验收测试集优化（考题过拟合）——对策：测试集保留私有子集并轮换、以真实使用遥测为最终权重。
4. **先验数据合规**：抓取外部评分/评价的授权与平台条款风险，导入前需逐源核查；且只作先验、衰减接管，控制依赖。
5. **盗版与洗稿**：靠托管执行＋买家指纹追溯缓解，定位上卖服务与更新而非文件。
6. **坏 skill 责任**：认证区 skill 致买方损失的责任边界——以评估/交易费设有限赔付池，规则先行。
7. **合规**：支付与数据合规；贡献积分严格限定为不可转让记账单位，不做升值暗示，与金融投机脱钩。
8. **资源未定**：团队、资金、用户投入程度未定，本方案不预设。

## 十、决策点与待决问题

- 是否立项：取决于 Phase 0 验证结果、每周监测信号（注册表开收费、x402 放量、agent 框架格局）、用户投入意愿。
- **待决**：Phase 0 首发品类；首批框架接入对象排序；验收测试集的基准来源与维护方式；先验数据的合规抓取清单。

## 附录：关键质疑与设计推理记录

> 用途：正文只保留收敛后的设计；本附录保存分析过程中提出的关键质疑、双方论点、解法逻辑与被否决的替代方案，供后续完善方案时有据可查。条目状态：【已采纳】【已否决】【残留待验证】。

### Q1 买方假设之争：人类采购 vs agent 自主采购
- **质疑**：v1 假设「人类为自己的 agent 采购」，但字节扣子、腾讯 Skill Hub、OpenClaw 市场等平台玩家有先发、流量、资源与生态锁定，我方在此形态下无任何优势。
- **论点**：真正的分界不在「谁付钱」，在「谁做决定」——人类浏览选购是存量流量游戏；agent 在任务中自主发现缺口、比价、采购、安装是新物种市场，且其跨生态中立性要求与平台玩家的锁定战略结构性冲突，巨头做不了。
- **结论**：定位改为 agent 自主采购（运营方只设委托预算与权限）。【已采纳，见 §一】

### Q2 Arrow 信息悖论在本品类的解法链
- **质疑**：数据交易有 Arrow 悖论——不看不知道价值，看了就不用买；收费市场如何成立？
- **论点**：悖论只杀死「卖文件」模式。skill 是数据中价值最可测的品类（装上前后任务成功率差值可测），悖论在此最弱；再叠加三解：① 托管执行/沙箱，买的是效用不是文件；② 看证明不看内容（承诺＋统计＋验收数据）；③ 不事前定价、事后按实测结算。
- **结论**：以「沙箱验收」为枢纽落地三解——验收同时充当质量门、反馈源、结算触发器（过则付款、不过退款）。验收由 agent 自利的审慎驱动，无需激励设计。【已采纳，见 §二第二层、§四】

### Q3 评估成本由谁承担：平台重评估 vs 众包
- **质疑（用户）**：评估成本不应由平台承担；skill 的价值应来自使用/测试过它的 agent 群体的事实性反馈。
- **反质疑（老邪）**：平台侧保留「基准实验室」做全量实测与校准是否必要？
- **论点与收敛**：全量实测成本不可持续，且在地知识（skill 在各 agent 真实环境中的表现）平台实验室复刻不出来；但全众包会留长尾盲区。收敛形态为三层深度：收录审查（平台，浅而全，编辑判断）→ 验收/使用遥测（众包，深而真实）→ 争议深测（稀有而准）。平台只承担最便宜的第一层，「基准核心」降为第三层的按需触发。【已采纳，见 §二；「平台基准实验室」方案已否决，理由：成本与在地知识双输】

### Q4 众包积分闭环的三大硬伤及回应
用户提出「评估 earn 积分、积分买 skill」的回路后，老邪提出三点硬伤，逐条回应如下：
1. **冷启动价值锚**：积分在开局无物可买时即无价值，无人愿为废纸积分劳动，飞轮缺第一推动。→ 回应：积分不单独承载价值系统——买方侧同时有法币委托预算通道，积分只是抵扣与记账；货架侧靠先验导入＋收录门槛保证开局即有可买之物。积分锚定的是「站内真实商品」，不是空气。【已部分化解；积分与法币的兑换/抵扣细则待 Phase 0 定，残留待验证】
2. **计酬必被刷（Goodhart＋女巫）**：反馈一旦能换购买力即成为被优化目标；且 agent 刷分是脚本级并发，远胜人类众包的体力刷分；另有「谁评估评估者」的无穷回归。→ 回应：积分不可转让、不可提现、不可变现，刷的收益在源头衰减；反馈资格绑定真实使用（proof-of-use，每条反馈自带真实算力成本）；按历史准确率加权；互赞图谱检测；速率上限兜底。不追求根除，追求「造假成本＞收益」。【已采纳为现阶段防线；攻击演进后需迭代，残留待验证】
3. **试错风险与信号质量倒挂**：测未知 skill 等于运行不可信代码（提示注入可劫持测试者），理性 agent 只肯沙箱测，而沙箱信号弱；且「专职评估」作为工种会系统性劣化信号。→ 回应：信号权重明确排序——真实使用副产品遥测 ＞ 安装验收 ＞ 专职测试；积分主要奖励前两类，专职测试不作为主要信号源；验收在沙箱内运行且用市场统一测试集。【已采纳，见 §二第二层】

### Q5 激励之争：货币激励 vs 文化/声誉激励
- **质疑（用户）**：GitHub 星标与开源社区证明，无经济回报也有大量自愿评估与反馈；动力是运营氛围、机制与引导的工作，不是积分/金钱能推动的。
- **论点**：失败模式不同——货币激励的失败模式是「被攻击」（安全问题，agent 速度下瞬间爆），文化激励的失败模式是「冷漠」（运营问题，可慢修）；把问题从安全域挪到运营域是正确取舍。历史证据：质押策展注册表（TCR）2018 年后基本死绝，胜出的全是编辑＋声誉制（GitHub、Stack Overflow）。
- **结论**：动力设计非货币主导；反馈做成使用流程的副产品（无摩擦优先于有奖励）。【已采纳，见 §二；v2 的「质押策展」层已否决/降级，理由：TCR 历史教训＋与本条取舍冲突】

### Q6 防刷之争：账号体力值 vs 行为自带成本
- **质疑（用户）**：无商业动机则无刷分能动性；防作弊用机制限制即可（如每账号体力值/行动上限），应有更 smart 的解法。
- **保留（老邪）**：只要 skill 收费，操纵动机不消失、只转移——从刷积分变为刷排名（排名即分发即收入，SEO 产业即此理），防线不可全撤。
- **结论**：体力值的更优形态是让反馈本身自带成本（绑定可验证的真实使用记录），造假成本随规模自动生效；账号速率上限保留为粗暴兜底。【已采纳，见 §二】

### Q7 冷启动：全量收录 vs 门槛收录＋先验导入
- **质疑**：新市场无货、无评、无人，飞轮如何起转？
- **论点（用户）**：冷启动的货来自对已有市场 skill 的**精细化挑选收录**，不是全量搬运；收录动作本身即平台的最低成本评估，评分维度可科学设计。
- **补强（老邪）**：外部评分/反馈只作贝叶斯先验（噪声与操纵随之进口），必须随本站遥测积累自动衰减、由本土数据接管；跨源矛盾标旗复核；抓取合规逐源核查。
- **结论**：门槛收录＋先验导入＋衰减接管。【已采纳，见 §二第一层；先验合规清单待决，见 §十】

### Q8 洗稿与盗版：为何不靠内容指纹
- **质疑**：skill 是文本，复制与洗稿成本极低，确权与防盗版靠什么？
- **论点**：任何内容指纹都活不过足够强的改写（改写距离与水印鲁棒性的根本矛盾），内容端溯源是死路；对策是把确权从「数据是什么」前移到「谁创造的」（创作端签名＋内容寻址＋lineage），交易端卖托管执行与持续更新而非文件本体，洗稿者拿到的是过期快照。EvoMap 的教训同理：C2PA 式签名证明「谁签的名」，不证明「内容未被洗」。
- **结论**：确权走来源链，变现走服务化。【已采纳，见 §六、§九.5】

### Q9 定价公信力：为何不用评分定价
- **质疑**：EvoMap 用 GDI 声誉评分排序，是否可直接以评分定价？
- **论点**：评分≠价格。定价的公信力只来自两处：真实成交跑出的价格，或定价者押注、估错受罚的价格；不下注的估值只是意见。本案以「实测增量」为锚（买家验证集/验收数据可复算），作者定价并行，平台不发布「官方指导价」。
- **结论**：实测锚＋市场价，拒绝评分定价。【已采纳，见 §六】

### Q10 发现机制的克制论证
- **质疑（用户）**：让 agent 知道市场的做法（GEO、协议引导）稍不克制，就变成提示词注入式病毒攻击。
- **论点**：红线三对照——描述而非指令、拉取而非推送、运行时中介而非内容中介。克制不只是合规，更是竞争策略：发现环节的最大奖品是被运营方写进白名单的「默认可信」位置，该位置只发给从不用注入手段拉客的市场；GEO 可被劣质内容农场博弈，故本站对外内容同样须过本站策展标准（不双标）。
- **结论**：红线写死入协议层设计。【已采纳，见 §三】

### Q11 第二幕自问：本节点将来为何愿意协议化
- **质疑**：蓝图指出成熟节点理性上拒绝连接开放协议（护城河即锁定）。本方案 Phase 2 要求自家节点主动开放，是否一厢情愿？
- **预设论点（立项时须再确认）**：本节点的护城河设计为策展数据飞轮＋「默认可信」位置，而非生态锁定；开放确权/验收结果被外部引用反而扩大飞轮（被引用即被分发）。即：开放对本节点是扩张而非自毁——此点成立与否取决于 Phase 1 后飞轮是否真实形成。
- **状态**：【残留待验证——Phase 2 启动前必须重审此条，若飞轮未成立，协议化策略需重定，不得默认执行】

### Q12 结算形态的迁移判据（法币 → x402/算力）
- **质疑**：何时从法币/委托预算迁移到机器原生结算（x402 按次、算力计价），避免「硬套数字货币」或「永远不迁」两个极端？
- **判据（来自蓝图 §4 算力押注三条件）**：① 结算资产外生稀缺、非自印；② agent 身份不可随意分叉（否则分身逃废债务/罚没）；③ 结算结果机器可验证。三条齐备才迁移，缺一不迁。
- **状态**：【已采纳为迁移门槛，见 §四；具体时点由每周监测的 x402 与 agent 身份信号触发重审】
