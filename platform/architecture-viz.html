个人数据主权硬件架构 可视化蓝图

目标不是"玩 gadget"，是视频/多模态数据主权——第一视角视频、语音、图像数据的采集、存储、定价、授权，全在自己手里。对抗大厂黑盒（Meta 眼镜 + Confidential VM）。

一句话：两头开放，中间自主 —— Agent 层可换、显示层可换；采集层、数据层、协议是自己的。

02系统闭环流程图

这不是单向管道，而是一个闭环控制系统：前向搬运数据，反馈回路调参。实线 = 前向数据流，虚线 = 反馈回路。点击虚线看回流的是什么；用场景按钮看某条旅程走哪几段。

全景 —— 前向实线搬运数据，反馈虚线调参：Agent 用 L4 策略下发调采集参数，数据层用自家数据重训 L3 模型，输出层把审批结果送回 Agent。这是一个活的闭环，不是一次性管道。
点击任意一条虚线反馈回路查看详情。

03触发策略 L0–L4

采集的"分类判断"在哪里做。点击每档看说明。核心不是"L2 为主"，而是 L2 → L3 级联。

级联才是答案：L2 做召回（宁可误报，PIR 漏报少）→ L3 做精确（守门员，过滤误报）。本地预过滤省约 90% Wi-Fi 功耗。对数据资产目标，L3 必需——宁可少，不可脏。
点击上面任意一档查看详情。

04协议与通道

Adapter 模式：私有协议终止于你的固件。Muse 相关代码只活在 adapter 里，不渗进数据层。

🟡 你的系统（开放层间协议）

  • MQTT — 事件 / 触发 / 审批卡片 / 通知
  • HTTP — 文件 / 批量上传
  • 标准格式 — JPEG / MJPEG-AVI / WAV / JSON
  • 固件内部：muse_chat_session.cpp 拿到回复文本后，你的代码接管 → 发 MQTT、存文件、调 TTS
  • 长期方向：数据层包装成 MCP server，任何支持 MCP 的 agent 即插即用
国境线 · 私有协议到此为止

🟣 Muse（Demo 期私有通道）

  • 上行：gadget 私有协议（Wi-Fi → Meta 云，加密会话 + SDK token）；语音 push-to-talk → 转写
  • 自定义命令：link.register / main/app.c（如"读传感器""拍张照"）
  • 下行：文字回复（captions / TTS）；图片可发到带屏板子
  • home-network tunnel：云端 Muse 回访你内网 HTTP API（需 PSRAM 板子）
