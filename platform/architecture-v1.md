# 个人数据主权硬件架构 v1

> 整理：2026-10-17 夜（用户主导探讨）
> 状态：架构定稿 v1，**各层只给举例产品、不做具体选型**（用户明确不急采购）。
> 核心目标：视频/多模态数据主权——采集、存储、定价、授权全在自己手里。
> 一句话：**两头开放，中间自主**——Agent 层可换、显示层可换；采集层、数据层、协议是自己的。

---

## 设计原则

1. **采集终端的所有权 = 数据的铸币权**。对抗大厂黑盒（Meta 眼镜 + Confidential VM：数据进黑盒、用户拿不到）。
2. **两头开放**：Agent 可替换（当前可用 Muse，不永恒）；显示面可替换（借屏，不买屏）。
3. **数据走开放格式、开放协议**（标准视频容器、结构化 JSON；MQTT / HTTP / 文件），不依赖任何厂商私有协议（Muse SDK token/配对体系只用于"玩"的接入，不用于"占位"的数据管线）。
4. **触发判断下沉端侧**，云端只做策略下发和事后分析；触发策略本身是资产。
5. **不把任何当前模型能力当永久约束**；架构接口稳定，设备可升级（见升级矩阵）。
6. **宁可少，不可脏**——数据质量优先于数据量。
7. **工作记忆与数据资产分离**：多 Agent 共享上下文是薄的、任务作用域的、短命的；绝不塞进数据层（数据层是主权资产库，只增不改）。

## 分层架构

```
┌─────────────────────────────────────────────────┐
│ Tier 1 随身终端（固定）   输入+采集+瞥一眼        │  ← 贴身
│ Tier 2 大屏（开放渲染目标） 显示，可借屏          │  ← 随手
├─────────────────────────────────────────────────┤
│ Agent 层（可替换，当前 Muse）  理解·任务·策略下发  │  ← 两头开放
│  · 工作记忆层（薄层）：多 Agent 共享任务上下文      │
├─────────────────────────────────────────────────┤
│ 数据层（自己的）   存储·定价·授权，开放格式       │
├─────────────────────────────────────────────────┤
│ 边缘层（可选）     缓冲·预处理·data mule          │
├─────────────────────────────────────────────────┤
│ 采集层（贴身，固定）  眼睛·耳朵·手                │
└─────────────────────────────────────────────────┘
```

### 采集层（贴身，固定）

- 职责：眼睛（图像/视频）、耳朵（语音）、手（L0 手动触发）。
- 触发策略 L0–L4：
  - L0 手动：按钮/语音指令，零误报，瓶颈是人。
  - L1 定时：间隔拍摄（timelapse），数据量可预测。
  - L2 事件：PIR/声音/加速度/光线阈值，ESP32 本地零功耗可做。
  - L3 端侧智能：FOMO 目标检测 / 关键词唤醒；**级联：L2 做召回（宁可误报）→ L3 做精确（守门员过滤误报）**。FOMO 在 ESP32-S3 约 143ms/帧（~7fps@96×96），只适合"看一眼再决定"；关键词唤醒 12–15ms（最成熟）。简单任务真实世界精度 85–90%，复杂场景需自家数据重训。
  - L4 Agent 协同：云端按上下文动态调策略；或边缘传缩略图、云端看后追采。
- 举例产品（非选型）：ESP32-S3 系开发板；Seeed SenseCAP Watcher（带摄像头）；运动相机解耦（零 hack 独立录 / ESP32 经 BLE 调 Open GoPro API 当"导演"）。
- 已知瓶颈：ESP32-S3 无 H.264 硬编码，MJPEG 是唯一现实路线（VGA–SVGA 25–30fps，720p 约 5fps）；连续高清靠运动相机/手机。

### 边缘层（可选）

- 职责：data mule（离线缓存→有网批量上传）、NPU 预处理、结构化。
- 举例产品（非选型）：手机（算力最强，NPU 预处理；gadget 协议未给手机边缘身份，走"结构化结果写云端文件、Agent 去读"的绕路）；GL.iNet BE3600（用户已有，OpenWrt + USB 存储，做 data mule；无 MicroSD 槽、无电池）。

### 数据层（自己的）

- 职责：存储、定价、授权。开放格式（标准视频容器、结构化 JSON 事件），开放协议（MQTT/HTTP/文件）。
- 换 Agent 只换消费端，采集端和数据层不动。

### Agent 层（可替换）

- 职责：理解、推理、真实任务执行（办公/编程）、向端侧下发采集策略（L4）。
- 当前可用 Muse；**不锚定**——锚定单一云端 Agent 等于把数据主权又送回去。
- Muse Gadgets SDK 的定位是"连上 Muse 玩"，不解决"自主采集"；"占位"的数据管线不建在其私有协议上。

### 工作记忆层（多 Agent 共享上下文，薄层）

- 职责：多个 Agent 执行**同一个任务**时的共享工作记忆——任务目标、步骤状态、Agent 决策、中间结论摘要、审批状态。**与数据层严格分离**（用户纠正：把共享上下文塞进数据层会导致臃肿和耦合，数据层只做主权资产库）。
- 三不：
  - 不存原始音视频/图像本体——只存指向数据层资产的**指针**（如 `video_id` 引用 + 决策文本），本体留在数据层，两层通过引用关联、零耦合。
  - 不做长期记忆——长期记忆各 Agent 自带，不归本层。
  - 不进数据层——数据层只增不改、重、持久；工作记忆是任务的便签纸，轻、短命。
- 特性：任务作用域（thread / workflow ID）、TTL（任务结束 + 宽限期后过期）、小载荷、乐观并发（写冲突返回 409 让后写者重读再写，不用锁——Agent 会 stall/crash，锁会被死 Agent 永远占住）。
- 位置：边缘/云端的小服务，**不在 ESP32 上**；各 Agent 经自己的 adapter 以 MCP 工具形式读写。
- 实现：候选方案调研中（见 `platform/research/working-memory-candidates.md`），**未启用**。

### 输出层

- 内容：文字、静态画面、音频语音为主；**高清视频输出不需要**；3D/VR/AR/MR 暂不考虑。
- **Tier 1 随身（固定）**：ESP32 + 小屏 + mic + speaker + 物理按钮 + 震动马达。听文字、看少量提醒、语音输入、L0 手动触发。触摸不需要（小屏误触；按钮更可靠，可盲操作、戴手套）。
  - 举例产品（非选型，此前为研究推荐、非用户定稿）：Waveshare ESP32-S3-Touch-AMOLED-1.75C、M5Stack StickS3。
  - 音频：板载 I2S DAC + 喇叭 + 云 TTS（社区 ElevenLabs 方案）；注意 ESP32-S3 无经典蓝牙，A2DP 不通。
- **Tier 2 大屏（开放渲染目标，不买硬件）**：有手机接手机、有平板接平板、可投车机、有墨水屏就当常亮终端、办公桌电子相框也行。技术表达即 pub/sub：Agent 向主题发布结构化输出（卡片/文本/图），各显示面订阅渲染。
  - 专用常开面（可选）：ESP32 + 电子墨水屏审批终端，只管显示+批准/驳回/翻页轻交互，输入走 Tier 1；双稳态 + deep sleep 按月充电；尺寸甜点 7.5–10.3 寸；B&W 对代码/文档审批够用。
  - 观察清单（非采购）：Bigme B13 Pro（13.3 寸 60fps 彩色墨水显示器，$569 预售，2026-10-26 发货）、Kaleido 4 设备（汉王 M10C II）。
- 对称问题（留待以后）：**打扰策略**——何时震动/亮灯/出声 vs 采集侧的触发策略。

## 协议与通道（2026-10-17，用户提问）

**原则**：私有协议终止于你的固件；你的层间全开放；Muse 相关代码只活在 adapter 里，不渗进数据层。

| 段 | 协议/通道 | 性质 |
|---|---|---|
| 采集→边缘→数据（你的层间） | MQTT（事件/触发/审批卡片/通知）+ HTTP（文件/批量上传）+ 标准格式（JPEG/MJPEG-AVI/WAV/JSON） | 开放，现在就定 |
| 设备→Muse（Demo 上行） | gadget 私有协议（Wi-Fi→Meta 云，配对建加密会话，SDK token 做设备标识）；语音 push-to-talk→转写；自定义命令经 `link.register`/`main/app.c`（如"读传感器""拍张照"） | 私有，Demo 期用 |
| Muse→设备（Demo 下行） | 文字回复（captions/TTS）；图片可发到带屏板子；**home-network tunnel**：云端 Muse 回访你内网 HTTP API（需 PSRAM 板子） | 私有，Demo 期用 |
| 你的固件内部 | `muse_chat_session.cpp` 拿到回复文本后，你的代码接管：发 MQTT、存文件、调 TTS | 你的地盘 |
| Agent 适配层（长期） | thin adapter：今天背后是 Muse 私有协议；明天换 MCP server（数据层包装成 MCP 服务，任何支持 MCP 的 agent 即插即用）或纯 HTTP API；采集/数据/输出层不动 | 开放方向 |
| 多 Agent 工作记忆 | MCP 工具（thread 作用域读写 + TTL + 乐观并发），独立薄层，不进数据层 | 开放，候选调研中，未启用 |

**Demo 验证清单（流程+体验）**：
1. 配对 → push-to-talk → 文字回复 → 小屏显示 + TTS 播报（Tier 1 输出闭环）。
2. 自定义命令"拍张照" → ESP32 拍照 → 你的代码存 SD 卡 + HTTP 上传 → 数据层。
3. Muse 经 tunnel 读你内网 API（如已存照片/传感器历史）→ 在对话里引用。
4. 审批卡片：你的代码把 Muse 回复转成卡片 → MQTT → 手机/e-ink 渲染 → 按钮批准 → 回传。
5. （可选但有说服力）换 adapter 演习：同一份数据走 HTTP 直读，证明不依赖 Muse 协议也能消费。

## 数据流示例

1. **日常 lifelogging**：Tier 1 上 L1 定时拍照 + L2 PIR 唤醒 → L3 FOMO 确认 → 存 SD 卡 / 经边缘层批量上传 → 数据层。
2. **会议记录**：L0 手动/语音"开始记录" → 运动相机录制（ESP32 经 BLE 当导演触发）→ 事后转录结构化 → 数据层。
3. **Agent 办公审批**：Agent 产出 → pub/sub 发布审批卡片 → e-ink 常开面 / 手机渲染 → 用户批准（Tier 2 按钮 / Tier 1 语音）→ 结果回传。

## 升级矩阵（架构支持设备升级，接口不变）

| 层 | 今天 | 明天（更好设备出现时） | 始终不变的东西 |
|---|---|---|---|
| 采集 | ESP32-S3（MJPEG） | 下一代 H.264 硬编码+无线二合一、更好 sensor | 触发协议 L0–L4、数据格式 |
| 边缘 | 手机 / BE3600 | 更强 NPU、更大存储 | MQTT/HTTP 接口 |
| 数据 | 本地 + 云文件 | 存储介质/位置可变 | 开放格式 |
| Agent | Muse | 任意模型/Agent | 消费接口 |
| 工作记忆 | 候选方案评估中（轻量 MCP server） | 同左（自研只在候选都不满足时） | MCP 工具接口 + thread/TTL/乐观并发约定 |
| 显示 Tier 1 | ESP32 小屏终端 | 更好屏幕/功耗的随身终端 | 渲染协议 |
| 显示 Tier 2 | 借屏（手机/平板） | 彩色墨水成熟、任意新显示面 | pub/sub 卡片协议 |
