# contracts/ — 项目内共享契约区

> 状态：已立区，契约本体待定稿；**契约一页（provenance 信封＋权威词表映射＋事件模型归属）为整体蓝图阶段二开工门**
> 维护线：两区共有（整体线／共享记忆子项目）
> 最后更新：2026-11-08
> 摘要：两区共享的接入契约、后续互通约定及变更协议。

## 本区是什么

整体线（`platform/`）与共享记忆子项目（`memory/`）之间**唯一的耦合面**。两个部分节奏不同、分别推进（2026-11-06 起为同一项目内的分区，不再是两条并行线），能长期互不干扰的前提，是它们之间只通过本区的成文契约打交道，而不是依赖任何一方的内部实现细节。

## 接入契约

| 文件 | 中文标题 | 说明 | 状态 |
|---|---|---|---|
| [memory-integration-spec.md](memory-integration-spec.md) | PAT 与共享记忆子项目接入契约 | 统一事件来源、主动回传、词表与确认，定义阶段一和二的交付边界 | 草稿，待两区确认 |

以下是契约覆盖方向。初期以同一份接入契约说明必要语义，有独立实施需求时再拆分。

- **provenance 信封**：跨线数据/记忆条目的来源标注格式（谁、何时、经何通道写入）。
- **文件原生约定**：共享内容以文件（Markdown / JSON 等开放格式）为原生载体的格式约定。
- **读接口约定**：数据层/记忆层对 Agent 暴露的 HTTP + MCP 读接口形态。
- **权威等级词表**：多来源内容冲突时的权威等级定义与取值。
- 其余互通点由两线在实际对接中提出，按下方协议增补。

## 变更协议（与根目录 AGENTS.md 一致，细化于此）

1. 任一区可提议新增或修改契约，修改直接提交到本区，但必须在 `CHANGELOG.md` 追加记录：日期、提出方、变更摘要、原因。
2. 破坏向后兼容的变更，须在记录中显式标注「破坏性」，并注明"待另一区确认"；另一区在下次同步本区时，将确认结果补记在同一条记录下。
3. 本区只放契约本体与变更记录，不放任一线的内部设计文档（各归本区）。
4. 未来 `memory/` 区抽出为独立仓时，本区中与共享记忆相关的契约条目一并复制随行；原仓保留原文，并在 `CHANGELOG.md` 注明抽仓日期。
