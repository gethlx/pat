# contracts/ — 两线共享契约区

> 状态：已立区，契约本体待两线共同定稿
> 维护线：两线共有
> 最后更新：2026-10-21

## 本区是什么

整体线（`platform/`）与共享记忆线（`memory/`）之间**唯一的耦合面**。两条线节奏不同、分别推进，能长期互不干扰的前提，是它们之间只通过本区的成文契约打交道，而不是依赖任何一方的内部实现细节。

## 预定收录的契约（待定稿，定稿后逐项落为独立文件）

- **provenance 信封**：跨线数据/记忆条目的来源标注格式（谁、何时、经何通道写入）。
- **文件原生约定**：共享内容以文件（Markdown / JSON 等开放格式）为原生载体的格式约定。
- **读接口约定**：数据层/记忆层对 Agent 暴露的 HTTP + MCP 读接口形态。
- **权威等级词表**：多来源内容冲突时的权威等级定义与取值。
- 其余互通点由两线在实际对接中提出，按下方协议增补。

## 变更协议（与根目录 AGENTS.md 一致，细化于此）

1. 任一线可提议新增或修改契约，修改直接提交到本区，但必须在 `CHANGELOG.md` 追加记录：日期、提出线、变更摘要、原因。
2. 破坏向后兼容的变更，须在记录中显式标注「破坏性」，并注明"待另一线确认"；另一线在下次同步本区时，将确认结果补记在同一条记录下。
3. 本区只放契约本体与变更记录，不放任一线的内部设计文档（各归本区）。
4. 未来 `memory/` 区抽出为独立仓时，本区中与共享记忆相关的契约条目一并复制随行；原仓保留原文，并在 `CHANGELOG.md` 注明抽仓日期。
