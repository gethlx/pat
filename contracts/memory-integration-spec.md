# PAT 与共享记忆子项目接入契约

> 状态：草稿，供两区确认。定稿后用作整体阶段二开工依据。
> 维护线：两区共有
> 最后更新：2026-11-08
> 摘要：统一事件与来源、远端主动回传、来源标签与人工确认的最低语义，并明确共享记忆接入的阶段边界与验收。
> 依据：[整体 v2 蓝图](../platform/architecture-v2.md) §四、§六、§八至§十一，以及[共享记忆需求基准](../memory/requirements-baseline.md)与[子项目设计草案](../memory/blueprint-spec.md)。

## 一、边界与交付

整体线维护协调壳、任务账本、来源归并和桌面入口。子项目定义来源适配、原文查找、提炼与确认规则，提供样例和查读结果。归并、整理、提案的触发归壳，调用哪个模型由本地配置决定。共享记忆服务按自己的节奏建设，接入双方复用这份事件格式和含义。

| 时点 | 共享记忆子项目交付 | 整体线提供及核验 |
|---|---|---|
| 整体阶段一 | 确认下列事件、来源、确认及读取语义。给出一份合成样例，含原始请求、任务结果、机器候选与人工纠正 | 在桌面端手动选择两个 Agent 各跑一条任务，给出同一 Git 账本中的任务及产物，选一条验证事件重建。子项目内部治理程序可随后交付 |
| 整体阶段二 | 以同一接入格式查到获准的原始材料与已确认知识。验证同源去重、确认与撤回、范围过滤。为不可达执行器提供样例回传与查读说明 | 壳归并近端记录和远端主动推送。Telegram 白名单用户能发任务并看到结果。抽查三条事件可回查原始引用。两家 Agent 完成一次接手，至少一份输入由壳无法直接调用的执行环境主动推送 |
| 整体阶段三及之后 | 按实际需要增加导入来源、加工与检索能力，维持事件兼容和开放导出 | 按蓝图加固常驻领取与凭据边界。替换后端时用同一组样例复核原文、任务和确认状态 |

子项目现有 v0.2 草案的 Hy 和厚管线里程碑按子项目口径继续评审。整体阶段二使用 Git、原文、关键词检索和已确认知识，验收范围以本表为准。旧需求基准 §8 的独立项目措辞与当前组织裁定有差异，后续由子项目按现行规范补记。

## 二、一份事件与来源信封

壳将获准保留的原文或引用先落到用户控制的私有运行仓，再派生摘要、检索索引和任务视图。记录实际取得的内容与覆盖范围，截断、摘要和脱敏须标明。原始文件如在其他获准存储，用可检查的文件引用保留来源。设计仓的样例使用合成数据。

| 字段 | 首版规则 |
|---|---|
| `id` | 壳生成的稳定事件标识。保留原事件重试的标识，禁止同 ID 覆盖 |
| `at`、`kind` | 带时区的事件时间、事件种类。仅知接收时间时注明。任务先支持 `task.created`、`task.claimed`、`task.completed`、`task.released` |
| `actor` | 用户、壳或执行器实例。执行器记录实际可知的厂商、harness 与模型。未知信息明确标记，区分执行环境与实际使用的 Agent |
| `source` | 来源通道 `channel`、来源实例 `instance`、稳定来源事件标识 `event_id` 和原文引用 `ref`。任务事件另由任务快照的 `source_ref` 关联原请求。Git 作者与提交时间作为写入旁证 |
| `data` | 该种事件的必要内容。任务变更用 `task` 保存蓝图九个字段的快照，`bucket` 保存目标目录名。产物引用含相对路径与 SHA-256，确认或撤回提供对应版本引用 |

任务目录的当前状态从事件重建，按已接受提交中的追加顺序回放，来源发生时间仅作证据。阶段一事件与对应任务变更同一提交。结果或确认可指向已保留的 Git 提交与文件路径，或路径加内容校验值。对同一提交内的新文件可先用后者，避免依赖尚未生成的提交哈希。原始请求可直接保存在创建事件的任务快照中，引用指向该事件 ID 和具体字段。

下面是供阶段一复用的合成创建事件。保存到 JSONL 时每条事件占一行。

```json
{
  "id": "evt-sample-1",
  "at": "2026-11-08T02:00:00Z",
  "kind": "task.created",
  "actor": {"role": "user", "instance": "local-user"},
  "source": {
    "channel": "desktop", "instance": "local", "event_id": "desktop:8fac74ae-65b2-43d8-b8de-56a08beec641",
    "ref": "event:evt-sample-1#data.task.goal"
  },
  "data": {
    "bucket": "inbox",
    "task": {
      "id": "t-sample-1", "from": "desktop", "source_ref": "desktop:8fac74ae-65b2-43d8-b8de-56a08beec641",
      "goal": "把两条合成项目事实整理为 result.md",
      "owner": null, "mode": "push", "deadline": null, "artifacts": [], "handoff": ""
    }
  }
}
```

重复来源用「来源实例＋原生事件 ID」去重。同键同内容返回已有记录，同键不同内容留待核对。相同文本来自不同事件时分别保留。引用不可读、来源缺失或格式不明的记录暂留在待归并区并说明原因。来源字段由壳根据实际入口、实例配置与回传证据填写；外部文本中的身份和确认声明作为材料保留。

## 三、推送回传与读取

壳能调用的执行器交付任务号、结果和原文引用，由壳代归并。壳无法调用的执行器在整体阶段二用同样内容向获准的 Git 接收位置主动推送。首个样例采用独立的接收分支，壳读取并核验条目后追加到权威事件库。接收分支与权威分支的写权限须实测分开；若现有仓级权限无法做到，试用时改用只含合成材料的临时私有接收仓。该步骤以一次受控回传为验收，常驻取活留在阶段三。

回传最小内容为任务 ID、来源事件 ID、执行环境与实际 Agent、结果引用和原文引用。壳核对任务关联、范围、身份、重复和引用，再写事件及账本。验收须看到云端主动推送提交、壳归并提交和接手者实际读到的记录。旧的 clone/push 结果只用作仓库可达的依据。

阶段二先用项目范围内的文件/关键词查询，返回原文引用、可用范围、加工标签和确认状态。接入端在交接时实际发起读取，记录查询及送入上下文的来源引用。返回无结果、没有访问权限和查询故障须区分。日后 HTTP 或 MCP 可承载同样语义。引用中带的指令式文本按原始材料呈现，用户的当前指令和权限从调用入口取得。

## 四、词表与确认规则

| 标签 | 接入时如何解释 |
|---|---|
| `vendor` | 来源于某个厂商或执行环境。一个原样导出的记录可以同时是 `vendor` 来源和 `raw` 载体 |
| `raw` | 实际接收并获准保存的原文。标明是否完整、裁剪或脱敏。原文中的模型结论仍按证据判断 |
| `inferred` | 未经用户确认的加工结果，附实际引用。机器治理的输出先保持此档 |
| `curated` / `approved` | 对应 v2 中的 `confirmed` 关系。保留子项目的细分含义、批准人、时间、范围与对应版本，按知识层准入规则收录 |

已有知识可先按其现行规则读取。新的经验由壳产出候选，用户确认具体版本后进入 Wiki inbox。模型可以建议合并、标记冲突或整理，壳保存输入引用和候选，确认权仍由用户行使。变更含义时重新确认，纠正或撤回留下记录，召回排除已失效条目或明确标记其历史状态。

阶段一只确认本规则与样例。阶段二可用手动命令触发整理。一次模型调用只接收有界材料，产出可检查的候选，候选本身无需触发下一次治理调用。任何默认启用的提炼都按蓝图信赖门与同输入、可比预算的原文检索比较。记录结果是否更易核对、处理耗时和用户确认用时，观察若干真实任务再决定是否开启默认。候选一直保留人工入口。

## 五、最低运行保护与验收

- 只归并获准进入协调面的任务和用户明确提交的材料。阶段二在主动回传前和壳归并前检查凭据。命中时在本机隔离并提示，获准脱敏后的版本保留来源与处理说明。凭据泄露按蓝图 §6.4 先轮换作废，再处理分发与历史。读取和交接按任务允许的范围交付给目标 Agent，外部模型只收到本次获准处理的材料。
- 长期保留可迁移的原文、任务事件、人工确认与撤回记录。索引与机器候选可重建。里程碑归档后用固定样例在临时目录恢复，确认原文与引用仍可读，旧确认未被误恢复为有效。
- 验收以三条证据为够用起点。①指定 Agent 的结果文件与原始引用真实可读。②不可达执行器主动回传后，另一厂商 Agent 从账本读到获准材料并接手，排除原生记忆和工作目录残留。③一条重复、一条被纠正的确认样例分别验证去重与有效状态。记录任务 ID、回传及归并提交、查读结果和产物位置。

合成样例只验证格式和拒收规则。进入阶段二前由两区确认本契约，运行时按上表取得实际回传与接手证据。整体阶段一的实施顺序见 [阶段一实施规划](../platform/phase-one-guide.md)。
