# 多智能体共享记忆系统 · 项目蓝图（草案 v0.2）

> 状态：**草案，待用户审定冻结**（v0.1 2026-10-21；v0.2 2026-11-05 并入 Raw-RAG／Obelisk 五条修订，理由见文末《v0.2 修订说明》）。依据：`requirements-baseline.md`（已冻结，含 2026-10-20 修订）。底座已定：混元 Hy-Memory（MemHub 现成用＋SDK 集成，不 fork）。本蓝图把此前各轮结论收拢为一张施工图：适配评估见 `projects-fit-2026-10-20.md`，社区实证见 `community-eval-2026-10-20.md`，设计借鉴见 `deepdive-hy-openviking-2026-10-20.md` 与 `design-notes-agent-beacon-2026-10-20.md`。

## 架构总览（五层）

```
┌ 接入层 ────────────────────────────────────────────────┐
│ MemHub 插件（已覆盖工具）｜ MCP/SDK 直连（自有 agent）   │
│ 可编程查询面（直查原始事件库）｜ 记忆→Skill 编译交付      │
│ Gateway 模式（预留：封闭 agent）                        │
├ 知识层（已建成，不动）─────────────────────────────────┤
│ LLM Wiki（git 仓，现行 WIKI_RULES）＝最高权威            │
│        ▲ 单向晋升（候选→人确认→inbox→策展）             │
├ 经验层（Hy 引擎，加工分档、存储统一）──────────────────┤
│ 厚管线：Chat/Working —— Hy 分层认知＋evolve（受治理）   │
│ 薄管线：Coding 先行 —— 捕获→候选门→审核→lesson         │
│ 统一存储与事件模型（两条管线产物同仓同格）              │
├ 输入与共存层 ──────────────────────────────────────────┤
│ MemHub 导入（本地 10 工具）｜ web 四家导出 ETL（自建）   │
│ deja-vu 式索引（未覆盖 harness 补位，可选）              │
├ 治理层（横切，全自有）─────────────────────────────────┤
│ provenance 信封＋权威词表 ｜ 行为轨迹（审计）｜ 检索轨迹  │
│ 衰减与归档 ｜ 失败看门狗 ｜ 数据镜像（原始层优先入 git）  │
└────────────────────────────────────────────────────────┘
```

## 关键设计约定

**1. 原始事件为真相源（2026-11-05 并入）。** 经验层内一切提炼产物（分层记忆、摘要、evolve 产物、晋升候选）都只是原始事件之上的视图与缓存：可丢弃、可从原始事件全量重建；任何蒸馏、进化、摘要不得成为其所依据内容的唯一副本。推论：事件存储只增不改（append-only）；数据镜像优先保证原始事件全量，提炼产物可再生、不承担主权保险。理由见文末《v0.2 修订说明》①。

**2. 统一事件模型（输入层契约）。** 一切输入先归一成事件再入层：字段至少含 id、时间、来源（厂商／harness／会话）、行为主体、事件类型（发言／工具调用／命令／编辑／审批／…）、内容引用、provenance（原始载体与导入路径）。解析器（MemHub 导入、ETL、索引器）各自适配此模型——借 Beacon 的"schema 先行"。

**3. 经验层：只分加工、不分存储（2026-10-21 用户裁决，带对冲并入）。**
- 薄管线（Coding）：捕获→**候选门**→人工审核→lesson（以 Skill／MD 形态交付，并写回统一存储）。
- 厚管线（Chat／Working）：Hy 全量分层认知；记忆写入先用前沿大模型，混元专用 30B 模型列为后续成本优化选项，不进一期。
- Hy 的 evolve 默认收着用：进化动作必须留痕、可回滚，按治理层规矩配置，不用其默认无监督模式。
- **对冲一（防碎片化）**：两条管线产物同仓同格，薄管线定位为厚引擎的前置过滤，不是平行系统；下游召回只面对一个存储。
- **对冲二（防押错）**：厚度升降级用硬信号触发——初始参考值：薄管线 lesson 人工驳回率滚动超过 30% → 评估该场景升厚；跨场景召回失败案例累计达 10 例 → 评估升厚；厚管线某场景条目 90 天零召回 → 评估降薄。（数值是初始值，运行后按数据校准。）
- **对冲三（防拖延）**：厚管线（Chat）最小闭环是阶段二的**硬里程碑**，不得以薄管线"够用"为由顺延。
- **对冲四（防误信，2026-11-05 并入）**：厚度的取舍是信赖问题、不是建造问题。厚管线照建（对冲三里程碑不动）；但每一项厚功能在转成系统默认依赖前，必须在与其功能对应的指标上赢过 Raw 基线（对原始事件的直接检索，见约定 1）——问答类比问答得分、主动浮现类比浮现命中率（推出去的记忆实际被采用的比例）、跨源合并类比跨源题（任何单一来源都答不出的问题）得分。赢不了的降为可选或关闭；每次对照的评测结果入档备查。理由见《v0.2 修订说明》②。

**4. 候选门规格（晋升与 lesson 共用）。** 模式借 Beacon＋Jev：类型化问题＋校准概率＋阈值，概率连同评估器身份与用量写入 provenance；评估器只分诊、不写文本，文本由人批准时产生。**修正 Beacon 的成功前置**：失败任务单设问题集（含"失败原因是否明确／教训是否可复用"），产出打 failure-lesson 标签——试错经验不被系统性过滤。实现优先本地（小模型须验证其概率可用性，不可信则退回纯人工分诊）；外部评估服务（如 Jev）只作可选项，且必须走脱敏投影。

**5. 知识层与晋升通道。** Wiki 维持最高权威与原有规则；晋升单向：经验层候选池→人确认→wiki inbox。晋升候选中的提炼性内容按"合成缓存"入池（权威上限见约定 6），不得以摘要形态冒充原文证据晋升。召回侧可跨层检索，但结果须带层级与权威标注，经验不得冒充知识呈现。

**6. 治理层细则。**
- 权威词表四级：raw／inferred／curated／approved，全层通用。**提炼产物权威封顶（2026-11-05 并入）**：一切机器提炼产物（分层记忆、摘要、evolve 输出、晋升候选摘要）最高只能标 inferred，必须链回所依据的原始事件，且可被原始检索结果推翻；curated 及以上只授予人确认过的内容。理由见《v0.2 修订说明》④。
- **行为轨迹（2026-10-20 用户批准并入）**：记录 agent 行为事件（命令、编辑、审批、敏感动作打标，风险分类词表借 Beacon），与记忆原料同一事件流，一鱼两吃（经验来源＋审计底账）。
- 检索轨迹：谁、何时、召回了什么，留痕备查并反哺衰减计算。
- 衰减：经验按召回曝光计龄，长期零召回者归档（可见、可恢复，不静默删除）；归档动作本身入轨迹。
- 失败看门狗：导入／进化类任务的"成功"必须附产物证据（条数、落盘校验），零产出报成功即告警——针对赛道通病"静默失败"设防。
- 数据镜像：经验层存储定期导出为开放格式（MD／JSONL）入我方 git 仓，作为主权保险与搬家通道；**优先级：原始事件全量优先，提炼产物可再生（呼应约定 1）**；镜像完整性纳入看门狗检查。

**7. 接入层梯队。** 已被 MemHub 覆盖的工具走其插件；自有 agent 走 MCP／SDK 直连；**可编程查询面（2026-11-05 并入）**：向 agent 开放对原始事件库的 JS／SQL 式查询接口（借 Obelisk 形态），与 MCP 并列为正式接入形态——真相源必须可被直接查询，而不是只能经提炼层转述，理由见《v0.2 修订说明》⑤；已批准 lesson 可编译为 Agent Skill 交付（借 Beacon）；Gateway 代理注入只预留接口与设计注记，一期不实现（触发条件：出现只能经 API 链路接入的封闭 agent，PAT 侧概率高）。

## 构建顺序

- **阶段一**：蓝图冻结；假设查实（Hy 的 SDK 写入协议、MemHub 本地数据目录与导出形态、事件模型字段细化）——查实是为蓝图落地，不是否决程序。
- **阶段二**：薄管线（Coding）跑通＋**厚管线（Chat）最小闭环跑通（硬里程碑）**；统一存储与事件模型落地；数据镜像开跑。**（验收注脚，2026-11-05 并入：里程碑原文不变；厚管线建成后须按约定 3 对冲四对照 Raw 基线量过、结果入档，才算验收完成。）**
- **阶段三**：web 四家 ETL；晋升通道与候选门完整形态；治理层自动化（衰减、轨迹、看门狗）。
- **阶段四**：调试优化期——分场景回归评测集（借 AML 方法论）上线，**评测常设 Raw-RAG 对照臂（2026-11-05 并入）**：任一厚功能以纯原始检索为对照组；题型在决策溯源题基础上扩为**证据链题**（答案依赖关系链／依赖路径的问题——提炼最易在此丢分，是检验提炼层成色的最严题型）。此后每次调参/改规则过评测再合入。

## 与需求基准的映射（摘要）

跨厂商（基准§1）→ 接入层梯队＋事件模型；两层分治（§2）→ 经验/知识分层＋晋升单向；慢层先行（§3）→ 全层无实时同步设计，快层仍观察；共存 ETL（§4）→ 输入层 MemHub＋自建 ETL；主权（§5）→ 数据镜像＋开放格式＋本地优先；治理底线（§6）→ 治理层五件；知识层形态（§7）→ 原样保留；PAT 预留（§8）→ Gateway 预留＋事件模型可扩展，不进一期实现。v0.2 新增的真相源原则与信赖门属基准§6（治理底线）在经验层内部的延伸，待基准下次修订时正式对齐。

## 未决项（不阻塞蓝图审定，阶段一查实/细化）

1. Hy 存储的实际格式与官方导出能力（决定数据镜像的实现方式）。
2. MemHub 与 SDK 的分工边界：MemHub 用到应用层为止，还是只取其导入能力、召回走 SDK。
3. 候选门本地实现的概率可信度验证方法。
4. 行为轨迹的采集范围与端点形态（哪些 harness 能采到动作级事件、采不到的如何降级为会话级）。
5. 信赖门的初始指标与阈值（浮现命中率口径、跨源题集构成）——阶段二建成厚管线后、首次对照评测前定。

## v0.2 修订说明（2026-11-05）

本版修订源于 Raw-RAG 论文（《Is Complex Agentic Memory Always Needed?》，arXiv:2610.30755）与 Obelisk 项目的参照评估（设计笔记 `2026-10-31-raw-rag-obelisk-notes.md`）。五条并入、一条否决，逐条理由如下：

- **① 原始事件为真相源（并入 → 约定 1）**。论文的机制解释指认：提炼丢失的恰是关系与依赖路径，"保留原始信息"是 Raw-RAG 胜出的关键变量。本蓝图原有统一事件模型、Wiki 层 raw 不可变、数据镜像三块拼图，但从未立为原则；立为明文后，提炼产物的地位（视图／缓存）与镜像优先级都有了统一判据。
- **② 信赖门（并入 → 约定 3 对冲四）；原拟"默认薄＋改写阶段二里程碑"方案未采纳。** 未采纳的三条理由：(a) Chat 场景的核心价值是主动浮现与跨源合并，原始检索在结构上做不到，而论文基准只测问答——用问答尺卡非问答功能，举证门会误杀；(b) Chat 厚管线由 MemHub 现成形态提供、不是从零建造，"先薄后厚"的建造成本论据不成立，真实问题是建成之后信它几分；(c) 把里程碑改写成"基线＋验证门"，会使厚管线最小闭环在没有任何厚产物时也能宣布完成，等于亲手拆掉 2026-10-21 对冲三的防吞噬保险。采纳的修正版：不翻默认姿态、里程碑不动，只改验收标准——实证主义用在"信赖"关、不用在"建造"门口。附带一条代价判断：两种错不对称——厚功能误建亏数周工时；浮现与合并能力漏建，亏的是本系统成立的理由。
- **③ 评测对照臂与证据链题（并入 → 阶段四）**。没有常设对照臂，"厚功能有增量"永远只是口号；证据链题是论文指认的提炼最易丢分处，与原有决策溯源题同族，合并扩容。
- **④ 提炼产物权威封顶 inferred（并入 → 约定 6、约定 5）**。借 Obelisk 对其自身记忆层的定位——"综合缓存，不是原始证据的替代品"（a synthesis cache, not a replacement for raw evidence）。防的是摘要在召回与晋升中冒充事实；与基准§2"经验不得冒充知识"同向，本次向经验层内部再延伸一层。
- **⑤ 可编程查询面（并入 → 约定 7 与架构图）**。Obelisk 证明：给 agent 一个可编程查询接口直查原始事件库，成本低、与薄管线天然配套。列为正式接入形态，与约定 1 呼应——真相源必须可被直接查询。
- **顺手对齐**：架构图知识层注记"WIKI_RULES v4"改为不钉版本号——现行 WIKI_RULES 已迭代至 v10，钉版号必然腐坏；需求基准 §7 的同类过期引用待基准下次修订时一并对齐。
