## 架构总览（五层）

```
┌ 接入层 ─────────────────────────────────────────────────┐
│ MemHub 插件（已覆盖工具）｜ MCP/SDK 直连（自有 agent）    │
│ 召回钩子（检索→注入→留记录）｜ 记忆→Skill 编译交付        │
│ Gateway 模式（预留：封闭 agent）｜ 读取范围配置           │
├ 知识层（角色位，独立实例）──────────────────────────────┤
│ 符合两层契约的 LLM Wiki 形态知识库＝最高权威（见样板）    │
│        ▲ 单向晋升（候选→人确认绑定版本→inbox→收录）       │
├ 经验层（Hy 引擎，加工分档、存储统一）───────────────────┤
│ 厚管线：Chat/Working —— Hy 分层认知＋evolve（受治理）    │
│ 薄管线：Coding 先行 —— 捕获→候选门→审核→lesson          │
│ 统一存储＝经验层唯一权威记录（只经受治理写入路径改动）    │

├ 输入与共存层 ───────────────────────────────────────────┤
│ MemHub 导入（本地 10 工具）｜ web 四家导出 ETL（自建）    │
│ deja-vu 式索引（未覆盖 harness 补位，可选）｜ 安全导入规程 │
├ 治理层（横切，全自有）──────────────────────────────────┤
│ provenance 信封＋权威词表 ｜ 写冲突分级 ｜ 批准与撤回     │
```

运行数据（真实会话、行为日志、经验条目及其镜像）一律存放在独立的私有数据存储中，不进入本设计仓，见约定 9。

## 关键设计约定

**1. 统一事件模型（输入层内部规则）。** 一切输入先归一成事件再入层：字段至少含 id、时间、来源（厂商／harness／会话）、行为主体、事件类型（发言／工具调用／命令／编辑／审批／…）、内容引用、provenance（原始载体与导入路径）。解析器（MemHub 导入、ETL、索引器）各自适配此模型——借 Beacon 的"schema 先行"。事件模型是本线内部规则，由本线自定、随实施细化；其中与整体线互通的部分只经契约区对接，见约定 10。原始事件保留不删，每条经验须能回溯到其原始事件。

**2. 唯一权威存储与写入路径。**
- **经验层的唯一权威记录是统一存储中的条目及其变更记录。** 一条记忆"现在是什么、处于什么状态、经过哪些改动"，只以这里为准。知识层另有其权威实例（远端仓为真相源，见[知识层样板](knowledge-layer-sample-spec.md)），两层各自一份权威、不共享运行时。
- **一切写入只经受治理写入路径。** 薄管线、厚管线（含 evolve）、MemHub 导入、web ETL、人工编辑、撤回与归档，都通过同一写入路径进入统一存储；这条路径统一执行：provenance 必填、权威等级赋值（约定 5）、写冲突分级（约定 5）、批准状态校验（约定 8）、读写范围（约定 9），并为每次写入追加一条变更记录。
- **派生产物不是事实来源。** 检索索引、开放格式镜像、编译出的 Skill 都是可从统一存储重建的派生产物；直接改派生产物不回写权威记录，需要改动时回到写入路径。MemHub 应用若保留自己的本地状态，同样视为输入源或派生视图，不作为第二份事实来源。
- 写入路径用 Hy SDK 能力实现，还是在其前面加一层薄的自有写入层，在阶段一按上述约束查实后定；约束本身不因实现方式改变。

**3. 经验层：只分加工、不分存储（2026-10-21 用户裁决，带对冲并入）。**
- 薄管线（Coding）：捕获→**候选门**→人工审核→lesson（以 Skill／MD 形态交付，并写回统一存储）。
- 厚管线（Chat／Working）：Hy 全量分层认知；记忆写入先用前沿大模型，混元专用 30B 模型列为后续成本优化选项，不进一期。
- Hy 的 evolve 默认收着用：进化动作必须留痕、可回滚，按治理层规矩配置，不用其默认无监督模式；evolve 产出的改写一律标 `inferred`，不继承被改写条目的人工批准（约定 8）。
- **对冲一（防碎片化）**：两条管线产物同仓同格，薄管线定位为厚引擎的前置过滤，不是平行系统；下游召回只面对一个存储。
- **对冲二（防押错）**：厚度升降级用硬信号触发——初始参考值：薄管线 lesson 人工驳回率滚动超过 30% → 评估该场景升厚；跨场景召回失败案例累计达 10 例 → 评估升厚；厚管线某场景条目 90 天零召回 → 评估降薄。数值是初始值，运行后按数据校准；统计口径见约定 7。这些是运行期观察信号，不是阶段验收门。
- **对冲三（防拖延）**：厚管线（Chat）最小闭环是阶段二的**硬里程碑**，不得以薄管线"够用"为由顺延。

**4. 候选门规格（晋升与 lesson 共用）。** 模式借 Beacon＋Jev：类型化问题＋校准概率＋阈值，概率连同评估器身份与用量写入 provenance；评估器只分诊、不写文本，文本由人批准时产生。**修正 Beacon 的成功前置**：失败任务单设问题集（含"失败原因是否明确／教训是否可复用"），产出打 failure-lesson 标签——试错经验不被系统性过滤。实现优先本地（小模型须验证其概率可用性，不可信则退回纯人工分诊）；外部评估服务（如 Jev）只作可选项，且必须走脱敏投影并受约定 9 的外部加工范围约束。

**5. 治理层细则。**
- **权威词表四级：raw／inferred／curated／approved，全层通用。** 导入的原始素材（MemHub 导入、web ETL、索引器采到的原文）默认 `raw`；模型对任何输入做的抽取、归纳、改写（含厚管线分层认知与 evolve）产物标 `inferred`；经人工审核纳入经验层的 lesson 标 `curated`；`approved` 只属于按约定 8 获得人确认、进入知识层的结论。权威等级只能由写入路径按上述规则赋值，加工动作不能抬高等级。
- **写冲突分级（不静默覆盖）。** ① 重复写入（重复导入、重试同一请求）：按来源标识＋内容指纹自动去重，记一次去重，不产生新记忆；② 版本冲突（写入时条目已被他方改动）：按版本号做乐观并发校验，拒绝本次写入并由写入方重读后重试；③ 内容冲突（两方对同一事实给出无法自动合并的不同说法）：双方版本都保留，条目标"待裁定"并进入人工队列。底线：任何情况下不做后写覆盖、不静默丢失；三类处理都写入变更记录。
- **召回保证（可验证的范围）。** 本系统保证的是：在支持的接入方式下，接入层**执行检索、把结果注入上下文、并留下检索记录**；不保证模型一定理解或采纳注入内容。触发时机：会话开局注入；会话中途在接入方式支持时，由任务切换／显式工具调用钩子再检索（MCP 工具、harness 钩子）。各接入方式的能力分档：MemHub 插件与 MCP/SDK 直连按其实际钩子能力标"开局＋中途"或"仅开局"；只能事后导出的 web 端厂商记为"无在线召回保证（仅事后导入）"；Gateway 模式为预留。召回结果带层级与权威标注，经验不得冒充知识呈现。阶段一查实各接入方式落在哪一档。
- **行为轨迹（2026-10-20 用户批准并入）**：记录 agent 行为事件（命令、编辑、审批、敏感动作打标，风险分类词表借 Beacon），与记忆原料同一事件流，一鱼两吃（经验来源＋审计底账）；采集前按约定 9 剔除凭证。
- **检索轨迹**：谁、何时、以什么查询、召回了什么、是否注入，留痕备查并反哺衰减计算与运行统计。
- **变更记录（版本历史）**：统一存储的每次新增、改写、状态变更（批准、撤回、替代、归档、恢复）追加一条只追加的变更记录，含前后版本引用、执行方与原因。**完整版本历史由主存储侧的变更记录承担**；若阶段一查实 Hy 存储原生版本机制满足"每次改写可追溯、不可静默改写"，可由其承担，变更记录退为索引。定期镜像只是快照，两次导出之间的多次改写不能靠镜像追溯。
- **衰减**：经验按召回曝光计龄，长期零召回者归档（可见、可恢复，不静默删除）；归档动作本身入变更记录。
- **失败看门狗**：导入／进化类任务的"成功"必须附产物证据。导入与写入任务的报告须含读入数、新增数、去重数、拒绝数、失败数并能对平；"零新增且去重数与读入数吻合"是合法结果，读入为零、计数不平或零产出报成功即告警——针对赛道通病"静默失败"设防。
- **数据镜像**：统一存储定期导出为开放格式（MD／JSONL）入我方私有数据仓（约定 9），作为主权保险与搬家通道；镜像须带上每条记忆的稳定标识、来源、权威等级、有效状态与变更记录；镜像完整性纳入看门狗检查，还原能力按阶段二验收标准演练。

**6. 安全导入规程（首次真实导入前的必要条件）。** 导入先写入暂存区，校验条数与 provenance 后再经写入路径合入；禁止"先删后验"的替换式导入；同一份导出包重复导入不得重复造记忆（按约定 5 去重）；导入失败不得破坏已有数据，失败与计数不平纳入看门狗。依据：社区实证评估记录的同类导入事故。

**7. 运行统计口径（对冲二的数据来源）。**
- 驳回率：薄管线某场景最近 30 天内人工审核的候选，驳回数／审核总数；样本少于 20 条时只记录、不触发评估。
- 跨场景召回失败：检索轨迹中经人工标记"应召回而未召回"的案例，每例记录查询、期望条目与场景；按场景累计。
- 零召回时长：以检索轨迹中条目最后一次被召回（注入）的时间计；从条目入库起算。
- 统计窗口、样本门槛均为初始值，运行后按数据校准；阶段验收只要求这些记录机制可用、能出数，不要求先跑满统计窗口。

**8. 人工批准与撤回。**
- **批准绑定文本版本。** 人确认的是一条具体的最终文本：批准记录含被批准文本的版本标识（内容指纹）、确认人、确认时间与确认方式，写入 provenance 与变更记录。确认人是所有者本人或其指定的人；agent（包括知识层维护人角色由 agent 担任时）只能起草、分诊、整理，不能代为确认。
- **改写不继承批准。** 被批准文本经 evolve、合并或任何改写后形成新版本，新版本回到 `inferred`（或其加工来源对应的等级），须重新确认才可恢复原权威；旧批准只对旧版本文本有效。
- **晋升顺序（与知识层样板统一）。** 经验层候选 → 人确认（绑定版本）→ 投入知识层 `inbox/` → 维护人收录整理。人确认在投稿之前完成；维护人的收录是整理与编译，不是确认环节；整理成页时承重结论须能追溯到已确认文本原样存档，不得引入未确认的新结论。驳回的候选保留并记原因，可作为 failure-lesson 来源。
- **撤回、失效与替代。** 条目被撤回、判定失效或被新条目替代时：经验层条目状态改为相应状态（不删除，入变更记录）；召回默认排除非有效条目，必要时以"已撤回／已替代"标注呈现；由该条目编译出的 Skill 在下次编译时移除或更新，已交付到各 agent 的 Skill 由编译清单标出受影响项并重新交付；已晋升到知识层的结论按知识层 Outdated 流程处理。
- 本约定不要求所有低权威加工都经人工审批，只要求**自动加工不能悄悄获得或继承人工权威**。

**9. 数据存放与读取边界。**
- **私有数据不进设计仓。** 真实会话、行为日志、经验条目及其开放格式镜像存放在独立的私有数据存储（私有数据仓或本地存储）；本设计仓只放设计、文档与代码。
- **凭证不进持久记忆和镜像。** 捕获与导入时按规则识别并剔除凭证、密钥、token 类内容（以占位符替代并标记）；看门狗对镜像做凭证扫描，命中即告警并按约定 8 走撤回。
- **简单范围配置。** 用一份范围配置声明：各接入 agent 可读取的项目／场景／权威等级范围（跨项目读取默认关闭，按项目显式允许）；允许交给外部模型加工的数据范围（厚管线写入模型、外部评估器等一切数据出口都受此约束，范围外的内容不出，必要时走脱敏投影）。外部加工的模型身份写入 provenance。个人系统用配置文件即可，不建设企业权限平台。

**10. 与 contracts/ 的对接（跨线契约）。**
- 区分两类规则：**本线内部规则**（事件模型全字段、写冲突分级、候选门、批准与撤回、范围配置等）由本线自定并在本蓝图与后续规格中维护；**跨线契约**只取 [契约区](../contracts/README.md) 预定的四项——provenance 信封、文件原生约定、读接口约定、权威等级词表——以契约区定稿为准，本蓝图中的取值是本线提案。
- 文件原生约定与约定 5 的镜像格式、阶段二的还原演练直接相关：镜像格式先按本线内部规则定，契约定稿后按契约对齐。
- 阶段一可向契约区提交上述四项的提案；但按需求基准 §8，PAT 对接仍挂起，**契约定稿不是一期的前置依赖**，一期不实现跨线服务。契约与内部规则不一致时，以映射层适配，不反向阻塞本线施工。

**11. 接入层梯队。** 已被 MemHub 覆盖的工具走其插件；自有 agent 走 MCP／SDK 直连；已批准 lesson 可编译为 Agent Skill 交付（借 Beacon，受约定 8 的撤回规则约束）；Gateway 代理注入只预留接口与设计注记，一期不实现（触发条件：出现只能经 API 链路接入的封闭 agent，PAT 侧概率高）。各梯队的召回能力档位见约定 5。

## 构建顺序与完成标准

每个阶段的完成以"交付物＋证据＋判定"为准；成功须附产物证据，不接受自报完成（与看门狗同一规矩）。

| 阶段 | 交付物 | 证据 | 判定 |
|---|---|---|---|
| **阶段一**：蓝图冻结与假设查实 | 冻结的蓝图 v0.1；查实记录：Hy SDK 写入协议与版本机制、MemHub 本地数据目录与导出形态、写入路径实现方式（约定 2）、各接入方式召回档位（约定 5）、事件模型字段细化；契约区提案（可选） | 每项查实附实测记录或官方出处；写入路径能否满足约定 2 的约束有结论 | 全部查实项有结论；不满足约束的项已给出局部修订方案。查实是为落地，不是否决程序 |

**镜像还原演练（阶段二验收项）的最低标准：** 在独立位置从镜像恢复；核对内容完整性、稳定标识、来源、权威等级、有效状态与必要历史（已驳回、已撤回条目不得被恢复为有效）；引用的原始材料可定位，不出现失效链接；用代表性查询验证召回结果与恢复前一致。检索索引可重建，不要求向量逐字节相同。冻结只要求写清此标准，演练在阶段二执行。

## 与需求基准的映射（摘要）

跨厂商（基准§1）→ 接入层梯队＋事件模型；两层分治（§2）→ 经验/知识分层＋晋升单向＋批准绑定版本；慢层先行（§3）→ 全层无实时同步设计，快层仍观察；共存 ETL（§4）→ 输入层 MemHub＋自建 ETL＋安全导入规程，导入素材默认 raw，统一存储为 system of record；主权（§5）→ 私有数据存储＋开放格式镜像＋还原演练＋本地优先；治理底线（§6）→ provenance 信封、写冲突分级、召回钩子与检索记录、变更记录（版本历史）；知识层形态（§7）→ 只作角色与接口位，形态见知识层样板；PAT 预留（§8）→ Gateway 预留＋跨线契约只经 contracts/，不进一期实现。

## 未决项（不阻塞冻结，阶段一查实/细化）

1. Hy 存储的实际格式、原生版本机制与官方导出能力（决定变更记录由谁承担、数据镜像的实现方式）。
2. MemHub 与 SDK 的分工边界：MemHub 用到应用层为止，还是只取其导入能力、召回走 SDK。无论哪种，均须满足约定 2（唯一权威记录、只经写入路径）。
3. 候选门本地实现的概率可信度验证方法。
4. 行为轨迹的采集范围与端点形态（哪些 harness 能采到动作级事件、采不到的如何降级为会话级）。
5. 各接入方式的召回档位（开局＋中途／仅开局／无在线召回）。
