# 知识层样板（通用模板）

本样板示意本项目设计中"知识层"这一角色的形态，供讨论与实现时参照。它是一个**通用模板**：任何符合下列结构与契约的知识库实例都可充任知识层；本样板不对应、不指向任何在用的私人知识库。

## 角色

知识层收纳**经人确认**的知识条目，是本系统权威等级的最高层（approved）。它与经验层（agent 推断、inferred）分治：经验层内容不得绕过人工确认直接进入知识层；召回结果跨层呈现时必须标注层级与权威等级，经验不得冒充知识。

## 结构（文件原生）

```
knowledge-base/
├── raw/          原始来源，只读不改（文档、导出、摘录，带来源与获取时间）
├── wiki/         编译后的知识条目（一文一主题，条目间以相对链接互连）
│   ├── index.md  全量索引（条目标题＋一句话摘要）
│   └── log.md    变更日志（每次收录/修订一行：日期、来源、动作）
└── inbox/        待审队列（经验层晋升候选与外部投递先落此地，人确认后才入 wiki/）
```

## 治理要点

- **溯源接地**：条目中的承重事实必须能在 `raw/` 中找到逐字出处，条目文末链回来源。
- **准入**：人触发或人确认；机器可起草，人定稿。争议/过期条目以状态块标注（Disputed / Outdated），不静默删除。
- **写入纪律**：单一维护者角色（由项目所有者指派，可轮换）；版本历史由 git 承载；写入前拉取最新、保持线性历史。
- **格式**：纯 Markdown＋相对链接，不依赖专有平台，随时可整体迁移。

## 与经验层的接口契约

- **晋升（单向向上）**：经验层候选 → `inbox/` → 人确认 → 编译入 `wiki/` 并记 `log.md`。晋升条目保留其经验层出处（provenance 信封随行）。
- **召回（只读向下）**：经验层与其他 agent 以只读方式检索知识层（文件直读或经 MCP/HTTP 读接口）；召回结果带权威标注 `approved` 与来源条目链接。
- **无共享运行时**：知识层不依赖经验层的进程与存储引擎；任一层替换实现不影响另一层的数据。

## 实例化说明

新建一个知识层实例 = 按上结构建仓＋启用治理规则＋在系统配置中登记其只读接口地址。实例是私有的还是公开的、托管在何处，均属部署选择，不写入设计文档。
