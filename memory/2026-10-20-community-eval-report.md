# 社区评价深挖报告（实测两段走 · 第一段）

> 日期：2026-10-20。背景：用户对全面实测的必要性存疑，改定两段走——先深挖社区评价，实测降级为决赛圈冒烟。本报告为第一段产出。
> 证据标准：只收**独立、亲手跑过、带日期**的评价；厂商 PR／投放稿单独标记，不计入口碑。来源：AML 官方仓与榜单、implicator.ai 独立测试、starryhope 用户报告汇总、各仓 issues 原文、中英文社区搜索。

## 全场级发现（比单个项目更重要）

1. **受控协议下全场低分，厂商跑分不可比。** AML 第一轮（2026-08-12 发布，67 个系统完成评测，20+ 高校发起）：商业组榜首是 MemoraX（总分 **58.02**），hindsight（Vectorize）、腾讯、Mem0、Supermemory 均在其后。也就是说在统一答案模型与评测管线下，全场最高分也只有 58 上下——与各家自报的 94.6% 之类数字完全不是一个世界。另有 2026-03 独立论文实测某 Mem0 配置在 LongMemEval 得 49.0%，同场纯长上下文推理 82.4%。**结论：选型不得依据厂商 benchmark，只能当存在性证据。**（MemoraX 的名次来自其 GlobeNewswire 通稿，名次本身与 AML 榜单互证，总分数字以通稿为准、待榜单页复核。）
2. **"静默失败"是赛道通病。** 五家 issues 里同类问题反复出现：ReMe 的 auto_dream 零提取却报成功（#646/#645，2026-10-20 当日）；TencentDB 的 L2 提取失败被误判"无新数据"（#1712）、vec0 损坏后写入静默失败（#1709）；rohitg00 的向量索引停滞自检失效（#1594）。本项目治理底线要求"失败与冲突可见"——社区证据表明**没有一家在这点上是干净的**，选谁都要自己加监控。
3. **证据密度严重不对称。** hindsight 的英文社区实证（独立测试、Reddit 长用报告、X 用户反馈）明显厚；ReMe 的中文独立长测评稀缺，其口碑证据主要来自仓内 issues 质量与 AgentScope 生态背书。**"没挖到差评"对 ReMe 只证明证据薄，不证明东西好。**

## 逐家社区画像

### hindsight（Vectorize）
- ✅ 独立两会话测试（implicator，2026-09-29）：编程 agent 把两条未成文规矩带进了后续会话，作者核查了记忆库与产物文件——捕获＋开局注入**真实有效**。
- ✅ Reddit 长用报告：用 Hermes Agent 灌入约 8400 万 token 的 bank，"彻底解决了上下文膨胀"，成本 0.85 美元（DeepSeek Flash）；但"让它稳定下来费了些功夫"。
- ⚠️ 五工具独立横评（implicator）列第 2，评语：**召回成绩文档最扎实，但装配最重**——与此前"heaviest setup"判断互证。
- ⚠️ 冲突处理被点名：竞品开发者与 issue #3509 一致指出**错误事实没有删除入口**（控制台只有 Edit／Invalidate），冲突记忆人工清理"messy"；静态共享 bank 下知识页出现空页／无关页（≤0.8.0）。
- ⚠️ 后台巩固会触发额外 LLM 合成调用，成本与延迟被竞品点名（结构性代价，非 bug）。

### ReMe（阿里 AgentScope）
- 仓内公开成绩（官方参考跑分，方法有文档）：LongMemEval cleaned-s 89.4%、BEAM 66.1／65.0、π-Bench PROC 0.580——按全场级发现 1，只作存在性证据。
- issues 质量高（中英双语、定位细），社区在推它往多工作区隔离、多用户方向走；当日的 auto_dream 静默成功 bug 说明其自动蒸馏的**失败可见性**有真实缺口。
- 中文社区独立评测稀缺（本轮多语种搜索只捞到官方文档与生态文章）——证据薄，置信度低于 hindsight。

### TencentDB Agent Memory（腾讯云）
- 国内真实用户密度全场最高（issues 大量中文接入问题），团队在仓内公开运营（贡献指南、分支治理）。韩语社区已有 Team Memory 的正面长文分析（分析文，非长测）。
- ⚠️ 与规模相称的复杂度事故面：多 agent 记忆隔离回归（#1718）、索引 worker 静默崩溃伴 CPU 失控（#1732）、CodeGraph／Compaction 多处边界 bug。能力与运维重量是同一枚硬币。
- 厂商 PR 密度高（20k star 通稿等），按证据标准全部标记为投放、不计口碑。

### rohitg00/agentmemory
- ⚠️ **版本间无存储迁移路径**（#1584：0.22.1 引擎读不了 0.11.2 的库）——对"长期托付"是实打实的扣分。
- ⚠️ **replace import 先删库再校验**（#1573）——与本项目 ETL 导入场景直接相关，导入安全性有坑。
- issues 标题工程诚实、社区贡献活跃（个人发起＋社区驱动的典型形态），稳定性类 bug（worker 掉线、帧上限）不少。

### EverOS（EverMind）
- 节奏最慢、issues 最"深"（幂等、级联状态、索引退役等内部工程议题多，用户面事故少）。
- ⚠️ 抽取边界 bug 存在（代码引号触发 add/flush 500，#515；SQLite busy 超时 500，#498）；反射合并的部分写入无补偿（#443）。无独立长测评可挖，证据量中等偏薄。

### tigerless／Hy-Memory／caura／deja-vu／memorix
- 均无成规模的独立社区实证可挖（太新或太小）——与观察定位一致，不构成新信息。

## 对选型与第二段的影响

- **排名不变，置信度分层**：hindsight 的 B（捕获/蒸馏）判断置信度上调（独立实证最厚）；ReMe 的功能判断维持，但挂"社区未验证"标注；rohitg00 因迁移/导入两坑，综合分再扣；TencentDB、EverOS 维持原判。
- **第二段冒烟范围再确认**：社区已答掉的——蒸馏大面上行不行（有实证）、维护方活不活（有数据）；社区答不了的仍是那三件——**与 LLM Wiki 仓的组合、拔插/数据完整导出、四家导出包的 ETL 灌入**。冒烟只测这三件，对象等 AML 第二轮（Cycle 2 已于 2026-09-28 开放注册）结果出来后在 hindsight／ReMe 之间定一家。
