# 调研项目适配性重评（按冻结需求基准）

> 日期：2026-10-20。基准：同目录 `requirements-baseline.md`（已冻结）。
> 方法：**只按新基准对 `projects-survey.md` 已核验证据重新称重，不引入新事实**（各项目此后若有版本变化，不在本评范围）。证据等级沿用调研原文（✅已验证／⚠️官方自述／❌未见）。

## 称重口径变了什么（相对上一轮 9 条打分）

1. **知识层席位已定**（karpathy-llm-wiki＋git 仓＋WIKI_RULES v4）→ 本轮各项目按**经验记忆层候选**评分；自带 wiki／知识页功能由"加分项"变为"中性／冗余"。
2. **快层已转长期观察** → 实时同步类特性（SSE 推送等）不再加分；慢层扎实程度才是分。
3. **原生记忆共存机制已定（批量导出 ETL）** → "能否吃下厂商导出包／批量会话导入"成为具体评分项。
4. **组合性入围** → 与已定知识层同处一个世界（文件原生／Markdown／git）的候选占优；独立服务型候选必须证明多一个筒仓的价值。

评分维度：A 跨厂商面｜B 经验层本职（自动捕获与蒸馏：情景／语义／程序性）｜C 与知识层的可组合性｜D ETL 导入｜E 治理（provenance／权威标注／版本）｜F License（硬门槛）。

## 重排结果

### 第一梯队（经验层主力候选）

| 项目 | 评 |
|---|---|
| **hindsight**（MIT✅） | B 最强：自动摄入＋会话开局注入，经验层的活它干得最全；C 为服务型（自有存储），作为 wiki 旁的查询层共存没问题。D 批量导入未见明确证据（⚠️）。适合当"自动记账员"。 |
| **ReMe**（Apache-2.0✅，阿里 AgentScope） | C 最佳：Memory as File（Markdown＋frontmatter＋wikilinks），与 wiki 仓同为 MD／git 世界，组合摩擦最低；B 有多 harness hooks 与自演化知识库。主权契合度在梯队里最高。 |
| **tigerless-labs/agent-memory**（MIT✅） | E 独一份：sleep-time 巩固＋**内置权威分级**，与本项目"两层权威分开治理"的模型直接对味；纯本地、无 API key。B 偏巩固而非捕获。既是候选，也是权威标注机制的借鉴源。 |

### 第二梯队

| 项目 | 评 |
|---|---|
| **TencentDB Agent Memory**（MIT✅） | B、E 都强（Chat Memory／Skill／治理在团队分支），但体量重：其 wiki 与已定知识层重复，服务化部署对个人阶段过重。**重型备选**：经验层将来要团队级治理时再议。 |
| **rohitg00/agentmemory**（Apache-2.0✅） | A 最宽（54 个 MCP tools、多 harness），B 有 12 个 auto hooks＋生命周期；置信度评分在经验层可用（知识层不用）。C 为本地运行时服务。 |
| **EverOS**（Apache-2.0✅） | C 好：.md 真相源＋Git 版本＋watcher 同步；B 中等。文件原生组合性仅次于 ReMe。 |
| **LongMemory**（Apache-2.0✅） | "TencentDB-lite"：纯本地 SQLite 是优点也是 C 的扣分（非文件原生）；自带 wiki 已冗余。 |

### 观察与降级

- **Hy-Memory**（Apache-2.0✅）：分层与冻结需求的模型最像（对话 L0–L7、工作记忆双层＋价值阈值、编程版本演化链）——架构契合度全场最高，但发布仅数日、**零独立验证**。观察名单第一名，验证前不进选型。
- **ai-memory**（MIT✅）：**移出经验层候选**——它本质是 wiki 系统，其席位已被选定技术栈占据；保留为知识层的备选／参考实现。
- **mcp-memory-service**（Apache-2.0✅）：原卖点 SSE 实时推送因快层搁置而失效，降为普通 MCP 存储备选。
- **OpenViking**（AGPL-3.0✅）：工程最强，但 F 硬门槛不变，继续排除；其 Gateway 注入模式只作设计参考。
- **mem0／supermemory／Memori**：维持原判——服务型筒仓，组合性、主权、治理都弱（mem0 图记忆还在付费墙后），列备选末位。
- **honcho**（AGPL-3.0）、**memU**（无 LICENSE 文件）：维持排除／警告，不变。

## 一句话结论

知识层定盘之后，经验层的牌面重排为：**hindsight（自动捕获）、ReMe（文件原生组合）、tigerless（权威治理）三家领跑**，TencentDB 为重型备选，Hy-Memory 是潜力最大但未验证的一个；上一轮靠 wiki 功能加分的项目（ai-memory、LongMemory、rohitg00）本轮相应回落。

## 再再补充（2026-10-20，用户决策）：设计维度排序（OpenViking、Hy 入池后）

前提变更：① 本项目不商业化、按开源建设 → AGPL 不再出局，OpenViking 回归候选（basic-memory／honcho／ByteRover 形式上同步解禁，但设计适配度不在前列，不影响排序）；② Hy-Memory 移入正式对比。本节按用户指定口径排序：**只看设计理念、架构、功能模块、已知拓展方向，不计 bug 与实际使用效果**。标尺是与冻结基准的设计契合度：与已定知识层（LLM Wiki＋git）不打架、原生记忆共存是否设计一等公民、主权形态、层间可替换性、拓展方向与个人主权是否同向。

| 名次 | 项目 | 设计评语 |
|---|---|---|
| 1 | **Hy-Memory（混元）** | 设计中心与本项目需求重合度最高：双系统认知分层对应经验三型（Chat 分层／Working 事实+经验／Coding 版本演化链）；**共存导入是 MemHub 的产品一等公民**（授权导入 10 种工具历史＋持续同步），正是基准 §4 的形态；模型／框架／应用三层可分开替换，且**不觊觎知识层**，与 LLM Wiki 并排不打架 |
| 2 | **OpenViking（字节）** | 架构完整度与想象力全场第一：统一虚拟文件系统＋L0/L1/L2 分层加载＋Gateway 注入，是"上下文数据库"级别的设计。屈居第二的原因是结构性的：它的设计要**连知识层一起拥有**，与已定、已运行的 LLM Wiki＋git 主权形态正面相撞；且其"文件"是引擎托管的虚拟文件，主权纯度低一档 |

## 定盘（2026-10-20，用户拍板）

**以混元 Hy-Memory 为底座**搭建本项目的共享记忆系统，在其上调试优化；其他项目的优秀设计、组件与工具吸收借鉴。老邪的客观修正（用户要求不迎合，已当面提出）：① 能吸收的主要是**设计与小工具**，跨项目**代码移植基本不成立**（各家数据模型与存储基底不兼容），移植为例外；② 采用深度分三级——MemHub 现成用＋SDK 集成起步，**不 fork**（五天大的高速迭代代码，fork 等于独自维护分叉）；③ 本决策本质是**对混元团队持续投入的下注**、非对当前代码的验收，故保留验收门：原定第二段冒烟（与 Wiki 组合／拔插导出／导入）对象直接定为 Hy，三项过关再谈深度集成；④ 范围提醒：MemHub 覆盖的是本地 harness 一半的共存问题，web 四家导出 ETL 仍须自建；⑤ 知识层权威边界由我方守住，Hy 只作经验层，防 MemHub 便利性架空 LLM Wiki。**2026-10-20 用户再明确（老邪认账修正）：底座已选定，测试不再是"否定底座的验收门"，定位改为服务构建的三件事——验证蓝图依赖的假设、接入调试中发现并解决问题、用自有小评测度量调试优化的效果；且蓝图（实现思路／借鉴清单／分层架构）先行，测试随后。**
