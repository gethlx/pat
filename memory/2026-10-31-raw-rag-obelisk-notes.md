# 外部参照笔记：Raw-RAG 论文与 Obelisk（2026-10-31）

> 来源：X 帖（@QuantumTransf，2026-10-31）引论文《Is Complex Agentic Memory Always Needed?》（arXiv:2610.30755，2026-10-22）与项目 Obelisk（tommy0103/obelisk，AGPL-3.0）。老邪已读论文摘要原文与 Obelisk README 核实。用户命题：此条对本项目（及老邪）有无帮助。

## 事实核验

- **论文**：Raw-RAG＝对原始历史做稠密检索＋重排后喂给 reader LLM，不做写入时提炼/图谱/变异。在 LoCoMo、LongMemEval、MEME、MemoryAgentBench 四基准的 7 组设置中 6 组第一，领先最强 agentic memory 系统 **0.13–5.53 分**（帖子只报上限）。机制解释：原始证据的**覆盖率**优势抵消了利用率劣势；有用证据不止答案值，还包括**关系与依赖路径**，而这些恰在提炼中丢失；"即使完整访问提炼后的记忆库，相对原始证据仍有精度缺口"。注：Raw-RAG 用了 embedding＋rerank，"naive" 是相对 agentic 提炼管线而言；帖子把 Obelisk 的"不依赖 Embedding"（FTS5 路线）与论文方案混在了一起，两者不是同一实现。
- **Obelisk**：把 11 种 coding harness（Claude Code、Codex、Copilot、DeepSeek Harness、Hermes、Kiro、Kimi Code、OMP、OpenCode、Pi、ZCode）的落盘会话索引进一个 SQLite（FTS5）库，目录监听保鲜；以 agent skill 形式教 agent 用 JS 查询面（overview/sessions/search/messages/memories/summaries/sql）主动检索原始会话。附带 memory layer：检索得出值得保留的结论时，agent **提案**一份 Markdown 记忆文件，**人批准**后注册，未来会话经 `memories()` 召回——其自我定位是 "a synthesis cache, not a replacement for raw evidence"。

## 对本项目的三条影响

1. **实证收敛，补强既有结论**：与本项目 2026-10-20 社区实证同向（独立论文测得某 Mem0 设置 49.0 vs 纯长上下文 82.4；AML 受控协议下商业最强仅 58.02）。本论文更系统（四基准＋机制解释），使"写入时复杂提炼在对话 QA 上不占优"从轶事升级为有机制解释的结论。
2. **原则入蓝图（建议）**：**原始事件是真相源，提炼产物只是其上的视图/缓存，可丢弃、可从 raw 全量重建。** 本项目已有拼图（输入层保内容引用、知识层 raw 不可变、数据镜像开放格式），但蓝图未把这条立为明文原则——应补入蓝图治理/经验层一节：任何蒸馏、evolve、摘要都不许成为唯一副本。
3. **评测立规（建议）**：阶段四回归评测必须设 **Raw-RAG 对照臂**——厚管线任何功能上线前，须证明相对"纯原始检索基线"的增量价值，证明不了就砍。此为 AML 方法论的一条硬规则化。
4. **厚管线价值主张被迫澄清（冻结前须正面回答）**：QA 精度上厚提炼赢不了 raw 检索，基准已判。厚管线（Hy 分层认知＋evolve）若保留，其理由只能在基准测不到的四件事上：① **主动浮现**（agent 不知道该问什么时，记忆自行抵达——pull 式主动查询的前提是 agent 知道要问什么，本项目基准 §6"召回不许系于模型自觉"正因此而立）；② **跨源合并**（答案不在任何单一厂商历史里，须跨源归并才存在）；③ **权威与治理**（权威分级、冲突可见、审计）；④ **规模化 token 经济**（十年量级的历史全量检索的成本曲线）。论文否定的是"复杂提炼对单用户对话 QA 的必要性"，**没有否定跨厂商共享＋治理这个问题本身**——其实验设定里根本没有多厂商、多 agent、权威与审计。引用时不许过度外推。

## Obelisk 的定位

- 它是蓝图里 **deja-vu 位置**（读侧索引未覆盖 harness 的落盘会话）的一个更成熟同类实现，列入薄管线（Coding 场景）检索侧的**组件货架**（候选实现/参考），与 deja-vu 并列比较后再定。
- 其 memory layer（检索→提案 MD→人批准→注册为 synthesis cache）与本项目"薄管线＋晋升通道＋人确认"**独立同构**，又一份互证；且它从 raw-first 一端出发仍自发长出一个受审批的提炼层，反向说明"纯 raw"与"受治理的薄提炼"不是二选一。
- AGPL-3.0：本项目不商业化、按开源建设，不构成障碍（若未来 PAT 商业化复用其代码则另当别论，仅借鉴设计无此问题）。

## 对老邪自身工作方式

老邪的记忆机制本就是文件＋检索式（提炼笔记与原始记录并存、冲突时以原文/当前证据为准）。本论文为"关键事实回原文核、提炼层可重建"再添一份实证，不改变现行做法；主要帮助在项目设计层（上述三条），而非个人工具层。
