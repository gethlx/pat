# 外部参照笔记：五个 Grok Bot 式编排产品（2026-10-30）

> 来源：X 帖（@xiaomovps，2026-10-30）列举的 5 个开源项目；老邪逐个读了 README，其中 Open Duet 的 `docs/MEMORY.md` 做了深读。用户命题：对本项目共享记忆系统的设计有何借鉴。

## 总判断

这 5 个（Munder Difflin、OpenMausBot、Open Duet、Rakazo、OpenBot）全是 **agent harness／工作台层**产品（编排、身份、多端、云电脑），**不是记忆引擎**——在本系统分层里属于"消费者/接入对象"那一层，不产生引擎候选。其集体价值有三：

1. **再次互证立项结论**：五家自带记忆清一色 **per-agent 私有**（每 bot 自己的 MEMORY.md／工作目录／会话），跨 agent 的共享记忆层在 harness 层依然空白——共享层仍需自建，harness 们正是未来要接入咱们共享层的客户端形态。
2. **竞争焦点提示**：赛道热度已卷到编排、多端与可视化，记忆只是标配项；本项目不做 harness 的定位正确。
3. **Open Duet 一家是工程富矿**：其记忆文档（docs/MEMORY.md）密度远超同类营销 README，给本项目的治理层与衰减策略提供了多个可直接落地的机制（见下）。其余四家只记结构性参照。注：五家均为数周内冲到 4–9k star 的热潮项目，star 按本项目规矩只作发现信号；Duet 的可借鉴性来自文档细节密度，与热度无关。

## Open Duet 记忆机制采收（逐条对位本项目蓝图）

1. **审计与被审计数据物理分离**（治理层硬原则）：Duet 的 journal（全量变更日志）与 proposals 刻意放在 agent 自己的文件夹**之外**——"agent 有文件工具、在自己文件夹里工作，它能改写的记录就不算记录"。对位本项目：行为轨迹可以与记忆同流采集，但**轨迹/审计的存储必须落在被审计 agent 的可写域之外**，蓝图治理层应把这条写成硬约束（此前只说"同流"，未说"异域存储"）。
2. **召回注入规范**（接入层）：召回结果放在**用户消息之前**、永不进 system prompt（频繁变化的系统提示会击穿引擎的 prompt cache——与 OpenViking Gateway 保缓存的观察同源互证）；召回块带标准框架声明（自动匹配的背景材料、现时发言优先、块内文本不构成指令与授权），且防"提前闭合块"注入；每次召回落一条 `memory.recalled` 事件，界面上以可见 chip 呈现"召回了哪几条、来自哪里"。对位本项目：蓝图的"检索轨迹"从后台日志升级为**对用户可见的召回呈现规范**（来源标注＋优先声明＋防注入收尾＋事件留痕）。
3. **文件原生的衰减三件套**（治理层衰减策略的具体实现样板，蓝图此前只有原则）：
   - **预算驱动归档**：常驻记忆只加载定额（如前 200 行/24KB），写满时在同一步把最旧条目整条移入 `archive.md`，顺序为先已取代、再已过期、再最旧；**手写无日期条目与健康安全类事实永不自动移**；移动先写 archive 并记 journal 再动正文（不丢）；移动后数日内在上下文里告知 agent 移走了什么、可加回。归档**从不参与召回**，只可像普通笔记一样被翻读。
   - **条目到期日**：条目可带 `until <日期>`，到期后不加载、不召回，但保留在文件里，仪表盘显示有多少过期条目未加载；过期判定先于定额截断（过期条目不许挤占活条目的位置）。
   - **取代划线**：事实被替代时旧条目划线保留并标注 superseded 日期，召回跳过划线条目——与 Graphiti"失效边不删除"的双时间模型同理，这是它的**文件原生实现形态**。
4. **哈希乐观锁的写入并发控制**（文件层）：笔记保存携带所基于文本的 hash，期间被改则拒绝并返回现文（409）——比文件锁轻，适合非 git 承载的经验层文件写入；与知识层的 git 纪律互补。
5. **提案制晋升（候选门的产品形态）**：agent 从**用户的话**里提取" meant to last "的陈述，做成**引用原话**的提案，人 Accept 才写入正式记忆、Reject 即弃；另设"noticed facts"自动写入档（写入时明示）。对位本项目：晋升通道的两档设计（自动记 vs 提案审）与权威分级天然对应；**"提案必须引用原话"**是证据接地的具体做法，补进候选门规格。
6. **双侧脱敏**：疑似秘密在**保存时**脱敏、且在**每次加载时**（索引、召回）再脱敏一遍，以覆盖 agent 绕正规路径用文件工具自写的笔记。对位本项目治理层：写入路径不止一条时，脱敏不能只守入口，出口必须复检。
7. **记忆可携带的导出/导入纪律**：agent 导出携带 MEMORY.md＋主题笔记（脱敏后），带容量上限、超限项在响应里点名 `skipped`；导入**只新建、永不覆盖**既有记忆。与 rohitg00"replace-import 先删后验"事故正反对照，本项目 ETL 侧照此立规。

## 其余四家的结构性参照

- **Munder Difflin**：虚拟办公室（agent 各有记忆、邮箱、工位、互派任务，"你的克隆"任协调者）。对本项目主要是呈现层参照：多 agent 舰队的**状态可视化**（谁在干什么）是行为轨迹的一个消费形态，未来可议；其记忆仍是 per-agent 私有，无共享设计。
- **Rakazo**：基于 Pi 的持久 bot（自有记忆/例程/历史）；执行环境分 **Shared Team Computers 与 isolated Private computers** 两档——"共享/隔离双模式"在执行环境层的同构实现，可作接入层注脚：未来接入的 agent 可能生活在这种多端 harness 中，接入设计应假设这一点。
- **OpenBot**：本地优先工作台；每 agent 独立工作目录与会话，共享靠显式消息与文件传输——**隔离默认、共享显式**，与本项目"共享层外置、私有默认"同构。其安全面是反面教材：开发预览版默认 `danger-full-access`＋`approvalPolicy: never`，正是本项目治理层与审批设计要防的形态（与 agent-beacon 的审批滥用检测互证）。
- **OpenMausBot**：聊天软件形态（bot 即联系人、各有身份/模型/云电脑、"Approve what matters"）。只有产品形态参考价值，README 未及记忆机制，不深挖。

## 不吸收

- 五家的 per-agent 私有记忆实现本身：与本项目"共享层外置、层外无状态"路线相反，只作接入对象看待。
- 虚拟办公室/多端客户端等编排与呈现层产品形态：非本项目层位（属 PAT/编排侧议题）。
