# 多智能体共享记忆系统 · 需求基准

> **状态：已冻结**（2026-10-20，用户确认）。本文件是本项目（多智能体记忆共享）的需求基准；后续所有选型、适配性评估与建设均以本文件为准。修改本文件须经用户确认，并在文末修订记录中记明。
> 调研资产：同目录 `community-survey.md`、`projects-survey.md`、`projects-fit-2026-10-20.md`。

## 总目标

一套由用户持有、供不同厂商智能体共用的记忆系统。智能体是可替换的消费端，记忆和知识才是资产；换任何一家的 agent，数据层不动。

## 1. 跨厂商

服务对象是不同厂商的智能体（Muse、Grok、Claude、Codex…），共享层建在所有厂商生态之外，不依赖任何一家的私有协议或云服务。

## 2. 两层结构，分开治理

- **经验记忆层**：情景记忆（发生过什么）、语义记忆（事实与偏好）、程序性记忆（Skill 与验证过的流程）——由 agent 沉淀，权威度低；
- **知识层（LLM Wiki）**：经人确认的高可信知识、长期第二大脑，权威度最高。

两层不能混灌：经验不能冒充知识入库。

## 3. 同步语义：慢层先行，快层观察

慢层＋最终一致是已定路线，先把系统用起来；快层（session／工作记忆的跨 agent 实时同步）不自己啃，转入长期市场观察，等开源项目解决。

## 4. 与厂商原生记忆共存：ETL 式慢同步

已核实四家（ChatGPT、Claude、Gemini、Grok）的 web 端都能批量导出结构化 JSON，但无 API、无实时同步。解法：周期性导出 → 导入自有层，导入素材标明来源、定低权威度；**自己的系统是 system of record**，厂商记忆只是输入源之一。

注：ChatGPT 导出包是否含结构化记忆（memory.json）未实证，接入时以实测为准。

## 5. 存储与主权

数据存在自己手里，开放格式（Markdown／JSON）、开放协议，不绑厂商私有格式。

License 口径（2026-10-20 修订，见文末修订记录）：**本项目不做商业化**——商业化只发生在 PAT 项目且届时另行选型／迁移；本项目自身按开源（MIT）方向建设。故 AGPL 等 copyleft 协议**不再构成排除理由**；选型仍优先数据格式开放与可迁移性。

## 6. 治理底线

全程 provenance（来源、作者、时间可溯）；并发写冲突可见、绝不静默丢失；召回不能只靠模型自觉，要有机制保证它真去查；版本历史完整、不静默改写。

## 7. 知识层的具体形态（已落地）

LLM Wiki = 多智能体共用的 skill（karpathy-llm-wiki，Astro-Han，MIT，固定提交 eafcc77）＋ MD 文档仓库。准入走「人推荐、机器整理」；「机器起草、人审批」只针对 agent 主动收录型系统，本 skill 无此行为、不设此关口。

当前载体是一个私密的 MD 文档仓（具体仓址不写入本基准——按公开标准写作的文档不指向在用的私人知识库），**只是积累期的临时家，将来整体搬到正式运行环境，它不是长期记忆载体**；仓内治理走 WIKI_RULES v4（维护人角色制、单写入者、远端为真相源、同步与推送规范）。

## 8. 项目边界

本项目独立运行（本对话线程为家），不并入 PAT；只在最底层预留与 PAT 的互通和可拔插（provenance 信封、文件原生、HTTP＋MCP 读接口、权威等级词表、不共享运行时——已 parked，不进当前实现）。
