# 外部参照笔记：Grok Bot "第二大脑" 20 库清单（2026-10-21）

> 来源：X 帖（@Greshamtrade，2026-10-21）＋其引用的 X 长文课程《How to Make Grok Bot Do 10x More Work…》。帖子给出复刻"第二大脑"的 20 个 GitHub 库；长文正文是给**单个 bot** 的工作流纪律课（复用研究、不重读未变来源、完成前核验等），不是记忆系统架构文。用户命题：其理念与 20 库对本项目共享记忆系统有无帮助。

## 总判断

这份清单是**零件架，不是架构图**：整套默认单用户、单 bot、以文档为中心的知识组装；没有权威分层、没有多 agent 写入治理、没有经验/知识分权——恰是本项目蓝图多出来的部分。其价值在三处：① 与本项目同向的理念互证（数据自有、文件为本、MCP 接入、从小起步逐件加）；② 几个现成组件可进我们的运维/摄入管线；③ 一道现成的评测题型。它不产生任何新的引擎候选，不动 Hy 底座与既有分层。

## 20 库逐项处置

**记忆引擎类（与 Hy 同位，槽已满，不换）**
- Basic Memory（#1）：MD＋MCP 知识存储，AGPL。此前已评估为知识层备选，槽位已被 LLM Wiki 占。
- Cognee（#2）：文档/对话→知识图谱引擎。此前扫荡在池，与引擎层同位，不替换底座。
- MemOS（#3）：记忆层 OS（MemCube/调度）。首轮调研在池，同位不换；其记忆调度思想此前已随赛道结论吸收。
- Mem0（#4）：已评估降级（服务化孤岛倾向），结论不变。

**时间事实类（本清单最有价值的设计参照）**
- Graphiti（#5）：**双时间事实模型**——事实边带 valid_at/invalid_at（事实有效期）与事务时间，事实变更走"失效＋新边"而非删除/覆盖，天然保留"以前为真、现在不真"的全史。本项目蓝图从 hindsight 借的"信念演进"只有语义，Graphiti 给出可落地的**数据模型范式**，列为阶段一细化信念演进时的一手参考。Neo4j（#17）只是其图库后端选项之一，本项目规模不引入图数据库服务，只借模型不借后端。

**检索/存储基座类（只取轻件）**
- sqlite-vec（#15）：镜像（MD/JSONL）本地向量索引的现成组件候选。注意前科：TencentDB 静默写失败事故（#1709）正出在 vec0 扩展——采用必须配治理层看门狗的落盘校验（蓝图已有此条）。
- PageIndex（#7）：长文档树索引＋结构导航式检索，与 OpenViking L0/L1/L2 分层加载同源互证，可作 wiki/镜像长文档检索的设计参考，不必引组件。
- LightRAG（#6）：文档 RAG（图谱＋向量、增量更新），与经验记忆不同层，不引入。
- pgvector（#14）/ Meilisearch（#16）：各多一台服务，违同尺寸原则，不引入。

**知识层摄入类（组件架，阶段三扩 raw 采集时取用）**
- MinerU（#12）/ Unstructured（#11）：PDF/文档解析为结构化文本——wiki raw 摄入管线的候选解析器（采用前须查 LICENSE 原文）。
- whisper.cpp（#13）：本地语音转写——语音笔记/会议录音进 raw 的候选组件。
- Linkwarden（#9）：网页归档防链腐——与 wiki "raw 不可变、来源保全"原则一致，可作 web 来源归档件。
- Karakeep（#8）/ Paperless-ngx（#10）：面向人的收藏/文档应用，与 agent 管线形态不合，只记理念不引入。

**运维管线类（小而锋利，可直接列入计划）**
- restic（#20）：加密增量快照备份——蓝图"数据镜像"的补强：git 镜像管文本，restic 管整个数据目录（含 Hy 存储）的加密快照与回滚，列为阶段二运维件候选。
- watchfiles（#18）：文件变更触发增量索引——镜像/索引保鲜的标准件，避免全量重扫（与长文"别重读未变来源"互证）。
- Syncthing（#19）：多机文件同步——文本纪律已由 git 定案，仅在大目录（如 Hy 存储）多机同步场景作备选。

## 理念层吸收

1. **决策溯源题型**（帖子的验收题）："六个月前为什么否掉这个方案？"——合格的回答须带原始推理、证据、以及后来取代它的决定。此题型直接纳入蓝图阶段四评测集设计（decision-provenance 类问题），比通用记忆基准更贴本项目的资产属性。
2. 长文的流程纪律（复用已有研究、不查未变来源、"无变化"也算结果、未完成不报完成）与本项目治理层/失败看门狗同源，属理念互证，不产生新设计。
3. "从一个项目＋一个后端起步，逐件加零件"与本项目同尺寸原则及分阶段构建顺序一致，互证。

## 不吸收

- 以该清单替代或增补引擎层的任何冲动：4 个引擎类库均已在册评估，Hy 定盘不动。
- Neo4j/pgvector/Meilisearch 等服务型基座：运维重量与本项目规模（一人＋约十个 agent）不匹配。
